> 를 다루는 심화 참고서로 재정의되었습니다(v2.0).

## 0. 공통 사항

- **접근 권한**: `ai_settings` 권한 — 테넌트 **마스터/디렉터** 랭크만 접근·수정 가능.
- **적용 범위**: 모든 설정은 **테넌트 단위 × 에이전트 단위**입니다. 화면 상단 *AI
  에이전트* 카드에서 선택한 에이전트의 설정을 편집하며, *"{에이전트}에 적용되는 설정"*
  카드가 실제 적용값(기본값 폴백 포함)을 요약합니다.
- **반영 시점**: 저장 즉시 DB 반영. 페르소나·응답 규칙·모더레이션 규칙은 성능을 위해
  **최대 60초 캐시**(저장 시 캐시를 비우므로 보통 즉시).

## 1. 화면 구성 (2026-09 현재 11개 섹션 + 스튜디오)

좌측 위→아래: **AI 에이전트** → 적용 설정 → 페르소나 → 응답 규칙 → **시나리오 버튼**
(언어별 라벨·버튼별 에이전트) → **기본 대화내용**(내장 스크립트 7종) → **AI 기능** →
모더레이션 → 회귀 검증 → 변경 이력 → 답변 재사용. 우측: **AI 스튜디오**(미리보기) ·
**에이전트 코칭**.

상담 전환(핸드오프·deny-list)은 이 화면에 없습니다 — **[테넌트 설정] → 기본 설정 탭의
상담원 연결 카드**로 이전되었습니다.

## 2. 프롬프트 조립 순서 (RAG 응답)

```
[페르소나] → [Response rules: 규칙 목록] → [검색 근거(KB)] → [고객 질문]
```

- 페르소나는 시스템 프롬프트 맨 앞. 언어는 무엇으로 써도 됩니다 — 응답 언어는 세션
  언어(en/es/ko/vi/ja/zh 6종)를 따로 따릅니다.
- 사실 정보(배송비 등)는 페르소나가 아니라 지식 문서에 — 페르소나는 검색되지 않습니다.
- 답변 재사용에 걸린 질문은 이 조립 자체를 건너뛰고 저장된 답변을 재생합니다
  (모더레이션·카테고리 에이전트 범위는 그대로 적용).

## 3. 시나리오 버튼·기본 대화내용의 내부 동작

- 버튼 **라벨은 언어별 맵**으로 저장됩니다(단일 문자열 라벨은 편집 시 6개 언어로
  시드되고, 6개가 전부 같으면 저장 때 다시 문자열 하나로 접힘). 위젯 와이어 계약은
  "버튼당 문자열 1개"라 서버가 세션 언어로 해석해 내려보냅니다 — 캐시된 구버전 위젯도
  그대로 동작합니다.
- 버튼 중 **배송 조회 → `shipping_policy`**, **취소/환불 → `cancel_refund`** 두 개만
  내장 스크립트를 실행합니다(행 아래 힌트에 표시). 나머지 5개 액션은 스크립트가 없고,
  `메시지 보내기`는 라벨을 그대로 질문으로 전송합니다.
- **기본 대화내용** 카드가 내장 스크립트 **7종 전부**(후속 칩 전용 5종 포함)의 응답
  문구·고객 발화·후속 칩·답변 후 이동을 6개 언어로 편집합니다. 기본값이 필드에 채워진
  채 열리고, 그대로 두면 저장되지 않습니다. ⚠️ 과거의 "스크립트 문구 갱신은 개발팀
  요청" 안내는 폐기 — 콘솔에서 직접 편집합니다.

## 4. AI 기능 (엔진·파라미터)의 실제 동작

기능 5종(chat/rag/summary/assist/moderation)별로 엔진과 파라미터를 지정합니다.

- **엔진 출처 2곳**: 테넌트 자체 엔진([테넌트 설정 → 기본 설정]의 *AI 엔진* 카드 —
  내 API 키, 플랫폼 엔진보다 **우선**, 비용은 테넌트 계정으로 청구)과 플랫폼 제공
  엔진(`/admin/ai-engines`).
- **폴백 사슬**: 선택 엔진 불가 → 테넌트 기본 → 플랫폼 기본 → **stub**(데모 응답).
  폴백 횟수는 *AI 사용량* 카드에 경고로 집계됩니다(토큰 0 = 실응답 아님).
- **temperature(0~1)**: ⚠️ **Anthropic(Claude) 엔진에는 전송하지 않습니다**(현행
  모델이 샘플링 파라미터를 거부) — 입력해도 무시되며 OpenAI 계열에만 적용.
  적용되는 엔진에서는 rag 0.2~0.4 권장.
- **max_tokens**: 응답 길이 상한. 챗 답변은 512~1024면 충분.
- **임베딩은 이 화면에 없습니다**: 전 테넌트가 벡터 공간을 공유하므로 서버 환경변수
  (`VOYAGE_API_KEY`/`VOYAGE_MODEL`, voyage-4)로 전역 관리.
- 계측: 모든 호출의 토큰·청구 주체는 게이트웨이 한 곳에서 기록되어 *AI 사용량* 카드에
  기간·기능·엔진·청구 주체 축으로 집계됩니다(금액은 표시하지 않음, 보존 400일).

## 5. 모더레이션 규칙의 실제 동작

AI·상담원의 **모든 발신**을 발송 전에 검사합니다(FR-069/POL-020 — 비우회, 검사 실패
시 안전하게 **차단**).

| 작업 | 실제 동작 |
|---|---|
| 차단 (block) | 메시지 미전달(AI 답변이면 상담원 인계로 전환, 로그 기록) |
| 마스킹 (mask) | 매칭 부분만 ▇▇▇ 치환 후 전달 |
| 재작성 (rephrase) | LLM이 안전한 문장으로 재작성 후 전달 |
| (레거시) warn | 과거 데이터용 — 차단과 동일, 신규 생성 불가 |

- 유형: 단어/문구(포함, 대소문자 무시) · 정규식 · **문맥(LLM)**(moderation 기능 엔진이
  메시지마다 판정 — stub 상태면 판정 품질 없음).
- ⚠️ 4xx 거부는 서버 로그에 남지 않을 수 있습니다 — "로그에 없음 ≠ 통과".

## 6. 검증 루프의 내부 사실

- **미리보기(AI 스튜디오)** 세션은 `channel='preview'`로 저장되어 **대시보드·통계
  대화 수에서 제외**됩니다.
- **회귀 검증**의 골든 질문은 지식 보드 **시뮬레이션 골든셋 A/B**에도 재사용됩니다
  (문서 미포함/포함 2회 실행 — 질문당 LLM 2회 호출).
- **에이전트 코칭**은 승인 없이는 아무것도 바꾸지 않습니다. 제안 적용/거절/되돌리기와
  *변경 이력* 리비전 복원이 안전망입니다. 문구 변동은 정상이고, 신뢰도 하락·인계
  증가가 진짜 이상 신호입니다.

## 부록 — 반영 시점 요약

| 설정 | 반영 |
|---|---|
| 페르소나 / 응답 규칙 / 모더레이션 | 저장 즉시(캐시 무효화), 최대 60초 |
| 시나리오 버튼 / 기본 대화내용 | 저장 즉시 — 위젯은 다음 로드/새 세션부터 |

| 에이전트 배정 | **세션 시작 시 1회 고정** — 진행 중 세션은 바뀌지 않음(라이브챗 [지정]으로 변경 시 다음 응답부터) |
