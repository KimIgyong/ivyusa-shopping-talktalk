## 2. 설계상 중요한 결정

1. **미리보기는 모의가 아니라 실제 파이프라인** — 페르소나·응답 규칙·KB 검색·모더레이션·시나리오
   스크립트가 그대로 실행됩니다. 검증 목적상 "실제와 같은 것"이 아니면 의미가 없기 때문입니다.
2. **운영 격리** — `sessions.channel='preview'` 세션은 에스컬레이션 이벤트를 발행하지 않고
   대화를 WAITING으로 바꾸지 않습니다. 즉 **상담원 알람·상담 큐·CJM 분석에 미리보기가 섞이지
   않습니다**. 관리자는 정보주체가 아니므로 동의 게이트도 면제됩니다.
3. **빈 값 = 기본값** — 시나리오 오버라이드는 비운 항목이 내장 스크립트로 폴백하고, 전부 비우면
   저장 시 항목 자체가 제거됩니다(= 초기화). 번역하지 않은 언어는 EN으로 폴백합니다.
4. **근무시간 외 메일함 미설정 시 상담원 호출로 폴백** — 요청을 조용히 삼키는 것보다 낫다는 판단.
5. **명시적 "상담원 연결"도 동일 라우팅** — 근무시간 외에는 위젯의 "연결 중" 문구 대신 안내
   문구를 대화에 저장해 고객이 실제 상황을 보게 했습니다.

## 5. 제약 및 후속 과제

1. **스테이징 관리자 로그인 미보유** — 콘솔 비밀번호가 변경되어 있어 미리보기 패널의 화면
   조작 검증은 하지 못했습니다(백엔드 경로는 401/공개 경로로 검증). **운영자가 브라우저에서
   /ai-setting 우측 패널을 한 번 확인**해 주시기 바랍니다.
2. **공휴일 미지원** — 근무시간은 요일·시각만 판정합니다(계획서 §5-2 합의). 공휴일 캘린더는 후속.
3. **오프아워 메일은 전역 SMTP 설정에 의존** — `SMTP_HOST`가 비어 있으면 발송되지 않습니다.
   콘솔은 메일 주소 미설정 시 경고를 표시하지만 SMTP 자체 상태는 표시하지 않습니다.
4. **타깃 알림은 대표 1명 저장** — 담당자를 여러 명 지정해도 알람 행에는 첫 번째 담당자가
   기록됩니다(중복 알람 방지). 다중 타깃이 필요하면 별도 조인 테이블이 필요합니다.
5. 미리보기 대화는 DB에 남습니다(계획서 §5-1 승인안). 이력 화면 채널 배지 표시는 후속 과제.
