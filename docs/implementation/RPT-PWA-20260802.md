## 1. 구현 방식 (멀티 에이전트)
백엔드(P1)와 PWA 프론트(P2/P3)를 **병렬 서브에이전트 2개**로 동시 구현
(경로 분리: apps/api/push↔apps/pwa, 오케스트레이터가 통합·검증·배포·문서 수행).
소요: 병렬 구현 ~12분, 이후 통합 검증에서 결함 2건(D1 migration 순서, D2 nginx
stale mount) 발견·수정 — 에이전트 산출물 자체는 무결(typecheck/테스트 전부 통과).

## 2. 무엇을 구현했나

### P1 — 백엔드 Web Push (apps/api)
- `WebPushProvider` 신규 (`web-push` 라이브러리, VAPID): 구독 JSON 파싱 → sendNotification
  (TTL 3600), **404/410 → 자동 revoke 티켓**, VAPID 미설정 시 경고 후 무발송(부트 안전).
- `PushService`: 디바이스 행 `provider`(expo|webpush)별 **프로바이더 라우팅** — 한 고객이
  RN 앱과 PWA를 동시 사용 가능. register가 Web Push 구독 수용(https 엔드포인트+키 검증,
  실패 시 E5006), upsert 기준을 token → **token_hash(SHA-256)**로 이전.
- `GET /push/vapid-key` (@Public) — 클라이언트 구독용 공개키.
- 스키마: `device_tokens.token` TEXT 확장(구독 endpoint>255자), `token_hash` varchar(64)
  UNIQUE 신설 + 기존 expo 행 backfill (`sql/migration_push_webpush.sql`).
- RN 앱 무수정 (provider 기본값 'expo').

### P2/P3 — apps/pwa (신규 워크스페이스, `/app/` 서빙)
- Vite + React 18 + react-router + React Query + i18next(en/es/ko 73키×3), strict TS.
- **manifest + Service Worker**: 푸시 표시, 클릭 시 category 딥링크(chat→/app/chat,
  shipping/payment→/app/orders, 기타→/app/alerts), 앱 셸 캐시(API는 미캐시), sw는 no-cache.
- **설치 UX (W-8)**: Android `beforeinstallprompt` 배너 / iOS Safari "공유→홈 화면에 추가"
  가이드 시트(iOS는 설치형만 푸시 가능 — 권한 프롬프트 전에 감지), standalone 감지로
  설정 화면 푸시 토글 상태 분기(활성/설치 유도/권한 거부 안내).
- 화면 4종: 상담(동의 게이트+5초 폴링+시나리오 칩), 주문(게스트 조회+상세+배송 스텝),
  알림(in_app 필터+읽음+30초 배지), 설정(언어·push 토글 3그룹·CCPA 옵트아웃).
  DSAR 내보내기/삭제는 verified 불가(C4)로 미노출+안내만. 쇼핑은 새 탭 이동(C1).
- 세션: localStorage 토큰, 부트 시 SW 등록→ensure→권한 기허용 시 멱등 재구독.

### P4 — 스테이징 서빙
- `Dockerfile.pwa` + `nginx.pwa.conf`(sw no-cache, manifest MIME, assets immutable,
  X-Frame-Options DENY) + compose `pwa` 서비스 + edge nginx `/app` 라우트.
- deploy 스크립트 개선: edge nginx **reload → force-recreate** (단일 파일 bind-mount의
  git-pull inode 고착 문제 — FIX 문서 참조).

## 7. 예방 패턴 (메모 승격)
- **단일 파일 bind-mount + git pull(rename) = stale inode** — reload는 옛 설정을 다시
  읽는다. 배포 스크립트가 recreate를 보장할 것 (FIX 문서).
- **MODIFY→TEXT는 해당 컬럼 인덱스 제거 후에** (MySQL 1170) — migration 순서 명시.
- 새 라우트 검증은 상태코드만으로 부족 — SPA 폴백은 200을 돌려준다.
  content-type/본문까지 확인.
