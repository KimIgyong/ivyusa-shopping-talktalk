## 3. 테스트가 검출한 결함 (수정 완료)

**D-01 — 허브 타임스탬프 타임존 부재로 활성 대화 유실 (PR-M2에서 수정)**
아메바톡/릴레이의 `last_message_time`은 `'YYYY-MM-DD HH:mm:ss'`로 **타임존이 없다.**
이를 파싱해 UTC 커서와 비교하면 실제보다 과거로 해석되어 **활성 대화를 "변경 없음"으로 건너뛰고
고객 메시지를 조용히 삼킨다** — 예외도 로그도 남지 않는 유형(REQ G3와 같은 계열의 실패).
→ 파싱 비교를 버리고 **타임스탬프 문자열 정확 비교**(대화별 Redis 워터마크)로 변경.
워터마크는 메시지를 읽은 **뒤** 기록하므로 중간 실패 시 건너뛰지 않는다. 회귀 케이스 U-35/U-36.

## 5. 엣지 케이스 메모

- 동시 배달로 같은 스레드가 두 번 생성되면 유니크 충돌 → 승자 행을 재조회(정상 경로).
- 인입 처리 도중 프로세스가 죽으면 매핑 이전 상태 → 재배달 시 정상 재처리(at-least-once).
- 채널 비활성화 중 쌓인 아웃박스는 재활성화 시 드레인된다(U-29).
- 허브 하나가 죽어도 다른 허브·직접 채널은 계속 동작(U-47).
