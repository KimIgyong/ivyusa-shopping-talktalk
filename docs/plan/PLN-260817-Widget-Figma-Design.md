# PLN-260817-Widget-Figma-Design

Figma "TalkTalk" **Master Shots** 디자인을 채팅 위젯(`apps/widget`)에 적용하는 구현 계획.

- 작성일: 2026-08-17
- 선행 문서: `docs/analysis/REQ-260817-Widget-Figma-Design.md`
- 디자인 원본: `design/screens/34~69` (FILE_KEY `Y3ql0jG7uicOMDCfQS5ApB`)
- **UI 변경 있음** → ASCII 와이어프레임 §3 포함

## 0. 확정 전제 (REQ §6)

| 항목 | 결정 |
|---|---|
| 대상 프레임 | 반출본 34–69 |
| 탭 IA | **상단 2탭 `Notifications \| Chat`** — 하단 3탭 바 및 주문 탭 소멸 |
| 유지 요소 | AI 고지 바 · 헤더 닫기(X) · 언어 스위처 · 첨부(클립) 버튼 — **디자인 대비 명시적 편차** |
| 봇 아바타 | 표시하지 않음 |
| 범위 | 리스킨 + 기능 추가(G-08/10/11/12) 전부 |
| 반응형 | 모바일 전체화면 바텀시트 유지, 데스크톱 폭만 380→404px |

## 1. 목표 / 비목표

**목표**
1. 위젯 팔레트·타이포·컴포넌트 형태를 Master Shots에 일치시킨다.
2. 하단 3탭을 상단 2탭 세그먼트로 전환하고, **주문 탭의 기능을 하나도 잃지 않고** 재배치한다.
3. 알림 행에 타입 아이콘·신규 하이라이트를 도입한다(G-08/09).
4. `배송` 필터를 가로 4단 스테퍼 + `배송조회` CTA 화면으로 만든다(G-11/12).
5. `리뷰` 필터에서 `⭐ 리뷰 쓰기`로 기존 `ReviewForm`을 연다(G-10).

**비목표**
- 콘솔(`apps/web`) 디자인 — Figma의 `Admin Dashboard Design` 페이지는 이번 범위 밖.
- 테넌트별 테마 색상 설정화 — 현재 색상은 빌드타임 상수이며 그대로 둔다.
- 디자인의 IVY 고정 문구(`IVY Beauty`, `1588-0000`, `help@ivy.com`) 이식 — **금지**(REQ §5-1).

## 4. 단계별 계획

목적지(알림 탭)를 먼저 만들고 출처(주문 탭)를 나중에 제거한다 — 순서를 뒤집으면 중간 상태에서
주문 기능이 접근 불가가 된다.

### S1 — 디자인 토큰 (선행, 독립)
- `apps/widget/tailwind.config.js` — §2 표대로 팔레트 교체, `review`/`highlight`/`surface-muted` 추가.
- 파급: `primary-*`를 쓰는 **모든** 위젯 컴포넌트가 자동 반영된다. 콘솔(`apps/web`)은 별도 config이므로 무영향.
- 산출: 색상만 바뀐 위젯. 이 시점에서 스테이징 배포 없이 로컬 확인.

### S2 — 알림 탭 재구성 (주문 콘텐츠 흡수)

### S5 — 리뷰 CTA (백엔드 스키마 변경 포함)
**문제**: `ReviewService.requestReview`가 `orderItemId`를 이벤트에 실어 보내지만(`review.service.ts:106-113`)
`NotifyInput`에 해당 필드가 없어 **조용히 버려진다**. 알림 행에서 `ReviewForm`(요구 인자 `orderItemId`)을
열 식별자가 없다.

- `notifications` 테이블에 `ref_type VARCHAR(24) NULL`, `ref_id BIGINT NULL` 추가.
- `NotifyInput`/`Notification` 엔티티/`notification.mapper`/`NotificationResponse`에 전파.
- `requestReview`가 `refType:'order_item', refId:orderItemId`로 발행.
- 위젯: `category==='review' && refType==='order_item'` → `⭐ 리뷰 쓰기` 표시 → `ReviewForm({orderItemId: refId})`.
- **기존 행은 `ref_id`가 NULL** → CTA 미표시(정상 폴백). 백필하지 않는다.

## 6. 마이그레이션 (S5)

```sql
-- sql/migration_notification_ref.sql
ALTER TABLE notifications
  ADD COLUMN ref_type VARCHAR(24) NULL AFTER link_url,
  ADD COLUMN ref_id   BIGINT      NULL AFTER ref_type;
CREATE INDEX idx_notif_ref ON notifications (ref_type, ref_id);
```
- 적용 순서: **스테이징 DB 선적용 → 코드 배포**. 스테이징은 `DB_SYNCHRONIZE=false`.
- 롤백: `ALTER TABLE notifications DROP COLUMN ref_type, DROP COLUMN ref_id;` (구코드 무해).
- PR 본문에 `## Migration` 섹션 필수.
- 착수 전 `pre-deploy-check` 스킬 사용.
