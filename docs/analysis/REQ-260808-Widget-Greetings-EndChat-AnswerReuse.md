## A. 위젯 문구 설정화 (요구 1·2·4)

### AS-IS
- **환영문구가 위젯 i18n에 하드코딩** — `apps/widget/src/i18n/locales/{en,es,ko}.ts`의
  `chat.welcome`/`chat.welcomeNamed` 문장 안에 "IVY USA" 브랜드가 박혀 있음.
  ⚠️ **멀티테넌트 결함**: Cafe24 테넌트(amoebaorder) 방문객도 "IVY USA에 오신 것을 환영합니다"로 인사받는 상태.
- **위젯 헤더가 `notificationCenter`("알림 센터") 고정** (`WidgetPanel.tsx:56`) — 테넌트명 미표시.
  `Tenant.name`은 콘솔 로그인용 `GET /tenants/by-slug`에만 노출되고 위젯 경로(`/session/ensure` 응답)에는 없음.
- **환영 버블은 렌더 아티팩트** (`ChatTab.tsx:270-282`) — DB 미저장, 상담원 트랜스크립트에 없음, 패널 열 때마다 재출력.
- **로그인 인사**: 로그인하면 `customerName`이 `/session/ensure`로 위젯에 이미 도달 → 버블 문구가
  `welcomeNamed`로 바뀌는 수동적 전환뿐. 별도 인사 메시지 이벤트 없음. (이름 데이터는 확보되어 있음 — 문구·설정만 없음)
- **설정 인프라**: tenants 타입드 컬럼(login_mode·timezone, `PATCH /tenants/widget-settings`) +
  `tenant_ai_config` JSON(페르소나·시나리오·핸드오프 — **언어별 고객 노출 카피 저장 전례** 있음: `ScenarioOverride.reply {EN|ES|KO}`).
  위젯 공개 설정 전달 경로는 `/session/ensure` 응답이 유일.

### TO-BE (FR)
- **FR-A1 테넌트 표시명**: 위젯 헤더·인사문에 테넌트 설정값 사용(기본 `Tenant.name`). 하드코딩 "IVY USA" 전면 제거.
- **FR-A2 첫 방문 안내문구**: 신규 세션 첫 오픈 시 표시되는 기본 안내 멘트를 콘솔에서 작성/수정(EN/ES/KO, 빈 값이면 언어별 기본문).
- **FR-A3 로그인 인사말**: 고객명 인식 시 "{name}님 반갑습니다. 무엇을 도와드릴까요?" 형식 출력, 템플릿({name} 치환) 콘솔 설정.
- **FR-A4 전달 경로**: `/session/ensure` 응답에 위젯 문구 번들(표시명·첫방문 안내·로그인 인사) 추가 — 신규 공개 엔드포인트 불필요(적정기술).
- **FR-A5 콘솔 UI**: /settings "위젯" 카드(로그인모드·타임존 옆)에 문구 3종 편집 + 저장 토스트(dev-kit §4.3).

### 결정 필요 (D)
- **D-A1**: 환영/안내 버블을 현행처럼 **렌더 전용**으로 유지할지(권장 — 저장 시 트랜스크립트·통계 오염과 매 오픈 중복 저장 문제), 아니면 대화에 영구 기록할지.
- **D-A2**: 문구 저장 위치 — ①`tenant_ai_config` JSON 확장(카피 전례 있음, 마이그레이션 불필요) vs ②tenants 컬럼 추가(SQL 필요). ① 권장.
- **D-A3**: "첫 방문" 정의 — 신규 세션 생성 시 1회(localStorage/세션 플래그) vs 패널 열 때마다. 전자 권장(요구 문언 부합).

## B. 상담종료 (요구 3)

### AS-IS
- **상담원 종료는 이미 구현·운영 중**: `POST /agent/conversations/:id/end` → `status=ENDED, endedAt`,
  배정 해제, 감사로그, 콘솔 종료 버튼(`LiveChatPage.tsx:355`).
- **고객(위젯) 측 종료는 전무** — 버튼도 엔드포인트도 없음. `status='ended'`를 받아도 UI 변화 없음.
- **재시작 시맨틱은 공짜**: `getOrCreateConversation`이 open 상태만 찾으므로, 종료 후 다음 메시지는 자동으로 새 대화 생성.
- 세션(로그인)은 종료 개념 없음 — 대화 종료와 별개.

### TO-BE (FR)
- **FR-B1** 위젯 채팅 탭에 "상담 종료" 버튼: 확인(취소 가능) → `@Public` 종료 엔드포인트(세션 토큰 검증, 본인 대화만) → `ENDED` 처리.
- **FR-B2** 종료 후 위젯: "상담이 종료되었습니다" 시스템 표시 + 새 메시지 입력 시 새 상담 시작(기존 시맨틱 재사용).
- **FR-B3** 상담원 종료 시 위젯에도 종료 상태 반영(폴링으로 status 이미 수신 — 표시만 추가).
- **FR-B4** 감사로그·(선택) 종료 사유 없이 심플하게 — 1차는 버튼+상태 표시만.

### 결정 필요
- **D-B1**: 고객 종료 시 **대화만 종료**(로그인·세션 유지, 권장) vs 세션/로그인까지 해제. 요구 문언 "세션 종료/대화종료" — 로그아웃까지 원하시면 범위 확대.

## C. 유사질문 답변 재사용 (요구 5·6)

### AS-IS
- **대화는 이미 전량 저장**(요구 6의 절반은 충족): `messages` 테이블(user/ai/agent/system, intent·confidence·retrieval_trace 포함, 365일 보존).
- **유사질문 인프라 일부 존재**: `question_clusters`(질문 임베딩 centroid, cosine 0.8, 일배치) — 단 **통계용**이라
  답변 연계 없음, 실시간 조회용 ANN 인덱스 없음(MySQL JSON). Qdrant는 `kb_documents` 컬렉션만.
- **AI 파이프라인**(`ChatService.handleUserMessage`): 동의 게이트 → 저장 → 상담원 소유 체크 → PII 스크럽 → 의도분류
  → 주문 컨텍스트 → **RAG+LLM**(`chat.service.ts:332`) → **모더레이션(필수, FR-069)** → 에스컬레이션 판단 → 저장.
- **답변 캐시는 전무**.

### TO-BE (FR)
- **FR-C1 답변 재사용 저장소**: 재사용 가능한 Q&A 쌍(질문 텍스트+임베딩, 답변, 출처 메타)을 테넌트 스코프로 적재.
  Qdrant에 질문 임베딩 컬렉션 신설(기존 `QdrantService` 패턴 재사용) + MySQL 메타 테이블.
- **FR-C2 적재 기준(안전 필터)**: 다음을 **모두** 만족하는 답변만 재사용 후보로 저장 —
  ① 상담원 답변 또는 인용(citation) 있는 고신뢰(threshold 이상) AI 답변, ② `needsOrderData` 아님(주문·개인 맥락 답변은 재사용 금지),
  ③ PII 스크럽 통과, ④ 모더레이션 BLOCKED 이력 없음, ⑤ 해당 대화가 low_confidence 에스컬레이션으로 끝나지 않음.
- **FR-C3 조회 시점**: LLM 호출 직전(`chat.service.ts:332`) — 질문 임베딩 1회로 유사도 검색, **고임계값**(예 ≥0.92) 히트 시
  LLM 생략하고 캐시 답변 사용. **모더레이션 게이트는 그대로 통과**(캐시 답변도 FR-069 적용, 게이트 앞 삽입 필수).
- **FR-C4 응답 계약 유지**: 캐시 히트도 `RagAnswer` 형태(text·confidence·citations)로 합성 — 에스컬레이션 로직·retrieval_trace 호환.
  trace에 `answeredFrom: 'reuse'` 기록(통계·디버깅).
- **FR-C5 무효화**: KB 문서 수정/시나리오 변경 등 지식 갱신 시 관련 캐시 무효화 또는 TTL(예 30일). 콘솔에서 재사용 답변 목록 조회·비활성화.
- **FR-C6 절감 효과 계측**: 재사용 응답 수/LLM 호출 절감을 통계 대시보드 dimension으로 노출(기존 question_stats 확장).

### 제약·주의 (설계 원칙)
- **임베딩 호출은 여전히 필요**(유사도 판단) — 절약 대상은 LLM completion. stub 엔진 테넌트는 임베딩이 의사값이라 재사용 부적합 → 실엔진 테넌트만 활성.
- 유사도 임계값이 낮으면 **오답 재사용**(다른 상품·다른 정책 질문에 과거 답) 위험 — 높은 임계값에서 시작해 통계 보고 조정.
- 시간 민감 답변(재고·프로모션·배송 일정) stale 위험 → 적재 제외 카테고리 또는 짧은 TTL 필요.
- 언어 불일치 방지: 질문 언어(lang)별 매칭.

### 결정 필요
- **D-C1 재사용 소스 범위**: ①상담원 답변만(최고 신뢰, 적재량 적음) ②상담원+고신뢰 AI(권장) ③모든 AI 답변(비권장).
- **D-C2 히트 시 표시**: 재사용 답변임을 고객에게 표기할지(무표기 권장 — 동일 품질 답변) / 콘솔 trace에는 항상 기록.
- **D-C3 관리 UI 범위**: 1차에 콘솔 목록+비활성화까지 포함할지, 2차로 미룰지.
