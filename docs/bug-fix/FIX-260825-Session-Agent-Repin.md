# FIX-260825 세션 재사용 시 페이지 지정 에이전트 미반영 (시나리오 스코프 "여전히 안 됨"의 진짜 원인)

- 신고: go2joy `/partner`(hotel-partner 임베드)에서 기본+랜딩게스트 전용 delivery_status 버튼이 노출됨 — PR #373(위젯 폴백 수정) 이후에도 재현.

## 근본 원인 (재현 기반)

- DB·콘솔 저장·서버 필터·**신규 세션**은 전부 정상: agent_code=hotel-partner로 새로 만든 세션은 핀=10, delivery_status 정확히 제외, 표시명 오버라이드까지 동작(스테이징 실측).
- 문제는 **세션 재사용**: 위젯은 세션 토큰을 영속하고, `SessionService.ensure()`는 기존 토큰이면 **그대로 반환**(핀은 생성 시 1회 — PLN-260820 설계). 방문자가 메인 페이지(기본 핀)에서 세션을 만든 뒤 `/partner`(hotel-partner 임베드)로 가도 **기존 default 핀 세션이 재사용**되어, 페이지의 `agent` 선언이 영구히 무시된다. default 핀에는 delivery_status가 허용이므로 "스코프가 안 먹는" 것처럼 보였다. 실제 스테이징 sessions에 tenant 4 / ai_agent_id=5(default) 행으로 확인.

## 수정 (최소 변경)

`ensure()`의 기존-세션 분기: **페이지가 명시한 agent_code가 유효(테넌트 내 active 코드로 해석)하고 현재 핀과 다르면 재핀** + 토큰→세션 캐시(30s) 버스트. 코드가 없거나(unknown 포함) 해석 실패면 기존 핀 유지 — 에이전트 파라미터 없는 페이지가 기존 핀을 default로 되돌리는 일은 없어야 함.

## 영향

- 페르소나·시나리오 버튼·표시명/인사말이 페이지 전환을 따라감(다음 응답부터). 같은 코드 재방문은 무쓰기.
- 유닛 5케이스(`session.service.repin.spec.ts`): 재핀·NULL핀 재핀·동일코드 무쓰기·코드부재/미지 코드 핀유지.

## 예방 패턴

"생성 시 1회" 캐시/핀 설계는 **재진입 입력이 달라질 수 있는지**를 함께 물어야 한다. 입력(페이지 선언)이 세션보다 자주 바뀌면, 1회 고정은 '최초 방문 페이지가 영원히 이긴다'는 숨은 규칙이 된다.
