# PLN-260818-Widget-Orders-Tab

주문탭을 "주문 관련 알림 모음"에서 **주문 목록**으로 바꾸는 계획.

- 작성일: 2026-08-18
- 선행: `REQ-260818-Widget-Orders-Tab.md`
- 기반: PLN-260817(탭 구성) · PLN-260818(테마) 구조 위에 얹음

## 1. 방침

주문탭에 목록을 **새로 만들지 않는다.** `GET /orders`, `OrderDetailView`,
`TrackingStepper`, `ReviewForm`은 이미 다 있고 동작한다. 없는 것은 **진입로**뿐이므로,
이번 작업의 대부분은 배선이다. 새 화면을 그리면 지금 배송 칩이 쓰는 구현과 갈라져
같은 것이 두 벌 생긴다 — PLN-260817이 `OrdersTab`을 12줄로 유지한 이유와 같다.

## 2. 결정안 (REQ Q1~Q4)

| # | 결정 | 근거 |
|---|---|---|
| Q1 | `결제` 칩을 **`주문내역`(목록)으로 교체**. 칩은 4개 유지: `주문내역`·`배송`·`리뷰`·`문의`. 진입 칩 = `주문내역` | **스테이징 전체 `payment` 알림 0건** — 한 번도 내용을 가진 적 없는 칩이다. 결제 알림 카테고리 자체는 알림탭 `전체`에 계속 흐르므로 기능 삭제가 아니다 |
| Q2 | **90일 · 20건**, 이후 "더보기"는 몰 마이페이지 링크 | 채팅 인라인 카드(10건/30일)는 대화 흐름을 안 끊으려는 값이고, 목록 탭은 목적이 다르다. Cafe24 몰 정책 상한(3개월)과도 맞는다 |
| Q3 | 상태 라벨은 **알려진 값만 i18n 매핑, 미지의 값은 원문 표시** | `status_ui`는 Shopify 표기 원문이라 몰마다 값이 다르다. 매핑 실패가 빈 뱃지가 되면 안 된다 |
| Q4 | 취소/환불 **노출**(뱃지 회색/적색) | 안 보이면 "주문이 사라졌다"가 된다. 숨기는 편이 문의를 늘린다 |

## 4. 단계

### S1 — 주문 목록 컴포넌트 (`OrderList.tsx`)
- `useOrders`(기존 훅) 재사용, `isShipmentish` **필터 없이 전체 상태** 렌더.
- 행: 주문번호·상태 뱃지·대표품목·주문일·금액. 배송중(`shipping`/`transit`)이면
  `TrackingStepperH`를 행 안에 표시 — 배송 칩의 카드와 같은 컴포넌트를 쓴다.
- 행 클릭 → `onOpenOrder(id)` (상세 화면은 `NotificationsTab`이 이미 띄운다).
- 빈 상태 2종(주문 없음 / 비로그인)은 기존 문구 컴포넌트 재사용.

### S2 — 칩 교체
- `tab-chips.ts`: `ORDER_CHIPS`의 `payment` → `orders`(주문내역)로 교체, 첫 자리 유지
  (= 진입 칩). `chipsFor` 흡수 규칙은 그대로 — 주문탭을 끄면 알림탭이 이 칩까지 받는다.
- `NotificationsTab`: `notifFilter === 'orders'`면 `OrderList` 렌더
  (현재 `isShipping` 분기와 같은 자리).
- ⚠️ **저장된 칩 마이그레이션**: 기존 사용자의 localStorage에 `payment`가 남아 있으면
  `chipBelongsTo`가 false → `defaultChip`으로 폴백하므로 자동 해소된다. 확인 필요.

### S3 — 상태 라벨 다국어
- `orders.status.*` 키 6개(결제완료·준비중·배송중·배송완료·취소·환불) × 6개 언어.
- 매핑은 `status_internal` 우선(`paid`/`shipping`/`delivered`/`cancelled`/`refunded`),
  실패 시 `status_ui` **원문 그대로**. 빈 뱃지를 만들지 않는다.

### S4 — 조회 범위
- `listOrders`에 `days`/`size` 인자 추가. 인라인 카드는 30일·10건 유지(호출부 기본값),
  목록은 90일·20건.
- 20건을 다 채우면 "더 이전 주문 보기" → `storefront_url` 기반 마이페이지 링크
  (기존 Cafe24/Shopify 안내 패턴 재사용).

### S5 — 백엔드 정리
- `listForSession` 쿼리에 `tenant_id` 조건 추가(CLAUDE.md §2 규약). 현재 유출은 없지만
  규약 위반 상태를 남기지 않는다.
- `DAYS_WINDOW_MAX = 90` 확인 완료 — 90일은 현재 상한에 정확히 걸리므로 **백엔드 변경 불필요**.
  (91 이상을 원하면 상한 상향이 별도로 필요하다.)

### S6 — 테스트 · 문서
- 단위: 상태 매핑 폴백, 전체 상태 노출(결제완료 주문이 목록에 뜬다), 칩 마이그레이션,
  `tenant_id` 필터.
- TCR/RPT 작성, 스테이징 배포 후 **고객 8(주문 #1004 Confirmed)로 실제 노출 확인** —
  이번 제보의 재현 계정이므로 이게 통과해야 해결이다.

## 5. 사이드 임팩트

| 영역 | 영향 | 대응 |
|---|---|---|
| 배송 칩 | 그대로 유지(라이브 추적 뷰) | 목록과 컴포넌트 공유라 이중 구현 없음 |
| 알림탭 | 변화 없음 | 결제 알림은 원래 `전체`에 흐름 |
| 주문탭 OFF 테넌트 | 칩 흡수로 알림탭이 `주문내역`까지 받음 | 흡수 규칙 회귀 테스트 |
| 채팅 인라인 주문 카드 | 호출부 기본값 유지로 무변경 | 30일·10건 그대로 |
| 스키마 | **없음** | 마이그레이션 불필요 |
| 기존 사용자 칩 상태 | `payment` 저장분 → 자동 폴백 | S2에서 확인 |

## 6. 규모

프런트 3파일 신규/수정 + 백엔드 2줄 + i18n 6개 언어 × 6키. 스키마 변경 없음.
새 화면은 목록 하나뿐이고 상세·추적·리뷰는 전부 기존 자산 재사용.
