## 1. 판정 기준

- **충족**: 구현과 운영 증빙이 모두 확인됨
- **부분 충족**: 구현은 있으나 적용 범위, 실패 처리, 정책 또는 증빙이 부족함
- **미충족**: 구현·정책·운영 증빙이 확인되지 않음
- 아래 체크박스는 후속 작업의 완료 기준이다. 코드 변경은 PLN 승인 후 시작한다.

## 4. 권장 실행 순서

1. **P0 정책·계약**: 개인정보처리방침/고지, DPA·처리자 대장, 사고 대응 계획, 암호화·백업 기준을 법무·보안 책임자와 승인한다.
2. **P0 코드·운영 통제**: 동의 fail-closed 및 저장 실패 UX, 암호화 백업/복구, 강한 비밀번호·MFA, 저장소 암호화 증빙을 구현한다.
3. **P1 데이터 거버넌스**: 데이터 인벤토리, 전체 보존/파기 매트릭스, opt-out 전파, DLP, 접근 재검토·감사 로그 확장을 수행한다.
4. **P1 AI 거버넌스**: AI 전송 최소화, 자동화 의사결정 심사·사람 검토·opt-out 게이트를 배포 프로세스에 편입한다.

## 5. 완료 판정

- 각 P0 항목은 정책/계약 문서, 구현 PR, 운영 환경 증빙, 담당자 승인, 테스트 또는 훈련 기록을 모두 갖춰야 완료로 판정한다.
- P1 항목은 데이터 인벤토리와 위험도 기준으로 기한·소유자를 지정하고 월간 점검에서 진행 상태를 갱신한다.
- 본 문서는 코드 변경 전 요구사항 기준선이다. 후속 구현은 항목별 PLN, TCR, RPT를 작성하고 승인 후 진행한다.
