## 1. 단위 테스트 (신규 8건, 전부 통과)

이 기능의 가치는 두 가지가 맞아야 성립한다 — **질문이 실제로 전부 물어졌는가**, 그리고
**비교가 근거 없는 결론을 내지 않는가**.

| # | 케이스 | 기대 | 결과 |
|---|---|---|---|
| G-01 | 빈 세트로 실행 | **E4017 거부** — 빈 통과는 통과가 아니다 | ✅ |
| G-02 | 활성 질문 전부 질의·기록 | 순서대로 2건 질의, 항목 2건 저장 | ✅ |
| G-03 | 중간 질문 실패 | 런 전체를 잃지 않고 **error로 기록 후 계속** | ✅ |
| G-04 | 상한 초과 세트 | 20건만 실행 + **`truncated` 표시** (조용한 절단 금지) | ✅ |
| G-05 | config 해시 | 같은 설정=같은 해시, 규칙 추가=다른 해시 | ✅ |
| G-06 | 비교 신호 | 신뢰도Δ·인용변경·문구변경 보고, **판정 문구 없음** | ✅ |
| G-07 | 같은 해시 두 런 비교 | **`sameConfig=true`** — 차이는 효과가 아니라 변동 | ✅ |
| G-08 | 세트가 바뀐 뒤 비교 | 질문을 **텍스트로 매칭**, 없는 쪽은 null | ✅ |

**G-04가 중요한 이유**: 일부만 실행하고 완료처럼 보이는 런은 없는 것보다 나쁘다 — 대부분 묻지도
않고 "다 통과"로 읽힌다.

**G-07이 이 PR의 핵심 주장**이다. 같은 설정으로 두 번 돌린 비교는 "모델이 스스로 얼마나 움직이는가"를
재는 것이지 변경의 효과가 아니다. 이 구분이 없으면 모든 diff가 회귀로 보인다(W3 실측 O-1).

## 2. 통합 검증 (로컬 실기동, 수행 완료)

`PORT=3013`, 마이그레이션 선적용. 로컬 코칭 엔진은 stub(무키).

| # | 검증 | 결과 |
|---|---|---|
| I-01 | 마이그레이션 적용 | ✅ `golden_questions` / `golden_runs` / `golden_run_items` 생성 |
| I-02 | 실기동·라우트 | ✅ 부팅 정상, golden 7개 + `apply-verified` 매핑 확인 |
| I-03 | 빈 세트 실행 | ✅ **E4017** "Add a regression question first" |
| I-04 | 질문 2건 추가 → 실행 | ✅ run #1 `manual`, 문항 2, config 해시 기록 |
| I-05 | 노이즈 런 → 비교 | ✅ `sameConfig=true`. stub은 결정적이라 Δ 전부 0 — 판정 로직 자체는 정상 |
| I-06 | **`apply-verified` 순서** | ✅ base=`baseline`(변경 전 해시) → 제안 `applied` → target=`after`(변경 후 해시, proposalId 기록), **`sameConfig=false`** |

⚠️ **I-05의 한계**: 로컬 stub은 같은 입력에 같은 답을 주므로 **실제 변동 폭을 측정하지 못했다.**
노이즈 런의 진짜 값은 실 LLM에서만 나온다(§3 S-02).

## 3. 미수행 — 스테이징 실 LLM (배포 후)

| # | 항목 | 확인 방법 |
|---|---|---|
| S-01 | 회귀 카드 표시·질문 CRUD | `/ai-setting`에서 추가·삭제·개수 상한 |
| S-02 | **노이즈 실측** — 같은 설정에서 답변이 실제로 얼마나 흔들리는가 | 노이즈 런 2회. **이 수치가 앞으로 "의미 있는 차이"의 기준선이 된다** |
| S-03 | `apply-verified` 실 LLM | 제안을 검증하며 적용 → 비교 모달에 전/후 |
| S-04 | W3 O-1 재현 | 공감 규칙을 **검증하며 적용**해, 규칙이 답변을 실제로 바꾸는지 여러 문항으로 판단 |
| S-05 | 실패 항목 처리 | Voyage rate limit 시 해당 문항만 error, 런은 완료 |
| S-06 | 21문항 이상일 때 `truncated` 배지 | |

**S-04가 이 작업의 최종 목표다.** W3에서 "규칙을 적용했는데 답변이 안 바뀐 것 같다"를 답변 하나로는
판단할 수 없었다. 이제 여러 문항의 전/후와 노이즈 기준선을 함께 놓고 볼 수 있는지 확인해야 한다.
