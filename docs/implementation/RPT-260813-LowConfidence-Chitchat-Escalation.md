## 2. 설계에서 의도적으로 선택한 것

**검색을 건너뛴 것이 핵심입니다.** "hello"로 지식베이스를 뒤지면 결론은 언제나 "닮은 문서 없음"이고, **그 결론이 이관 판단의 입력**이었습니다. 판정을 검색 앞에 두면 그 고리가 끊깁니다. 덤으로 임베딩·벡터 검색·긴 프롬프트가 짧은 생성 1회로 바뀌어 **비용도 줄었습니다** — 고치면서 싸지는 흔치 않은 경우입니다.

**두 관문은 기본이 닫혀 있습니다.** 분류 실패(`fallback`)는 신호가 아니고, 0.6 미만도 아닙니다. 이 기능의 나쁜 실패는 **진짜 질문에 인사만 돌려주고 사람도 붙지 않는 것**이라, 애매하면 기존 경로(답변 시도 → 필요 시 이관)로 보냅니다.

**인사+질문은 질문입니다.** 프롬프트에 이 케이스를 명시했습니다. `안녕하세요, 배송 언제 오나요?`가 `delivery`로 잡히는 것이 이 설계의 성패를 가르며, 실측으로 확인했습니다.

**3회 안전망은 제안이지 이관이 아닙니다.** 계속 겉도는 말을 하는 고객은 실제로 사람이 필요할 수 있지만, 판단은 고객에게 남깁니다. 스트릭은 이미 매 턴 저장되는 `messages.intent`로 세므로 **새 컬럼이 없고**, 미분류 행에서 끊깁니다 — 값의 부재는 잡담의 증거가 아닙니다.

**응답은 고정 문구가 아닙니다.** 인사에 정형 문구로 답하면 위젯이 로봇처럼 보입니다. 페르소나·응답규칙을 그대로 태우고, 지시문만 종류별로 한 줄 붙입니다.

**모더레이션은 그대로입니다.** 새 경로 응답도 같은 게이트를 지나고, 차단되면 기존처럼 이관합니다.
