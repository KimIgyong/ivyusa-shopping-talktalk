## 0. 확정 전제 (REQ 확정)

| 항목 | 결정 |
|---|---|
| 테마 범위 | **기준색 1개 + 헤더(배경/글자)** |
| 대비 | **전경색 자동 산출** — 테넌트는 입력하지 않는다 |

| 기본값 | 미질의 → **NULL = 현행 팔레트(#2B7FFF)** 가정 |

## 1. 목표 / 비목표

**목표**
1. 테넌트가 브랜드 색 하나(+헤더)를 정하면 위젯 전체가 따라온다.
2. **읽을 수 없는 조합이 만들어질 수 없다** — 전경색은 시스템이 정한다.
3. 설정하지 않은 테넌트의 위젯은 오늘과 픽셀 단위로 동일하다.
4. 탭 설정을 "설정 페이지에서 눈에 띄는 것"으로 만든다.

**비목표**
- 상태색 테마화 — 의미를 지닌 색이다(REQ §1.3).
- 테넌트별 번들 빌드 — 배포·캐시가 테넌트 배수로 늘어난다.
- 폰트·라운드·간격 — 색상만.

## 2. 설계

### 2.1 색을 CSS 변수로 내린다

Tailwind 클래스는 빌드 시점에 hex로 굳는다. 공용 번들 하나로 테넌트마다 다른 색을 내는
방법은 이것뿐이다.

```js
// tailwind.config.js
primary: {
  500: 'rgb(var(--ivy-primary-500) / <alpha-value>)',  // "43 127 255" 형태
  …
}
```
채널 삼중값(`R G B`)으로 두는 이유: `bg-primary-500/10` 같은 **알파 표기가 4곳** 있고,
`#hex`를 변수에 넣으면 그 표기가 깨진다.

### 2.2 램프는 생성한다 — 기준색 1개 → 50~900

테넌트에게 9단계를 입력받지 않는다. **레퍼런스 램프가 명도 곡선을 제공하고, 테넌트는
색상(hue)과 채도(saturation)만 제공한다.**

```
현재 팔레트(#2B7FFF 계열)의 단계별 L 값을 기준 곡선으로 삼고
  → 500은 테넌트가 고른 hex 그대로 두고(고른 색이 그대로 보여야 하므로)
  → 곡선 전체를 (브랜드 L − 기준 500의 L)만큼 평행이동해 50~900 산출
  → 0..100 구간으로만 클램프 — 안쪽으로 좁히면 극단색에서 500과 충돌해
     600이 500보다 밝아지는 역전이 생긴다(구현 중 실측)
```
※ 초기안은 "H·S만 얹는다"였으나, 그러면 테넌트가 고른 색이 500에 그대로
나오지 않는다. 구현에서 500 고정 + 곡선 평행이동으로 확정했다.
이렇게 하면 어떤 브랜드 색이 와도 **디자인이 만든 명암 관계가 유지된다.**
(위젯이 실제로 쓰는 단계: 500·600·400·700·50·100·200·300 — 8종)

### 2.3 전경색은 계산한다 (Q2)

`primary-500` 위에는 흰 글씨가 올라간다(전송 버튼·유저 말풍선·스테퍼).
→ `--ivy-on-primary`를 **WCAG 상대휘도로 산출**해 흰/짙은회색 중 대비가 높은 쪽을 고른다.
헤더도 같은 방식(`--ivy-header-fg`).

> 테넌트가 전경색을 고를 수 없게 만드는 것이 요점이다. 고를 수 있으면 언젠가
> 읽을 수 없는 위젯이 배포된다.

### 2.4 저장

| 컬럼 | 타입 | 기본 | 내용 |
|---|---|---|---|
| `tenants.widget_theme` | `json NULL` | `NULL` | `{ brand: '#2B7FFF', headerBg: '#FFFFFF' }` |

`widget_tabs`와 같은 NULL 규약 — 미설정이면 현행 팔레트. 백필 없음.

### 2.5 첫 페인트 깜빡임 (T-04)

`session/ensure`는 비동기라 위젯이 **기본색으로 먼저 그려진 뒤 테마가 덮는다.**
→ 마지막으로 받은 테마를 `localStorage`에 shop 키로 캐시하고 **부팅 시 동기 적용**,
   ensure 응답이 오면 갱신한다. 첫 방문에서만 기본색으로 뜬다.

## 4. 단계별 계획

### S1 — 색 토큰을 변수화 (테마 없이도 무변화여야 함)
- `tailwind.config.js` — `primary-*`를 `rgb(var(--ivy-primary-N) / <alpha-value>)`로.
- `index.css` `:root`에 **현재 hex와 동일한 채널값**을 기본으로 박는다.
- ⚠️ 이 단계만으로 화면이 1px도 바뀌면 안 된다 — 회귀 기준선.

### S2 — 램프·대비 계산 (`packages/types`, 순수 함수 + 테스트)
- `buildThemeRamp(brandHex)` → `{50..900}` 채널 문자열
- `readableForeground(bgHex)` → 흰색/짙은회색 중 대비 높은 쪽
- `normalizeWidgetTheme(input)` → 잘못된 hex 거부, `null`이면 미설정
- **단위 테스트**: 밝은색/어두운색/회색/잘못된 입력/기본색 원복

### S3 — 스키마 + 전달
- `sql/migration_widget_theme.sql` — `tenants.widget_theme json NULL`(멱등 가드)
- `tenant.entity` · `UpdateWidgetThemeRequest` · `TenantMapper.toWidgetTheme`
- `PATCH /tenants/widget-theme` (+ `AuditService.write`)
- `SessionService.privacyNotice` → `SessionResponse.widgetTheme`

### S4 — 위젯 적용
- `applyTheme(theme)` — `:root`에 변수 주입
- 부팅 시 `localStorage` 캐시 동기 적용 → ensure 응답으로 갱신 (§2.5)
- 헤더 배경/글자에 `--ivy-header-*` 사용

### S5 — 콘솔 UI
- **위젯 테마** 카드(색 입력 + 헤더 선택 + 라이브 미리보기)
- **위젯 탭 구성** 카드 분리(요구 2) — 기존 `WidgetBehaviorCard`에서 탭 2행을 옮긴다
- 저장 토스트, i18n 6개 언어

### S6 — 가이드 문서 (요구 2)
`docs/guide/위젯설정가이드_Widget-Settings.ko.md` — 탭 구성·테마·알림 채널 경로와 화면 캡처 설명.

### S7 — 회귀
- **미설정 테넌트 무변화**(가장 중요) · 상태 배지 색 불변 · 알파 4곳 정상 · 첫 페인트

## 6. 마이그레이션

```sql
ALTER TABLE `tenants` ADD COLUMN `widget_theme` json NULL AFTER `notification_channels`;
```
- 백필 없음(NULL = 현행 팔레트). 롤백은 컬럼 DROP.
- 선적용 후 코드 배포.

## 7. 승인 요청

**PLN 승인 전 구현 착수하지 않습니다.** 특히:
- **§2.2 램프 생성 방식** — 테넌트는 색 하나만 주고 명암 곡선은 디자인 것을 재사용합니다.
- **§2.5 첫 방문 깜빡임** — 캐시로 2회차부터 없어지지만 첫 방문은 기본색으로 잠깐 뜹니다.
