## 1. 문제

버튼 라벨이 단일 문자열이었다. 6개 언어를 쓰는 테넌트(go2joy: VI/EN/KO)가 저장하는 순간 **운영자가
입력한 한 언어가 모든 언어에 나갔다**. 기본 버튼은 더 나빴다 — API가 **영어 문자열**을 내려주고,
위젯이 가진 번역은 **요청이 실패했을 때만** 쓰였다. 설정 화면을 한 번도 열지 않은 한국어 몰이
"Delivery status"를 보고 있었다.

## 2. 설계 판단

- **저장은 `string | LocalizedText`.** 평문 문자열은 "모든 언어에 동일"이라는 뜻이며, 이는 기존 행이
  이미 의미하던 바다 → **마이그레이션 0건**.
- **위젯 계약은 `label: string` 유지.** 서버가 세션 언어로 해석해서 내려준다. 이미 브라우저에 캐시된
  위젯 빌드도 그대로 동작하고, 위젯 코드는 한 줄도 바뀌지 않았다.
- **해석 순서**: 세션 언어 → 영어 → 값이 있는 아무 언어. 자기 언어가 비어도 빈 알약이 뜨지 않는다.
- **기본 버튼 6종을 6개 언어로.** 위젯이 이미 갖고 있던 번역을 API로 올렸다(중복 제거이자 버그 수정).
- **평문 라벨을 편집하면 먼저 전 언어에 그 문자열을 채운다.** 안 그러면 한국어를 입력한 순간 나머지
  다섯 언어가 조용히 비어버린다.
- **6개 값이 모두 같으면 다시 평문으로 축약.** 6벌로 남기면 나중에 하나만 고쳤을 때 나머지가 낡은
  번역처럼 보인다.

## 3. 타입이 잡고, 리뷰가 마저 잡았다

`label` 타입을 넓히자 컴파일러가 **세 소비처**(콘솔 입력칸·에이전트 요약 뱃지·미리보기 칩)를 즉시
멈춰 세웠다. 네 번째(에이전트 범위 모달 힌트)는 **문자열 보간 자리라 타입이 못 잡았고** 리뷰가 찾았다
(PR #466). 넓은 타입은 소비처를 세어주지만, 문자열로 합쳐지는 자리는 세어주지 못한다.

## 4. 검증

- 단위 신규 4건 포함 **180 suites / 1,802 tests PASS** · typecheck 9/9 · build 6/6 · i18n 5개 언어 complete
- 스테이징 E2E: KO·EN 두 언어 저장 → KO 세션 `[E2E] 객실 안내` / EN 세션 `[E2E] Rooms` /

## 5. 실측 · 남은 것

스테이징 14개 테넌트 중 `scenario_buttons` 저장분이 있는 곳은 **4곳, 전부 평문 영어 라벨**이다. 예전에
설정 화면에서 한 번 저장하며 그때의 영어 기본값이 굳은 경우다.

- 나머지 10곳은 이번 **다국어 기본값**을 바로 받는다.
- 4곳은 콘솔에서 언어별로 고치면 되고, 버튼을 전부 지우면 다국어 기본값으로 복귀한다.
- **자동 마이그레이션은 하지 않았다** — 저장된 영어 라벨이 손대지 않은 기본값인지 테넌트가 그렇게
  정한 것인지 서버는 구분할 수 없다. 잘못 덮으면 테넌트가 정한 문구가 사라진다.
- 후속(범위 밖): 후속 칩 라벨·`postAction` URL 등 나머지 시나리오 텍스트는 이미 언어별이다.
