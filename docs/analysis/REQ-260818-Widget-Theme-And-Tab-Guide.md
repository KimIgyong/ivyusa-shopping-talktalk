## 요구 2 — 탭메뉴 설정 경로

### 결론: 경로는 아래와 같고, **찾기 어려운 것이 실제 문제**다

```
콘솔 로그인 → 좌측 메뉴 [설정] → 페이지 스크롤
  → "위젯 동작" 카드
      ├ 로그인 방식      (기존)
      ├ 타임존           (기존)
      ├ 노출 탭   ☑알림 ☐주문 ☑채팅   ← 여기
      ├ 탭 위치   [상단 ▾]             ← 여기
      └ 위젯 문구 …      (기존)
```

### 왜 못 찾는가 — 확인된 원인 3가지

| # | 원인 | 근거 |
|---|---|---|
| C-1 | **카드 이름이 "위젯 동작"** — 탭 설정을 찾는 사람이 열어볼 이름이 아니다 | `SettingsPage.tsx:899` |

## 요구 1 — 테넌트별 스킨/테마

### 1.1 AS-IS — 색상은 전부 빌드타임 상수다

| 축 | 현황 | 근거 |
|---|---|---|
| 색 정의 | `tailwind.config.js`의 고정 hex (`primary-500: #2B7FFF` 등) | 위젯 tailwind 설정 |
| CSS 변수 | **하나도 없다** (`var(--`/`:root` 0건) | `index.css`·tailwind 설정 |
| 사용 개소 | `primary-*` 클래스가 **23개 파일** | 위젯 컴포넌트 전역 |
| 번들 | **전 테넌트 공용 1벌** — `/widget/assets/index-*.js` | 스테이징 배포 실측 |
| 테넌트 인지 시점 | 런타임. `?shop` → `session/ensure` | `useSession.ts:172` |
| 테넌트 설정 항목 | `widget_login_mode`·`widget_copy`·`widget_tabs`·`widget_tab_position`·`notification_channels` — **색상 없음** | `tenant.entity.ts` |

> REQ-260817-Widget-Figma-Design §1.2에 "색상이 테넌트 설정값이 아니라 빌드타임 상수"라고
> 기록해 둔 그 갭이다. 당시엔 팔레트 교체가 목적이라 문제가 안 됐지만, 이제 정면으로 걸린다.

### 1.2 핵심 제약 — 번들이 하나다

Tailwind 클래스는 **빌드 시점에 hex로 컴파일**된다. 공용 번들 하나로 테넌트마다 다른 색을
내려면 방법은 사실상 하나다.

```
tailwind 색상 → CSS 커스텀 프로퍼티(var(--ivy-primary-500) …)
                     ↑
          session/ensure가 테넌트 값을 내려주고
          위젯이 :root에 주입
```

테넌트별 번들을 굽는 방식은 배포·캐시·CDN이 전부 테넌트 배수로 늘어나 배제한다.

### 1.3 무엇을 테마화하고 무엇을 하지 않을 것인가 (제안)

| 구분 | 대상 | 테마화 |
|---|---|---|
| 브랜드 | `primary-*`(런처·유저 말풍선·전송·스테퍼·링크) | **O** |
| 브랜드 | 헤더 배경/글자 | O (선택) |
| **의미** | `success`(Confirmed)·`warning`(In Transit)·`error`(미읽음)·`review` | **X — 상태를 뜻하는 색이다.** 테넌트가 바꾸면 "배송중"이 초록이 되는 사고가 난다 |
| 중립 | `gray-*`(말풍선·구분선·본문) | X (가독성 기준선) |
| 형태 | 라운드·폰트 | 별도 결정(Q3) |

### 1.4 반드시 같이 풀어야 하는 것 — 대비(contrast)

`primary-500` 위에는 **흰 글씨**가 올라간다(전송 버튼·유저 말풍선·스테퍼). 테넌트가 밝은 색을
고르면 **읽을 수 없는 버튼**이 만들어진다. 이미 D-10(배지 대비 미달)을 미해결로 남겨둔 상태라
여기서 같은 실수를 반복하면 안 된다.

→ 전경색을 **입력받지 말고 자동 산출**(상대휘도 기준 흰/검 선택)하거나, 저장 시 대비를 검증해
   경고/거부해야 한다. Q2.

## 4. 제약

1. **의미 색상 불가침** — 상태 배지는 테넌트가 바꿀 수 없어야 한다(§1.3).
2. **번들 1벌 유지** — 테넌트별 빌드는 배제.
3. **기존 테넌트 무변화** — `NULL = 미설정 = 현행 팔레트`(widget_tabs와 같은 규약).
4. **스키마 변경 시 선적용** — 스테이징 `DB_SYNCHRONIZE=false`.
5. **첫 페인트 깜빡임** — 기본색으로 그린 뒤 테마가 덮으면 눈에 띈다. 대응 필요(T-04).
