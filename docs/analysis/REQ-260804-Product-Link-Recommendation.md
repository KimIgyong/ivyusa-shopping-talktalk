## 0. 결론 먼저

| # | 요구 | 현행 | 판정 |
|---|---|---|---|
| ① | 콘솔 상품링크 바로가기 | URL은 **144건 전부 저장돼 있으나**, 편집 모드의 입력란에만 노출 | **부분 존재 — 표시만 없음** |
| ② | 위젯 지식참조·추천링크 | **인용 렌더링과 링크 처리가 이미 구현돼 있음.** 다만 데이터에 URL이 없어 항상 텍스트로만 표시 | **배선 완료, 데이터 미공급** |
| ③ | 검색 링크 형식 | 없음 | **미구현 — 도메인 결정 필요** |

**핵심 발견 3가지**

1. **위젯은 이미 인용을 링크로 그릴 줄 압니다.** `MessageBubble.tsx`가 `citations`를 목록으로 렌더링하고
   `c.url`이 있으면 `<a>`로, 없으면 제목 텍스트로 표시합니다(`safeHttpUrl` 검증까지 포함).
   `ChatCitation` 타입에도 `url?: string`이 **이미 존재**합니다.
   → **막힌 곳은 단 하나**: RAG가 반환하는 `RetrievedChunk`에 `url` 필드가 없어 항상 `undefined`입니다.
   ②는 "만드는" 작업이 아니라 **한 필드를 채우는** 작업에 가깝습니다.

2. **`ivyusa.com`을 코드에 박으면 안 됩니다.** 테넌트 2곳이 있고,
   `tenants.shop_domain`은 **`ambshop-dev.myshopify.com`**(Shopify 개발 도메인)이라
   요구하신 스토어프론트 주소 `ivyusa.com`과 다릅니다. 두 번째 테넌트는 `annehearts.cafe24.com`입니다.
   → 링크 베이스는 **테넌트별 설정값**이어야 하며, `shop_domain`에서 유도할 수 없습니다.

3. **직접 상품 URL을 이미 보유하고 있습니다.** 임포트한 144건 전부 `source_url`에
   `https://ivyusa.com/products/{handle}` 형태의 **정확한 상품 페이지 주소**가 들어 있습니다.
   요구는 그럼에도 **검색 페이지 링크**를 지정하고 있어, 의도 확인이 필요합니다(§5 F2).

## 1. ① 콘솔 상품링크(바로가기)

### 현행
- `kb_documents.source_url` — S4에서 추가한 출처 필드. **상품 144건 전부 채워져 있습니다**(실측).
- 콘솔 노출은 **문서 상세 모달의 편집 모드 입력란 하나뿐**입니다(`원문 URL`).
- 보기 모드·문서 목록에는 **링크가 없습니다.** 충돌 검토 카드에는 외부링크 아이콘이 있습니다(S4).

### 갭
- 상품 문서를 열어도 **바로 상점 페이지로 이동할 방법이 없습니다.** 편집을 눌러 URL을 복사해야 합니다.
- 목록에서 144건을 훑을 때 어느 상품인지 확인하려면 매번 상세를 열어야 합니다.

### 고려사항
- S4에서 만든 `source_url`을 그대로 쓰면 되고 **스키마 변경이 없습니다.**
- 상품 그룹에만 필요한 것이 아니라 **정책 문서에도 유용**합니다(Google Docs 원문 등) —
  다만 현재 정책 230건은 `source_url`이 **0건**이라 당장은 상품에만 보입니다.

## 2. ② 위젯 지식참조 · 상품추천링크

### 현행 — 배선은 이미 있습니다

```
RagService.answer()  →  citations: RetrievedChunk[]   ← url 필드 없음
        ↓
ChatTurnResult.reply.citations  →  ChatCitation[]      ← url?: string 있음
        ↓
useChat.ts  →  message.citations
        ↓
MessageBubble.tsx  →  c.url ? <a href={safeHttpUrl(c.url)}> : 제목 텍스트
```

`MessageBubble`은 이미 이렇게 동작합니다.

```tsx
const href = c.url ? safeHttpUrl(c.url) : null;
{href ? <a href={href} target="_blank" rel="noopener noreferrer">{c.title}</a> : c.title}
```

### 갭

| 갭 | 내용 |
|---|---|
| **URL 미공급** | `RetrievedChunk`에 `url`이 없어 위젯이 받는 `c.url`은 **항상 undefined** → 늘 텍스트 |
| **표시 위치** | 현재는 **각 AI 말풍선 아래**. 요구는 "**대화방 하단**" — 위치 결정 필요(§5 F1) |
| **그룹 구분 없음** | 정책 문서 인용과 상품 인용이 **같은 목록**으로 나옵니다. "상품추천링크"로 부르려면 상품만 골라야 합니다 |
| **라벨 없음** | "지식참조"라는 제목이 없어 목록의 성격이 드러나지 않습니다 |

### 고려사항
- **모더레이션 경로 밖입니다.** 인용은 AI 생성 문장이 아니라 **저장된 문서의 제목**이므로
  `moderate()`를 다시 통과시킬 필요가 없습니다(제목은 관리자가 통제하는 값).
- **개인정보 영향 없음** — 상품 제목·URL은 고객 데이터가 아닙니다.
- 상품 문의가 아닐 때(정책 질문) **상품추천을 띄우지 않아야** 합니다. 그룹 정보가 인용에 필요합니다.
- 위젯은 이미 `safeHttpUrl`로 URL을 검증합니다 — **javascript: 스킴 등은 차단됩니다.**

## 3. ③ 링크 형식

요구: `https://ivyusa.com/search?type=product&q={Title}`

### 갭
- **베이스 도메인이 테넌트마다 다릅니다.** 코드에 `ivyusa.com`을 박으면 두 번째 테넌트
  (`annehearts.cafe24.com`)에서 잘못된 링크가 나갑니다.
- `tenants.shop_domain`은 **`ambshop-dev.myshopify.com`** 이라 이 값으로 만들 수 없습니다.
  스토어프론트 주소를 담는 **별도 설정이 필요**합니다.
- 제목을 그대로 넣으면 안 됩니다 — **URL 인코딩 필수**. 상품 제목은 평균 103자에
  `&`·`(`·`+` 같은 문자가 포함됩니다(예: `Arocell Super Collagen Mask (2 sheets) Hydrogel Mask with 1.5oz…`).
- 제목이 매우 길어(최대 196자) 검색어로 그대로 쓰면 **검색 결과가 0건**일 가능성이 큽니다.
  실제 스토어 검색은 긴 문장 전체 일치를 잘 못 찾습니다.

### 확인이 필요한 지점
**직접 상품 URL을 이미 갖고 있는데 검색 링크를 쓰는 이유**가 무엇인지에 따라 설계가 갈립니다.
- 상품이 사라지거나 URL이 바뀌어도 **검색은 깨지지 않는다**는 이유라면 검색 링크가 타당합니다.
- 단순히 직접 URL의 존재를 모르셨다면 **`source_url`을 쓰는 편이 정확**합니다(클릭 1회로 상품 도착).
- 둘 다 제공하는 방법도 있습니다(제목 = 상품 페이지, 보조 = 검색).

## 4. 공통 관찰

1. **①과 ②는 같은 데이터(`source_url`)를 씁니다.** ③만 새로 만드는 값입니다.
2. **스키마 변경이 필요 없습니다** — 링크 베이스 설정을 어디에 둘지에 따라 달라집니다(§5 F3).
3. 규모가 작습니다. 세 요구를 합쳐 **1.5d** 수준입니다.

### 4-1. 앞선 보고 정정 — "가격 유출 0건"

PR #104 보고에서 "가격 유출 0건"이라고 말씀드렸는데, **검증에 쓴 정규식이 셸 이스케이프를 거치며
망가져 아무것도 매칭하지 않았습니다.** 스테이징에서 다시 재보니 **30건이 매칭**됩니다.

다시 확인한 결과는 이렇습니다.

| 위치 | `$xx.xx` 포함 |
|---|---|
| `Detail` | **0 / 144** |
| `How to Use` | **0 / 144** |
| `Tags` | **30 / 144** |

즉 **`Price(USD)` 컬럼 제외는 정상 동작**했고, 걸린 30건은 `Tags`의 Shopify 컬렉션 이름
(`Over $29.98`)입니다 — 상품 가격이 아니라 **가격대 분류 태그**입니다.

실질 위험은 낮지만 D4의 취지("낡은 가격이 답변에 남지 않게")를 생각하면
태그의 가격 문구도 정리 대상일 수 있습니다(§5 F4). **결론은 바뀌지 않았으나 근거가 틀렸던 것을
정정합니다.**

## 5. 결정이 필요한 사항

| # | 결정 | 선택지 | 기본 권고 |
|---|---|---|---|
| **F1** | 위젯 표시 위치 | 각 답변 아래(현행 구조) / **대화방 하단 고정 패널** / 둘 다 | **답변 아래 유지 + "지식참조" 라벨** — 어떤 답변의 근거인지가 붙어 있어야 의미가 있고, 하단 고정은 대화가 길어지면 근거와 답변이 분리됩니다. 요구 문언은 "하단"이나 **의도는 "답변과 함께 보이게"** 로 읽었습니다 |
| **F2** | 링크 대상 | 검색 링크(요구안) / **직접 상품 URL** / 둘 다 | **확인 필요.** 직접 URL을 이미 보유. 검색 링크는 제목이 길어 결과 0건 위험 |
| **F3** | 링크 베이스 도메인 | 코드 상수 / **테넌트 설정** / `shop_domain` 재사용 | **테넌트 설정**(신규 설정값). `shop_domain`은 myshopify 주소라 사용 불가 |
| F4 | Tags의 가격 문구 | 유지 / 임포트 시 제거 | **유지** — 가격대 태그는 검색에 유용하고 실제 가격이 아님. 다만 AI 응답 규칙에 "가격은 상품 페이지 확인 안내" 추가 권고 |
| F5 | 상품 인용만 링크 | 전체 인용에 링크 / **상품 그룹만** | **상품만** — 정책 문서는 `source_url`이 0건이라 링크가 생기지 않음 |
| F6 | 콘솔 노출 위치 | 상세 모달만 / **목록 + 상세** | **둘 다** — 목록에 아이콘, 상세 보기 모드에 링크 |

## 7. 권고 진행 순서

1. **F2·F3 회신** — 링크 대상(검색 vs 직접)과 베이스 도메인 출처. 나머지는 권고안대로 진행 가능.
2. PLN 작성(위젯 와이어프레임 포함) → 구현 → TCR → RPT.

> **F2에 대한 제안**: 제목을 그대로 검색어로 넣으면 결과가 0건일 위험이 큽니다(제목 최대 196자).
> 검색 링크를 쓰신다면 **제목 전체가 아니라 브랜드+핵심 명사 일부**로 줄이거나,
> **직접 상품 URL을 1순위로 두고 검색을 보조 링크**로 제공하는 편이 안전합니다.
