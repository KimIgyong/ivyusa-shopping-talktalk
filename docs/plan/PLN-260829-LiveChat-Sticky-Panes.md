# PLN-260829 라이브챗 스크롤 분리(필터/헤더 상단 고정) 작업계획서

- 근거: `docs/analysis/REQ-260829-LiveChat-Sticky-Panes.md`

## 핵심 설계 결정

| # | 결정 | 근거 |
|---|---|---|
| D1 | 좌측 목록: 칼럼 스크롤 유지 + 헤더 묶음에 **`sticky top-0 z-10 bg-white`** | 칼럼 자체가 스크롤 컨테이너라 sticky 기준이 명확·확실. 마크업 이동 최소(래퍼 1개), 하단 액션바(sticky bottom-0)와 대칭 |
| D2 | 페이지: 고정 매직값 `h-[calc(100vh-220px)]` 폐기 → 페이지 래퍼를 **뷰포트 정합 flex**(`h-[calc(100dvh-112px)] flex flex-col`, PageHeader `shrink-0`, 그리드 `flex-1 min-h-0`) | A2의 근원 제거 — 112px = 글로벌 헤더 64 + main 상하 패딩 48(실측치, 매직값이지만 그리드가 flex-1이라 오차가 **잘림이 아닌 여백**으로 나타남 — 현행은 오차가 본문 스크롤로 나타남). `dvh`로 모바일 주소창 변동 대응 |
| D3 | 중앙 패널: 구조 변경 없음 — `min-h-0` 방어만 보강 | 헤더 고정+메시지 스크롤 flex 구조는 기구현. D2가 서면 그대로 살아남 |
| D4 | 앱 셸(AppLayout) 무수정 — 라이브챗 페이지 스코프로만 | 셸 높이 잠금은 전 페이지 파급(긴 폼 페이지들 스크롤 모델 변경) — 과함 |

## 작업 범위 (웹 전용 1PR, 스키마/API/i18n 무변경)

`apps/web/src/domain/live-chat/LiveChatPage.tsx`:
1. 루트 `<div>` → `flex h-[calc(100dvh-112px)] flex-col`, `<PageHeader>` 래퍼 `shrink-0`.
2. 그리드 `h-[calc(100vh-220px)]` → `min-h-0 flex-1` (grid-cols-12 gap-4 유지).
3. 좌측 칼럼: 제목줄~검색박스(4개 블록)를 `<div className="sticky top-0 z-10 bg-white">`로 묶음
   (기존 각 블록의 border-b 유지 — 최하단 블록에만 border-b로 정리).
4. 중앙 칼럼·메시지 영역·우측 칼럼에 `min-h-0` 보강(플렉스 수축 방어).
5. GroupRoom(중앙 대체 뷰)도 동일 구조 확인 — 자체 flex-col이면 무수정.

## 부수영향
- 그리드가 `flex-1`이 되면 높이 오차(조건부 배너 등)가 **본문 스크롤 대신 그리드 축소**로 흡수 — 배너 표시 세션에서 목록/메시지 가시 영역이 배너만큼 줄어드는 것이 새 동작(수용).
- sticky 헤더가 목록 위에 겹치므로 `bg-white` 필수(투명이면 목록이 비쳐 보임) — z-index는 행 hover/배지(z 없음)보다 위, 모달(z-40대)보다 아래.
- 다른 페이지 무영향(라이브챗 스코프). 우측 칼럼 `xl:sticky` 사용처 없음(이 페이지는 자체 스크롤) — 변경 없음.

## 검증 계획 (유닛 대상 로직 없음 — 실측 중심)
1. 세션 50건 테넌트(ivyusa)에서 목록 최하단까지 스크롤 → 필터·검색 상시 노출, 스크롤 중 탭 전환 동작.
2. 긴 대화(100+ 메시지) 과거 로드 후 스크롤 → 상단 헤더 2줄·IssuePanel·컴포저 고정, 메시지만 이동.
3. 본문 스크롤 부재 확인(창 높이 700px·1080px), 비밀번호 배너 세션의 축소 동작, 그룹 탭·그룹 룸 무회귀.
4. typecheck/build + 스테이징 배포 후 위 육안 실측(TCR로 기록).
