## 1. 단계별 계획

### S1 — 번역본 작성 (코드 아님)
1. `reference/go2joy-hotel-admin-kb.en.md` — 아티클 18건 + 용어집 + 상태값 전문 영어 번역.
   제목은 순수 영어(`Reply to a Review`). 원문 병기 영문 용어를 그대로 채택.
2. `reference/go2joy-hotel-admin-kb.vi.md` — 동일 범위 베트남어 번역.
   제목은 베트남어 + 영문 병기(`Trả lời đánh giá (Reply to a Review)`) — 상담원이 EN 기능명
   혼용하는 현장 관행 반영. UI 버튼 라벨은 `[Trả lời / Reply]`처럼 병기 유지.
3. 두 파일 모두 원본과 같은 헤딩 구조(`## GTJ-REV-01 · <제목>`)·경계 규칙을 지켜
   기존 파서가 그대로 20건을 추출하게 함. §7(보완 필요 항목)·§8(변경 이력)은 번역 제외(미적재 메타).

### S2 — 변환기 언어 옵션
- `scripts/convert-go2joy-kb.mjs`: `--lang` 파서 추가 — `CATEGORY_BY_PREFIX`·`APPENDIX`
  (부록 헤딩 문자열)·키 접미사를 언어별 테이블로. 무인자 기본 ko(기존 호출 호환).
- 검증: 3개 언어 각각 20건 추출·본문 비어있지 않음·키 접미사 정확.

### S3 — 스테이징 적재·검증
1. en CSV·vi CSV 생성 → go2joy 일괄등록(operation) — 기대 `created:20, embedded:20` × 2.
2. 재업로드 멱등(`skipped:20`) × 2.
3. `categories/counts?group=operation` — 카테고리 15종(언어별 5종)·60건.
4. ask 스모크: en 질문("How many times can I reply to a review?") → `GTJ-REV-01-EN` 인용,
   vi 질문("Tôi có thể trả lời đánh giá bao nhiêu lần?") → `GTJ-REV-01-VI` 인용,
   ko 질문 → 기존 ko 문서 인용 유지.

### S4 — 마무리
- TCR/RPT 작성, PR(문서+스크립트) squash 머지. 스키마·SQL 없음 → Migration 섹션 N/A.
- 배포 불필요(서버 코드 무변경 — 데이터는 API로 직접 적재, 스크립트는 로컬 실행 도구).

## 4. 리스크

- **번역 정확성**: 절차(숫자 스텝)·경고(⚠)는 의미 변형 없이 직역 우선; 수치·경로·버튼명은
  원문 병기 유지. 산출 md가 reference/에 남으므로 사후 검수·수정→재업로드 가능.
- **파서 회귀**: 번역 md가 경계 규칙(`# ` 챕터·`## n.n` 그룹만 flush)을 지키는지 변환 결과
  20건·본문 길이로 즉시 검증(전회 예방 패턴 적용).
