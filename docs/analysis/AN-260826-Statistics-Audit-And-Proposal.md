## 2. 점검 결과 — 결함 7건

### D-1 (P2) ~~집계 작업을 아무도 돌리지 않습니다~~ → **오판. 스케줄러는 있고 돌고 있습니다**

> **정정(2026-08-26, 같은 날)**: 처음에 "스케줄러가 없다"고 적었습니다. **틀렸습니다.**
> `QuestionStatsService`는 `OnModuleInit`에서 `QUESTION_STATS_INTERVAL_HOURS`(기본 24h) 타이머를
> 걸고 부팅 10분 뒤 1회 실행합니다(PR #90부터). 스테이징 로그가 그대로 보여줍니다.
>
> ```
> 06:57:50 Question stats scheduled every 24h (first run in 10 min)
> 07:07:56 Question stats 2026-08-25: questions=287 rows=990 newClusters=0
> ```
>
> 제가 "결손"이라고 부른 것들도 결손이 아니었습니다.
> - **오늘(08-26) 없음** → 정상입니다. 어제치만 집계하므로 오늘은 내일 들어옵니다.
> - **08-23 없음** → 그날 **전 테넌트 고객 발화가 0건**이었습니다. 질문이 없으면 행도 없습니다.
> - **테넌트 5·6이 08-19에서 멈춤** → 그 뒤로 오늘까지 고객 발화가 없었습니다(08-19 이후 첫 발화가
>   오늘 아침). 멈춘 게 아니라 쓸 게 없었습니다.
>
> 검증 없이 "화면 숫자가 낡고 있다"고 단정했습니다. 실제로는 어제치가 오늘 아침에 정상 기록됐습니다.

남는 것은 훨씬 작습니다.

- `runScheduled()`는 **어제 하루만** 계산하고 결손을 확인하지 않습니다. 24시간 타이머는 부팅
  시점에 위상이 잡히므로, 컨테이너가 하루 종일 떠 있지 않으면 그 하루는 **영구히 빈 채로**
  남습니다. 지금 그런 흔적은 없지만, 생기면 되돌릴 방법이 없습니다.
- 마지막 집계 시각이 **어디에도 보이지 않습니다.** 실제로 이번 오판의 원인도 그것입니다 —
  화면을 보고는 신선한지 낡았는지 알 수 없어서 DB를 직접 뒤져야 했습니다.

### D-2 (P0) 대시보드가 샌드박스 트래픽을 고객 트래픽으로 셉니다

대화 검색(`searchConversations`)은 `/ai-setting` 미리보기 스레드를 **의도적으로 제외**합니다
(주석: "they would inflate every count on this screen"). 그런데 **같은 서비스의 `dashboard()`는
제외하지 않습니다.**

```
tenant 4(go2joy)  대화 42건 중 미리보기 11건 = 26.2%
tenant 1(ivyusa)  대화 207건 중 13건 = 6.3%
```

go2joy 대시보드의 대화 4건 중 1건은 운영자가 시험한 것입니다.

### D-3 (P0) "해결"의 정의가 세 가지입니다

| 곳 | 정의 | 스테이징 값 |
|---|---|---|
| 대시보드 `aiResolutionRate` | 종료됨 & 이관 안 됨 | 16/143 = **11%** |
| 고객여정 리포트 `classifyOutcome` | CSAT 응답 / 상담원 종료 / 유도 후 종료 / 고객이 마지막 | 다른 값 |
| `agent_daily_stats.resolved` | — | **한 번도 기록 안 됨** |

대시보드 정의는 **고객이 그냥 나가버린 대화도 성공으로 셉니다.** 화면 두 개가 서로 다른
해결률을 말하면, 둘 중 하나가 틀린 것보다 나쁩니다 — 어느 쪽을 믿을지 판단할 근거가 없어집니다.

### D-4 (P1) `agent_daily_stats`는 답처럼 보이지만 비어 있습니다

9개 컬럼 중 **`csat_avg` 하나만** 기록됩니다(평점이 들어올 때만). 나머지 8개
(handled·avg_first_response_sec·avg_handle_sec·resolved·escalated·online_sec·blocked_msgs)는
**전무**하고, 행은 4개(테넌트 2곳)입니다. 읽는 화면도 없습니다 — API만 있고 콘솔에 없습니다.

### D-5 (P1) 대시보드 KPI에 기간이 없습니다

`totalConversations`·`aiResolutionRate`가 **전 기간 누적**입니다. 누적은 시간이 갈수록 움직이지
않으므로, 이번 주가 나빠도 카드는 그대로입니다. "지난 30일" 같은 창이 없습니다.

### D-6 (P2) 새 만족도 탭에 미리보기 제외 규칙이 없습니다

PR #401의 CSAT 집계는 `conversations`를 직접 세면서 `/ai-setting` 미리보기 스레드를 거르지
않습니다 — D-2와 같은 누락입니다. **다만 지금 스테이징에는 종료된 미리보기 대화가 0건이라
현재 숫자는 영향이 없습니다.** 잠재적 불일치이지 지금 틀린 값은 아닙니다.

같은 쿼리의 `DATE(c.ended_at) BETWEEN …`은 컬럼에 함수를 씌워 인덱스를 못 씁니다.
`conversations`에 `ended_at` 인덱스도 없습니다 — 스테이징 426행에서는 무의미하지만 대형
테넌트에서는 전수 스캔입니다.

### D-7 (P2) 스냅샷의 92%가 키워드 행입니다

`question_stats_daily` 20,101행 중 **키워드 18,505행**. 키워드는 어휘 수만큼 늘어나고 상한이
없습니다. 이 테이블은 보존 정책 대상도 아닙니다(대화 로그는 365일에 지워지는데 스냅샷은 남음 —
통계 목적상 옳지만, 무한 증가는 별개 문제).

### D-8 (P2) 집계 기준일이 UTC입니다

`aggregateDay`는 UTC 자정으로 하루를 자릅니다. 한국 테넌트의 "어제"는 실제로는 오전 9시부터
다음날 오전 9시까지입니다. 지금은 눈에 잘 안 띄지만, **요청하신 시간대 통계를 붙이는 순간
정면으로 드러납니다**(테넌트 11곳 중 타임존 설정은 2곳뿐).
