## 1. 무엇을 했나

`reference/hoteladminvideoguidevien.md`(231KB·956줄, 무성 화면녹화 51편의 프레임 분석 문서, VI·EN
한 줄 병기)를 **영상 1편 = 지식 1건**으로 쪼개 go2joy 지식베이스에 등재했다.

- **문서 104건** = 영상 51 × (VI·EN) + 참고 1 × (VI·EN)
- 키 `GTJ-VID-{00~50}-{VI|EN}`, 참고 `GTJ-VIDREF-01-{VI|EN}` — 기존
  `(tenant, doc_group, external_key)` 업서트 축이라 **재실행 멱등**
- 카테고리 11종: 기존 5종 재사용(대시보드·리뷰·객실유형·리포트·참고자료의 VI/EN 라벨) +
  6종 신설(예약 관리·정산·상품·쿠폰·광고 캠페인·직원 관리)

## 2. 설계 판단 (왜 이렇게)

- **AI 인제스트를 쓰지 않았다.** 같은 날 `.md` 인제스트를 붙였지만 이 문서에는 부적합하다:
  ① LLM 재작성이 화면 라벨(`Chờ nhận phòng` 등)을 변형할 위험, ② 승인 결과가 **보드**로 가서
  요구한 목적지(지식베이스문서)와 다름, ③ 51편×2언어 검수 승인 부담, ④ **한 줄 병기라 언어 분리가
  불가능**. 원문이 이미 아티클 단위로 규칙적이므로 결정적 변환이 정확·멱등·무비용이다.
- **카테고리는 화면경로 유추가 아니라 명시 구간표.** 경로 첫 메뉴로 유추하면 Video 25(홈→정산)와
  39(홈 배너→쿠폰)가 대시보드로 오분류된다. [[kb-operation-bulk-import]]의 "명시 규칙만" 교훈.
- **한국어판은 만들지 않았다.** 원문에 없는 언어를 지어내지 않는다. 필요하면 기존 EN/VI 번역
  선례(PR #433/#434)대로 별건.
- **Duration 제외 / Not verifiable 유지.** 영상 길이는 답변에 쓸모없는 노이즈지만, "영상이 성공
  토스트까지 담지 못했다"는 사실을 지우면 KB가 확인되지 않은 결과를 단정하게 된다.

## 3. 언어 분리를 어떻게 증명했나 (핵심)

모든 서술 줄이 `VI<br>*EN*` 한 줄에 들어 있어, 분해 실패는 **조용히** 반대 언어를 남긴다. 그래서
변환기가 스스로 검사하고 실패 시 exit 1 한다. 검사 규칙을 두 번 고쳤다.

1. ❌ "이탤릭 `*…*`이 남았나" → 원문의 **필수입력 표시**(`Tên đăng nhập *`, `(*)`)를 전부 오탐.
2. ❌ "버린 반쪽이 결과에 **포함**되나" → 이 가이드는 *의도적으로* 영어 문장 안에 베트남어 화면
   라벨을 인용한다(원문의 표기 규칙). 규칙을 지킨 문장을 위반으로 몰았다.
3. ✅ "버린 반쪽이 **같은 아티클의 한 줄과 통째로 일치**하나" — 아티클을 넘나들면 안 된다.
   같은 화면을 다루는 두 영상(6·7)은 화면경로 줄이 정당하게 동일하다.

결과: VI/EN 각각 **634개 반쪽 폐기, 0개 생존**.

## 5. 재실행 절차 (원본 개정 시)

```bash
# 1) reference/hoteladminvideoguidevien.md 수정
node scripts/convert-go2joy-video-kb.mjs --lang vi   # → go2joy-video-kb.vi.csv
node scripts/convert-go2joy-video-kb.mjs --lang en   # → go2joy-video-kb.en.csv
# 2) 콘솔 /knowledge → 운영매뉴얼 탭 → [일괄등록]으로 두 CSV 업로드 (또는 POST /knowledge/documents/import/bulk)
```
같은 external_key로 업서트되므로 중복은 생기지 않는다. **변경된 문서만** 재임베딩된다.
