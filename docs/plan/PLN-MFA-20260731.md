## 1. 설계 요약

- **TOTP RFC 6238** (SHA-1, 30s step, 6자리, ±1 step 허용) — Node 내장 `crypto` HMAC으로
  구현, **신규 백엔드 의존성 0**. 시크릿은 `crypto.util` AES-256-GCM으로 암호화 저장.
- **step-up 로그인**: 비밀번호 검증 성공 + MFA 활성 계정 → access/refresh 대신
  `{ mfaRequired: true, mfaToken }` 반환. `mfaToken`은 목적 제한 단명 JWT(5분,
  `purpose:'mfa'`, 일반 API 사용 불가). `POST /auth/mfa/verify`로 코드(또는 복구 코드)
  검증 시 정식 토큰 발급. 미등록 계정 응답은 현행과 동일(하위 호환).
- **재사용 방지**: 마지막 사용 time-step 저장, 같은 step 코드 재수락 금지.
  검증 rate limit은 기존 `login-rate-limit` 패턴 재사용(키: actor+ip).
- **적용 정책(승인 필요, §7)**: admins(super/admin)·users(master/director) 필수 +
  유예 14일, manager/staff 선택.

## 2. 단계별 구현

### Stage M1 — 백엔드 TOTP 코어 + step-up 로그인
1. `global/util/totp.util.ts`(+spec): secret 생성(base32), `otpauth://` URI, 코드 검증(±1 step).
2. 엔티티+SQL: `mfa_credentials`(actor_type/actor_id 복합 유니크, secret_enc, enabled_at,
   last_used_step, created_at), `mfa_recovery_codes`(credential_id, code_hash(bcrypt),
   used_at) — `sql/migration_mfa.sql` + `01-schema.sql` 동기. 널러블 컬럼 explicit type.
3. `auth` 도메인 확장: `POST /auth/mfa/enroll`(인증 필요 — URI+수동키 반환),
   `POST /auth/mfa/enroll/verify`(코드 확인 → 활성화 + 복구 코드 10개 1회 반환),
   `POST /auth/mfa/verify`(mfaToken+코드 → 정식 JWT), `POST /auth/mfa/disable`
   (비밀번호+코드), 로그인 흐름 분기. 에러: `E1010 MFA_REQUIRED`, `E1011 MFA_CODE_INVALID`,
   `E1012 MFA_ALREADY_ENROLLED`(auth 블록 연속 할당).
4. 감사: `mfa.enrolled/verify_failed(result:'denied')/disabled/recovery_used` — PR #39
   확장 스키마(ip/request_id 자동 주입) 활용.
5. 테스트: totp.util 벡터(RFC 6238 테스트 벡터 포함), step-up 흐름, 재사용 거부,
   복구 코드 1회성, rate limit.

### Stage M2 — 웹 콘솔 UI
6. 로그인 2단계 화면(코드 입력 + 복구 코드 전환), 설정>보안 등록 플로(QR 렌더 —
   경량 QR 라이브러리 1개 web 전용 추가 승인 필요 §7 D-M3, 아니면 수동키만),
   복구 코드 1회 표시+다운로드, 비활성화. 전부 i18n(en/es/ko) + 토스트 규칙.
7. 관리자 콘솔: 사용자 상세에 "MFA 리셋" (RequireCapability, 감사 기록, 확인 다이얼로그).

### Stage M3 — 정책 집행
8. 필수 rank 미등록 계정: 유예기간(설정값, 기본 14일) 경과 후 로그인 시 등록 강제
   (등록 전 다른 API 접근 불가 — mustChangePassword 패턴 재사용).
9. 문서: 운영 가이드(등록/분실/리셋 절차) + OPS 공지, TCR/RPT.
