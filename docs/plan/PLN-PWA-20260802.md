## 2. 단계별 계획

### P1 — 백엔드 Web Push (API)
- `npm i web-push` (+`@types/web-push`), env `VAPID_PUBLIC_KEY/PRIVATE_KEY/SUBJECT`
- `provider/web-push.provider.ts`: send(구독 JSON parse → sendNotification, TTL·urgency 설정,
  **410/404 → shouldRevoke 티켓**), getReceipts는 no-op(Web Push는 영수증 없음)
- `push.service.ts`: register에 `provider('expo'|'webpush')` + 구독 필드 수용(webpush면
  Expo 토큰 정규식 검증 스킵, endpoint https 검증), token_hash 계산·저장;
  dispatch를 provider별 그룹 발송으로 확장
- `GET /push/vapid-key` (@Public) — 클라이언트 구독용 공개키
- entity: `token` TEXT + `tokenHash` (uk 이전), **Migration**:
  `sql/migration_push_webpush.sql` (MODIFY token TEXT, ADD token_hash + UNIQUE, 기존 행
  backfill UPDATE, uk_device_token 제거) — staging 수동 선적용
- 단위 테스트: webpush register/검증, provider 라우팅, 410 revoke

### P2 — PWA 셸 (`apps/pwa`)
- Vite 프로젝트(base `/app/`), manifest.webmanifest(standalone, theme #6366F1, 아이콘 192/512),
  `sw.ts`: push→showNotification(data.category), notificationclick→클라이언트 포커스/라우트,
  pushsubscriptionchange→재구독+재등록, 정적 자산 프리캐시(API 캐시 없음)
- api-client/서비스 계층: apps/mobile의 fetch 클라이언트 이식(X-Session-Token, envelope 언랩),
  세션 부트스트랩(localStorage 토큰 — SW와 공유 필요성상 secure-store 대체)
- 설치 UX(W-8) + 푸시 구독 흐름 + i18n en/es/ko(모바일 로케일 이식)

### P3 — 화면 (라우트: /chat /orders /alerts /settings)
- RN 화면 4종의 웹 구현(동의 게이트/5s 폴링/시나리오 버튼, 게스트 조회+상세+트래킹,
  알림센터+읽음, 설정: 언어·pref 토글 3그룹·옵트아웃) — UX 피드백 토스트 규칙 동일 적용
- 상단 헤더: 쇼핑하기(W-7), 미설치 시 설치 배너/가이드

### P4 — 배포 + E2E
- `docker/staging`: `Dockerfile.pwa` + compose 서비스 + nginx `/app/` 라우팅(+SW 헤더
  `Service-Worker-Allowed`), `VITE_API_BASE_URL`/`VITE_SHOP_DOMAIN` 주입
- E2E(데스크톱 Chrome + Android 실기기 가능 범위): 구독→register(webpush 행)→배송 웹훅→
  **실제 Web Push 수신**→클릭 딥링크; 만료 구독 410 revoke 확인
- 스토어프론트에 PWA 진입 배너(선택, Shopify 테마에 링크 1줄)

### P5 — 문서
- TCR-PWA / RPT-PWA (배포 상태·migration 체크 포함), SPEC.md(§4/7 갱신), CONFIG(VAPID env)

## 4. 측면 영향 분석

| 대상 | 내용 | 위험 |
|---|---|---|
| device_tokens 스키마 | token TEXT + token_hash 유니크 이전 — **기존 expo 경로 회귀 테스트 필수** | 중간 (P1 스펙에 포함) |
| PushService | provider 라우팅 리팩터 — 기존 expo 디스패치 동작 불변 확인 | 중간 |
| RN 앱 | register 요청에 provider 기본값 'expo' 유지 → **앱 수정 불필요** | 없음 |
| 위젯/웹 콘솔 | 변경 없음 (enum은 이미 push 포함) | 없음 |
| staging | migration 선적용 + compose/nginx 변경 재배포 | 규칙 준수 |
| 개인정보 | webpush 구독도 device_tokens 삭제 경로에 자동 포함(기존 구현) | 낮음 |
