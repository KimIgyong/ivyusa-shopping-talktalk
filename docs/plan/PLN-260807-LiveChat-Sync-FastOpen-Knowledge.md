## 결정 제안

| # | 결정 | 제안 | 이유 |
|---|---|---|---|
| D1 | 브리핑 분리 | **별도 엔드포인트** `GET /agent/conversations/:id/briefing` | 대화 조회는 항상 즉답. 브리핑은 필요할 때만 호출되므로 5초 폴링이 모델을 다시 건드리지 않음(현재는 캐시로 가려져 있을 뿐) |
| D2 | 초기 건수 | **최근 30건**, 더보기 30건 단위 | 요구는 10건이나, 상담사는 맥락을 보려고 곧바로 스크롤한다. 30건이면 대부분 한 화면에 끝나고 왕복이 줄어듦. 현재 대화가 2~6건이라 어느 쪽이든 즉시 로딩 |
| D3 | 저장 권한 | **`knowledge_source.manage` 보유자에게만 버튼 노출**(v1) | 지식은 모든 상담에 영향을 주는 자산 — 검토 없는 직접 쓰기를 상담사 전원에게 열지 않음. 필요해지면 "제안 큐"를 후속으로 |
| D4 | 문서 기본값 | 분류 `faq`(변경 가능), 그룹 `counsel`, **출처에 대화 링크**(`/live-chat?c=105`) 기록 | 나중에 "이 지식이 어디서 왔나"를 되짚을 수 있어야 함 |

## Stage 1 — 즉시 열리는 대화창 + 싱크 버튼

대상: `apps/api/src/domain/agent/{agent-console.controller.ts, agent.service.ts, dto/request/agent.request.ts}`,
`apps/web/src/domain/live-chat/{LiveChatPage.tsx, live-chat.hooks.ts, live-chat.service.ts}`, i18n

1. `GET /agent/conversations/:id`에서 **브리핑 제거**, `?limit=&before_id=` 추가:
   - 기본 최근 30건을 **오름차순**으로 반환 + `hasMore`(더 오래된 메시지 존재 여부).
   - `before_id` 지정 시 그보다 오래된 30건(블록 로드).
   - `AgentService.listMessages`에 limit/before 적용(현재 전체 조회).
2. `GET /agent/conversations/:id/briefing` 신설 — 기존 캐시 로직 그대로 사용.
3. 콘솔:
   - 대화 열면 메시지 먼저 렌더, 브리핑 패널은 별도 쿼리로 로딩 표시 후 채움.
   - 헤더에 **싱크 버튼**(회전 아이콘): 클릭 시 대화·목록 즉시 refetch, 진행 중 스피너.
   - 스레드 상단 **[이전 대화 더보기]** 버튼(`hasMore`일 때만) → 이전 블록 prepend, 스크롤 위치 보존.

```
┌ 대화 ────────────────────── [🔄 싱크] [수락] [종료] ┐
│        [ 이전 대화 더보기 ]        ← hasMore일 때만  │
│ ────────── 2026-08-06 ──────────                     │
│        건성피부에 좋은 제품 추천해주세요      09:31 │
│ 09:32  AI  안녕하세요! 건성 피부를 위한…            │
└──────────────────────────────────────────────────────┘
┌ AI 브리핑 ───────────────────────────────────────────┐
│ (요약 생성 중…)  ← 대화 표시를 막지 않음             │
└──────────────────────────────────────────────────────┘
```

## Stage 2 — 모범답안 → 지식 저장

대상: `apps/web/src/domain/live-chat/{LiveChatPage.tsx, KnowledgeCaptureModal.tsx(신규)}`,
`apps/api/src/domain/knowledge/{knowledge.controller.ts, knowledge.service.ts, dto/request/knowledge.request.ts}`, i18n

1. **API**: `CreateDocumentRequest`에 `source_url?`(생성 시에도 허용) + `doc_group` 값 검증(`@IsIn(counsel|product)`) 추가.
   생성 로직은 현행 그대로(동기 임베딩 + 실패 시 재시도).
2. **콘솔**: AI 답변 말풍선에 **[지식으로 저장]** 액션(권한 보유자에게만).
   클릭 시 모달:
   - 상단: **고객 질문**(바로 앞 user 메시지, 다른 메시지로 변경 가능) + **AI 원답변**(읽기 전용 참고)
   - 입력: 제목(기본값=질문 앞 80자), 분류(기본 `faq`), **모범답안**(기본값=AI 답변, 편집)
   - 저장 → `POST /knowledge/documents` → 성공 토스트 + "지식 문서 보기" 링크
3. 저장 문서의 `source_url`에 대화 딥링크를 넣어 출처를 남긴다.

```
┌ 지식으로 저장 ───────────────────────────────┐
│ 고객 질문                                     │
│  [한국 화장품 회사 제휴문의드립니다        ▾] │ ← 대화 내 user 메시지 선택
│ AI 원답변 (참고)                              │
│  ┌─────────────────────────────────────────┐ │
│  │ …제가 이 채팅에서 바로 도와드릴 수 …    │ │ (읽기 전용)
│  └─────────────────────────────────────────┘ │
│ 제목 [한국 화장품 회사 제휴문의            ]  │
│ 분류 [faq ▾]                                  │
│ 모범답안                                      │
│  ┌─────────────────────────────────────────┐ │
│  │ 안녕하세요, 문의 주셔서 감사합니다…     │ │
│  │ help@ivyusa.com 으로 보내주시면 …       │ │
│  └─────────────────────────────────────────┘ │
│                        [취소] [지식으로 저장] │
└───────────────────────────────────────────────┘
```

## 사이드 임팩트

| 영역 | 검토 | 판단 |
|---|---|---|
| 브리핑 분리 | 기존 응답에서 `briefing` 필드 사라짐 → 콘솔만 소비 | 동시 배포로 정합 |
| 메시지 제한 | 오래된 상담 전체를 한 번에 보던 동작 변경 | 더보기로 도달 가능, 기본 30건 |
| 5초 폴링 | 폴링은 최근 30건만 조회 → 더 가벼워짐 | 개선 |
| 지식 쓰기 권한 | 상담사(MANAGER/STAFF)는 버튼 미노출 | D3 결정대로, 제안 큐는 후속 |
| 임베딩 비용 | 저장 1건당 임베딩 1회 | 미미 |
| 잘못된 지식 저장 | 사람이 쓴 문서가 검색에서 우대(SOURCE_BONUS) | 편집·비활성화는 기존 지식 화면에서 가능, 출처 링크로 추적 |

## 검증 계획 (TCR)

- 단위: listMessages limit/before_id 분기, 브리핑 엔드포인트 캐시 동작, 문서 생성 시 `source_url`/`doc_group` 검증.
- 통합(스테이징): 대화 최초 오픈 응답시간 **5~8초 → 1초 미만**, 싱크 버튼 즉시 반영,
  더보기 블록 로드, 세션 105 사례로 모범답안 저장 → 지식 문서 생성·임베딩 확인 →
  동일 취지 질문에 **새 답변이 반영**되는지(위젯에서 재질문).
