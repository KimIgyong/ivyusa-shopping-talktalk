# REQ-260808-Console-Product-List

콘솔에서 **가져온(동기화된) 상품 목록을 보는 화면** 요구사항.

- 작성일: 2026-08-08
- 요청: "가져온 상품목록 보기 화면 필요"
- 관련: `REQ/PLN/TCR/RPT-260808-Cafe24-Product-Knowledge`(상품 가져오기), `PLN-260807-IvyusaApp-Revamp F1`(products_cache)

---

## 1. AS-IS

`products_cache`에 상품이 들어왔는지, 무엇이 들어왔는지 **콘솔에서 볼 방법이 없다.**

- 상품을 읽는 API는 `GET /products` 하나뿐인데 **위젯 전용**이다: `@Public` + 세션 토큰 기반이라 콘솔 JWT로는 호출할 수 없고, `status='active'`만 돌려주므로 **보관(archived)된 상품은 보이지 않는다**.
- `/admin/products`에는 동기화 트리거(`POST sync`)만 있고 조회가 없다.
- 콘솔 사이드바에 상품 메뉴 자체가 없다.
- 그래서 이번 Cafe24 검증도 **DB에 직접 접속해서** 확인해야 했다(28건, 카테고리 23건 등). 운영자는 그 방법이 없다.

## 2. TO-BE

| ID | 요구사항 |
|---|---|
| FR-P1 | 콘솔에서 테넌트의 **가져온 상품 전체**(판매중 + 보관됨)를 페이지 단위로 본다 |
| FR-P2 | 상품명·태그 **검색**, **카테고리** 필터, **상태**(판매중/보관됨) 필터 |
| FR-P3 | 행마다 이미지·상품명·카테고리·가격·상태·최종 동기화 시각·몰 상품 링크 |
| FR-P4 | **지식 등록 여부**를 행에 표시 — "가져온 상품이 실제로 상담에 쓰이는가"가 이 기능의 목적이므로, 캐시에만 있고 지식이 안 된 상품을 즉시 구분할 수 있어야 한다 |
| FR-P5 | 상단 요약: 총계 / 판매중 / 보관됨 / 지식 등록 수 / 마지막 동기화 시각 |
| FR-P6 | 상품이 0건일 때 "설정에서 상품을 먼저 가져오세요" 안내(빈 화면에 아무 설명도 없으면 고장과 구분되지 않는다) |

**비요구(이번 범위 밖)**: 상품 편집·삭제, 이 화면에서의 동기화 실행(설정 화면의 [상품 가져오기]에 이미 있음 — 플랫폼별 분기를 화면에 중복시키지 않는다), 지식 문서 편집(지식 화면에 있음).

## 3. 제약

- 멀티테넌시: 조회는 반드시 `tenant_id` 스코프.
- 권한: 기존 상품 동기화와 같은 게이트(`module.operations`)를 쓴다 — 새 capability를 만들지 않는다.
- 목록 응답은 `Paginated` + `buildPagination`, 프런트는 `apiGetList`.
- 지식 연결은 `kb_documents.external_key = products_cache.handle`(doc_group='product') — 이미 성립하는 관계이므로 스키마 변경 없음.
- 가격은 화면 표시용으로만 쓴다(지식 문서에는 여전히 넣지 않는다).

## 4. 수용 기준

- AC-1 콘솔 사이드바에서 상품 화면에 진입해 테넌트 상품이 보인다(보관된 상품 포함).
- AC-2 검색·카테고리·상태 필터가 각각, 그리고 함께 동작한다.
- AC-3 각 행에서 지식 등록 여부를 구분할 수 있다.
- AC-4 상단 요약 숫자가 실제 DB 집계와 일치한다.
- AC-5 다른 테넌트의 상품은 어떤 경로로도 보이지 않는다.
- AC-6 상품 0건이면 다음 행동을 안내한다.
