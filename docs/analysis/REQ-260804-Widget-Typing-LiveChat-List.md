# REQ — 위젯 답변 대기 인디케이터 + /live-chat 목록 개선 (2026-08-04)

## 1. 요구사항 원문

1. (위젯, ambshop-dev) 채팅 답변이 나오기까지 몇 초간 아무 움직임이 없음 →
   `[담당자가 답변을 작성중입니다…]` 텍스트 또는 `..` `...` `....` 표시 노출.
2. (콘솔 `/live-chat`) 대화방 목록에 **개설시간 / 마지막답변시간** 표시.
   목록 출력이 너무 오래 걸림 → 시간 단축. 대화방 **고객명 검색** 필요.

## 2. AS-IS (코드·실측)

### 2.1 위젯 답변 대기

- `POST /chat/message`는 서버에서 RAG+AI 완성까지 **동기 처리** — 이 대기(수 초)가 요구의 공백.
- 대기 중 표시는 전무: `sending`은 전송버튼 disable/aria-busy에만 사용(`ChatTab.tsx:236,354`).
  타이핑 인디케이터 컴포넌트 없음. `ChatMessage.pending` 필드는 선언만 되고 미사용.
- 상담사(agent) 모드: 응답 `reply:null` + 5초 폴링으로 사람 답변 수신 — 이때도 아무 표시 없음.
  대화 상태(`ai_active/waiting/agent`)는 API 응답에 있으나 위젯 훅이 버림(`useChat.ts:44-45`).

### 2.2 /live-chat 목록

- **API는 빠름**: 스테이징 실측 `GET /agent/sessions → 4~21ms` (대화 77건·메시지 342건).
  "목록이 느리다"의 실체는 서버가 아니라 **프런트 갱신 구조**:
  - 목록 폴링 15초(`live-chat.hooks.ts:11`) → 새 상담/변경이 최대 15초 늦게 표시.
  - **열린 대화방은 자동 갱신 없음**(`useConversation` refetchInterval 부재) — 고객의 새 메시지가
    상담사가 뭔가 보내거나 새로고침하기 전까지 안 보임(중대 결함).
- 시간 표시: 응답에 `createdAt`은 있으나 UI 미표시. **마지막답변시간은 응답에 없음**
  (서버는 마지막 메시지를 이미 조회하면서 `body`만 쓰고 `createdAt`을 버림 — mapper 한 줄 거리).
- 필드 불일치 버그: 서버는 `lastMessagePreview`, 클라이언트는 `lastMessage`를 읽어
  **미리보기가 항상 '—'** 로 표시됨.
- 검색: 목록에 검색 UI 없음. `customers.name`은 AES-256-GCM 암호화(PRV-M6)라 서버 LIKE 불가.
  기존 선례: 상담사 "고객 연결" 검색이 **복호화-후-필터**(최근 500명 한정) 방식
  (`CustomerService.searchByEmailOrName`).
- 성능 예방 관점: `conversations`에 `(tenant_id,status,id)` 복합 인덱스 부재(현재 규모에선
  무해하나 성장 시 filesort), 마지막메시지 조회가 `retrieval_trace JSON`까지 전체 컬럼 로드.

## 3. TO-BE

1. 위젯: 메시지 전송 직후 **타이핑 버블(●●● 애니메이션 + 문구)** 표시.
   - AI 응답 대기(ai_active): "답변을 작성 중입니다…"
   - 상담사 모드(waiting/agent): "담당자가 답변을 작성 중입니다…" — 답변 도착까지 유지.
2. /live-chat 목록: 각 항목에 개설시간·마지막답변시간 표시(상대시간+툴팁 절대시간),
   미리보기 정상화, **고객명/이메일 검색 박스**, 목록 폴링 15s→5s + **열린 대화방 5s 폴링**.

## 4. 사용자 플로우 (TO-BE)

```
[쇼퍼]  메시지 전송 → 즉시 ●●● "답변을 작성 중입니다…" → AI 답변 도착시 교체
        (상담사 연결 상태면 "담당자가 답변을 작성 중입니다…"가 폴링 수신까지 유지)

[상담사] /live-chat 진입 → 목록(고객명·상태·미리보기·개설/마지막답변 시간, 5s 갱신)
        → 검색박스에 고객명 입력 → 해당 고객 대화만 필터
        → 대화방 열람 → 고객 새 메시지가 5s 내 자동 표시
```

## 5. 제약

- 이름 검색은 암호화 제약상 **완전한 부분일치 서버검색 불가** — 복호화-후-필터(최근 500 고객
  한정, 기존 선례와 동일 한계)로 구현. 한계는 UI/문서에 명시. (name_hash 블라인드 인덱스는
  정확일치만 가능해 부분검색 요구에 부적합 → 채택 안 함)
- 폴링 주기 단축은 서버 부하 증가(콘솔당 3배) — API 실측 4~21ms로 여유 충분.
- 진짜 "작성 중" 신호(상담사 키 입력)는 실시간 채널(SSE/WS)이 필요해 범위 외 —
  본 건은 대기 상태 표시로 충족.
