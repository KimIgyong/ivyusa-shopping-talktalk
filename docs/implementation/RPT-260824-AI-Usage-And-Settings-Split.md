## 2. 요청과 실제 작업의 차이

### A — "사용량 통계"는 리포팅이 아니라 계측이었습니다
토큰 수는 **계산되고 있었지만 저장되는 곳이 코드 전체에 0곳**이었습니다. 어댑터가 매 호출마다
`tokensIn`/`tokensOut`을 돌려주고 `RagService`가 호출자에게 넘긴 뒤 사라졌습니다.

그래서 화면보다 계측이 먼저 들어갔습니다. **소급 집계는 불가능**하며, 데이터는 2026-08-24부터
존재합니다.

### B — "페이지 분할"의 쟁점은 UI가 아니라 메뉴 권한이었습니다
15개 섹션 중 12개가 이미 독립 컴포넌트여서 이동이 대부분이었습니다. 실제 쟁점은 카탈로그의
규칙 **"1코드 = 1화면"**이었고, 6개 화면은 코드 6개를 뜻했습니다.

**지금이 가장 싼 시점이었습니다** — 스테이징에 `settings`를 참조하는 저장 예외가 0건이라
이관이 없었습니다. 배포 직전에 다시 세어 확인했습니다.

## 3-1. 내비게이션 결정 변경 (2026-08-25)

계획서 D6은 **접이식 2단**을 권장안으로 잡았고 #365는 **평면 6줄**로 구현했습니다.
실제로 배포해 보니 좌측 메뉴에 "설정"이라고 읽히는 줄이 6개 생기고 전체가 20개를 넘었습니다.

사용자 결정으로 **좌측 메뉴는 `설정` 한 줄, 그 안에 탭 7개**로 바꿨습니다(#367).
**개인정보 처리 안내도 탭으로 편입**했습니다 — 그것도 설정인데 매일 쓰는 화면 옆에 혼자
서 있었습니다.

| | 계획서 D6 | #365 | **#367(최종)** |
|---|---|---|---|
| 좌측 메뉴 | 접이식 2단 | 평면 6줄 | **1줄** |
| 화면 도달 | 메뉴 | 메뉴 | 탭 |
| 라우트 | 6개 | 6개 | **7개(중첩)** |

**탭이지만 라우트는 유지했습니다.** 로컬 state로 만들면 코드는 짧아지지만 딥링크가 죽고,
뒤로가기가 설정 화면을 통째로 벗어나며, 새로고침하면 첫 탭으로 돌아갑니다.

**탭별 권한 판정도 유지했습니다.** 화면을 나눈 덕에 "위젯 설정은 되고 자격증명은 안 됨"을
표현할 수 있게 됐는데, 메뉴를 접으면서 조용히 되돌리면 분할의 이유가 사라집니다. 배포본에서
확인했습니다 — 메뉴 번들에는 하위 코드가 없고, 레이아웃 청크에는 6개가 그대로 있습니다.

부수 효과 하나: 자식 페이지가 각자 `PageHeader`를 갖고 있어 레이아웃 헤더와 겹쳤습니다.
**페이지가 두 개 쌓인 것처럼** 보여 자식 헤더를 지우고 설명 줄만 남겼습니다 — 탭은 이름은
주지만 용도는 주지 못합니다.

## 4. 설계 판단 기록

- **계측은 게이트웨이 한 곳.** 호출자 10여 곳에 흩으면 열한 번째가 조용히 누락되고, 침묵은
  "그 기능은 싸다"로 읽힙니다.
- **계측을 `await` 하지 않습니다.** 고객 응답 경로에 있는 코드입니다. 통계를 지키자고 대화를
  늦추거나 깨뜨리는 건 잘못된 교환입니다.
- **합치지 않는 축 둘**: `engine_owner`(청구서가 다름), `stub_calls`(토큰 0이라 섞이면
  응답 못 하는 엔진이 "싼 트래픽"으로 보임).
- **stub 폴백은 *원래 답했어야 할* 엔진 앞으로** 기록합니다. stub 앞으로 달면 실패한 엔진은
  사용량도 실패도 0이라 그냥 안 쓰는 엔진처럼 보입니다.
- **`engine_id`는 nullable** — 엔진을 지워도 그 엔진이 쓴 기록은 남아야 합니다.
- **금액은 표시하지 않습니다.** 모델별 단가가 바뀌고, 틀린 금액은 없느니만 못합니다.
- **화면에 집계 시작일을 표시합니다.** 없으면 계측 이전 달이 "사용량 0"으로 읽히는데, 그건
  다르고 틀린 진술입니다.
- **`MENU.SETTINGS`는 남깁니다.** 지우면 플랜 프리셋과 nav 참조가 한꺼번에 깨집니다.
  `/settings`는 첫 화면으로 리다이렉트합니다.
- **플랜은 6개를 한 덩어리로** 줍니다. 플랜별 분할은 아무도 하지 않은 영업 판단이고, 실수로
  인코딩하면 지금 쓰는 테넌트에게서 화면이 조용히 사라집니다.
- **자체 개발 연동에 재발급 버튼을 넣지 않았습니다.** 재발급 엔드포인트가 없습니다. 저장이 곧
  교체이므로 그 사실을 문구로 적었습니다 — 조용히 웹훅을 실패시키는 버튼보다 정직합니다.

## 5. 계측이 배포 당일 잡아낸 것

첫 실호출에서 **`stub_calls=1`**이 함께 기록됐습니다. 응답은 그럴듯했지만 stub이 답한 것이었고,
계측이 없었다면 정상으로 넘어갔을 상황입니다. 따라가니 둘이 나왔습니다.

**① 제가 만든 데이터 오류** — go2joy 엔진 행의 `endpoint`에 `go2joy`가 들어가 있었습니다.
콘솔 API를 쓰지 않고 DB에 직접 INSERT 한 대가입니다.

**② 저장된 키가 비밀번호 형태의 값으로 바뀌어 있었습니다** — 15:35에 넣고 복호화·실호출로
확인했을 때는 정상(암호문 136바이트)이었는데, 확인 시점에는 10자짜리 값(38바이트)이었고
Anthropic이 401을 반환했습니다.

원인은 **제가 만든 AI 키 입력란에 `autoComplete="off"`가 빠진 것**으로 보입니다. 바로 옆
자격증명 다이얼로그는 이미 그 가드를 갖고 있었는데 새 카드에서 빠뜨렸습니다. 비밀번호
관리자가 콘솔 로그인을 제안하고 그대로 저장되면 키가 조용히 교체되며, 증상은 몇 시간 뒤의
401뿐입니다. PR #365에서 고쳤습니다.

둘 다 정정 후 **실제 Claude 응답, 폴백 0건**을 확인했습니다.
