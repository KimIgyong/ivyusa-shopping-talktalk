| # | 요구 | 현행 | 판정 |

| ② | 1분 무응답 시 종료 | 자동 종료 경로 없음 (고객이 직접 종료하는 경로만 있음) | **미구현** |

### 다만 **자리는 이미 마련돼 있습니다**

`agent_daily_stats.csat_avg` 컬럼이 **이미 존재하는데 값을 쓰는 코드가 한 줄도 없습니다.** 상담원 통계 화면과 매퍼(`agent.mapper.ts:78`)까지 이 값을 실어 나르도록 만들어져 있고, 채워 넣을 입력원만 없었습니다. **이번 요구가 정확히 그 입력원입니다.**

### 실측 — 방치가 실제로 존재합니다

| 지표 | 값 |
|---|---|
| `agent` 상태 대화 | **7건**, 전부 24시간 이상 상담원 메시지 없음 |
| 가장 오래된 방치 | 대화 5번 — 마지막 메시지 **2026-06-30** (40일 이상) |
| 답 없는 고객 메시지 | **10건** |

S1(재위임)으로 상담원이 **의도적으로** 넘길 수는 있게 됐지만, **아무도 아무것도 하지 않는 경우**는 여전히 아무 일도 일어나지 않습니다.

## 1. AS-IS

### 1-1. 대화 종료 경로 (요구 ①②)

| 경로 | 트리거 | 결과 |
|---|---|---|
| 상담원 종료 | 콘솔 `[상담 종료]` | `ended` + `endedAt` + 배정 해제 + 이슈 종결 |
| 고객 종료 | 위젯 종료 | 동일 + 이슈 **자동 해결** 처리 |
| **시간 경과** | **없음** | — |

- 스케줄러 패턴은 이미 있습니다(`scheduled-shopify-sync`, `scheduled-cafe24-sync`: `onModuleInit` + `setInterval` + `unref`, 간격은 환경변수). **방치 감지만 없습니다.**
- 대화가 며칠씩 열려 있어도 아무 비용이 들지 않으므로 지금까지 드러나지 않았습니다 — 드러난 계기가 S1 조사였습니다.

### 1-2. 종료 표시 (요구 ③)

`ChatTab.tsx:395` — `status === 'ended'`이면 구분선과 고정 문구(`chat.endedNotice`)만 표시합니다. 만족도를 물을 자리는 없고, 종료가 **상담원이 끝낸 것인지 자동인지 구분도 없습니다.**

### 1-3. 만족도 (요구 ④)

- `conversations`에 평점 컬럼 없음
- 제출 API 없음
- 위젯에 별점 컴포넌트 없음
- **`agent_daily_stats.csat_avg`만 존재** — 계산 주체 없음(§0)

## 4. 결정 필요 사항

| # | 항목 | 선택지 | 분석 의견 |
|---|---|---|---|
| **D1** | 방치 판정 시간 | 요구에 없음 — 15분 / **30분** / 60분 | **30분** 권장, 환경변수로 조정 가능하게 |
| **D2** | 대상 상태 | `agent`만 / **`agent` + `waiting`** | **둘 다** — 아무도 잡지 않아 대기열에 방치된 것도 같은 문제 |
| **D3** | 제외 대상 | — | **`reply_channel='email'`(오프아워 회신 약속) 반드시 제외** (G6) |
| **D4** | 평점 저장 | 신규 테이블 / **conversations 컬럼 2개** | **컬럼**(`csat_rating`, `csat_rated_at`) — 대화당 1건이라 테이블이 과함 |
| **D5** | 평점 제출 기한 | 종료 즉시만 / **24시간 내** | **24시간** — 고객이 나중에 위젯을 열어도 남길 수 있게 |
| **D6** | 재제출 | 1회 고정 / **마지막 값으로 갱신** | **갱신** — 오클릭 정정이 안 되면 데이터가 더 나빠짐 |
| **D7** | **기존 방치 7건 소급** | 자동 적용 / **최근 N일만** / 수동 1회 | **최근 7일 이내만 자동**, 그보다 오래된 건 조용히 종료(확인 질문 없이) — 40일 전 대화에 갑자기 말을 거는 건 고객 입장에서 이상합니다 |
| **D8** | 확인 질문 푸시 | 발송 / **미발송** | **미발송** — 새벽에 "더 도와드릴까요?" 푸시는 해롭습니다 |

## 5. 리스크

| # | 리스크 | 대응 |
|---|---|---|
| R1 | **1분은 매우 짧음** — 고객이 잠깐 자리를 비우면 종료됨 | 종료돼도 고객이 다시 말하면 **새 대화가 즉시 열립니다**(기존 `getOrCreateConversation`). 실질 손실은 스레드 연속성뿐이며, 요구대로 1분을 적용하되 환경변수로 조정 가능하게 |
| R2 | 오프아워 이메일 회신 대화를 종료 | D3에서 제외 |
| R3 | 확인 질문 반복 발송 | 발송 시각을 대화에 기록하고 **1회만** |
| R4 | 상담원이 응대 중인데 종료 | 판정 기준은 **상담원 마지막 메시지 이후 경과**이므로 응대 중이면 발동하지 않음 |
| R5 | 평점 조작(같은 세션 반복 제출) | 대화당 1행 갱신이므로 총량 조작 불가 |
