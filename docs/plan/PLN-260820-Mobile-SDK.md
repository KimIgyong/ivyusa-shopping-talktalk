# PLN-260820-Mobile-SDK

고객사 모바일 앱에 ShopTalk를 넣는 SDK(FR-S6) 구현 계획.

- 작성일: 2026-08-20
- 근거 요구: `docs/analysis/REQ-260819-Widget-Theming-Embed-SDK.md` FR-S6, Q-5(WebView 래퍼로 결정)
- 선행 완료: S1~S3 임베드 토대(PR #319), 테마 확장(#323), 배포 패키지(#325)
- 대상 고객사: **go2joy**(자체 개발 앱, 베트남) — 웹은 이미 S3 SDK로 붙는다
- **UI 변경 있음**(위젯의 앱 모드) → §5 와이어프레임
- **스키마 변경 없음**

---

## 0. 조사 결과 — WebView에서는 지금 아무것도 동작하지 않는다

위젯의 호스트 연동은 전부 `window.parent`를 전제로 한다. WebView 안에서는
`window.parent === window`이므로 **네 개 훅이 모두 즉시 빠져나간다**:

| 훅 | WebView에서 |
|---|---|
| `useEmbedIdentity` | 신원 핸드셰이크 없음 → 항상 게스트 |
| `useEmbedCommands` | `identify`·`open`·`logout` 도달 불가 |
| `useLauncherReport` | 보고 대상 없음(앱에서는 무해) |
| `usePurchaseSignal` | 스토어프론트 없음(무해) |

즉 "웹 SDK를 WebView에 그대로 넣으면 된다"가 아니다. **호스트 채널의 추상화**가 이 작업의 본체다.

그리고 화면도 그대로 쓸 수 없다:

- 임베드가 아니면 App이 **데모 스토어프론트**를 함께 렌더한다 — 고객사 앱 안에서는 나오면 안 된다.
- 런처 버튼이 뜬다 — 앱은 자기 진입점(문의하기 버튼)이 따로 있다.
- 패널의 닫기(X)는 패널만 닫는다 → WebView에는 **빈 화면**이 남는다.

좋은 소식 하나: 패널은 이미 모바일 폭에서 전체화면이다(`fixed inset-x-0 bottom-0 top-0`),
따라서 레이아웃을 새로 만들 필요는 없다.

## 1. 설계

### 1.1 호스트 채널을 추상화한다 (핵심)

```
                 웹(iframe)                     앱(WebView)
호스트→위젯   parent.postMessage()          RN: injectJavaScript()
                                            iOS: evaluateJavaScript()
                                            AOS: evaluateJavascript()
                                              → window.__shoptalkHost(json)

위젯→호스트   window.parent.postMessage()   RN: window.ReactNativeWebView.postMessage()
                                            iOS: webkit.messageHandlers.shoptalk.postMessage()
                                            AOS: window.ShopTalkAndroid.postMessage()
```

위젯에 `lib/host-bridge.ts`를 두고 네 훅이 그것만 쓰게 한다:

- `hostPresent()` — 부모 프레임 **또는** 네이티브 브리지가 있는가
- `postToHost(msg)` — 있는 채널로 보낸다
- `onHostMessage(fn)` — `message` 이벤트 + 네이티브가 부르는 전역 함수 둘 다 받는다

**메시지 타입은 웹과 동일하게 유지한다**(`ivy:ready`·`ivy:identify`·`ivy:command`·`ivy:event`).
앱 전용 프로토콜을 새로 만들면 같은 기능이 두 벌이 되고, 웹에서 고친 버그가 앱에 남는다.

### 1.2 앱 모드 (`?mode=app`)

| 동작 | 웹 임베드 | 앱 |
|---|---|---|
| 데모 스토어프론트 | 없음 | 없음 |
| 런처 버튼 | 있음 | **없음**(호스트 앱이 연다) |
| 패널 | 닫힌 채 시작 | **열린 채 시작** |
| 닫기(X) | 패널만 닫음 | **호스트에 닫아달라고 요청**(`ivy:close-request`) |

닫기 처리가 중요하다 — 앱에서 패널만 닫으면 사용자는 **아무것도 없는 하얀 화면**을 본다.

### 1.3 신원은 웹과 완전히 같다

고객사 서버가 `HMAC(embed_secret, userId)`로 서명 → 앱이 SDK에 넘김 → 위젯이
`POST /public/embed/identify`로 검증(PLN-260819 S2). **앱에는 시크릿이 들어가지 않는다** —
앱 번들은 뜯어볼 수 있으므로 서명은 반드시 고객사 서버에서 만든다. 가이드에 굵게 적는다.

### 1.4 무엇을 만들고 무엇을 만들지 않는가

| 만든다 | 만들지 않는다 |
|---|---|
| 위젯의 호스트 브리지 + 앱 모드 | 네이티브 UI 재구현(Swift/Kotlin 채팅 화면) |
| **RN 참조 컴포넌트**(`packages/shoptalk-rn`) | npm 레지스트리 발행 |
| 브리지 계약 문서 + iOS/Android 연동 스니펫 | 완성형 Swift/Kotlin SDK 패키지 |
| 브리지 계약 자동 테스트 + 시뮬레이터 페이지 | 실기기 자동화 테스트 |

go2joy의 앱 스택을 아직 모른다. **계약(브리지 프로토콜)이 진짜 산출물**이고, RN 컴포넌트는
그 계약의 참조 구현이다. 네이티브라면 같은 계약에 스니펫 30줄이면 붙는다.

### 1.5 모바일에서만 터지는 것들

| 항목 | 처리 |
|---|---|
| **첨부 업로드** | Android WebView는 `onShowFileChooser`를 구현하지 않으면 파일 선택이 **조용히 아무 일도 안 한다.** RN 컴포넌트에 포함하고 네이티브 가이드에 명시 |
| 링크 | 대화 속 외부 링크는 시스템 브라우저로 — 채팅 WebView 안에서 열리면 돌아올 길이 없다 |
| 키보드 | 입력창이 키보드에 가리지 않도록 RN 컴포넌트가 처리 |
| 세션 유지 | localStorage가 앱별로 유지된다(추가 작업 없음) |
| 푸시 | **비범위** — 호스트 앱의 푸시 체계를 쓴다 |

## 2. 단계 계획 (WBS)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **W1** | `host-bridge.ts` + 네 훅 이관 | 웹 임베드 **무회귀**(기존 계약 테스트 통과) |
| **W2** | 앱 모드(`?mode=app`) — 런처 없음·패널 열림·닫기 요청 | 시뮬레이터 페이지에서 확인 |
| **W3** | `packages/shoptalk-rn` 참조 컴포넌트(파일 선택·외부 링크·키보드 포함) | typecheck·lint 통과 |
| **W4** | 브리지 계약 문서 + iOS/Android 스니펫 + 연동 가이드 | 처음 보는 앱 개발자가 따라갈 수 있는가 |
| **W5** | 계약 테스트 + 시뮬레이터 페이지, 스테이징 배포 | §4 |

## 3. 부수영향 분석

| # | 영역 | 영향 | 대응 |
|---|---|---|---|
| 1 | 웹 임베드(ivyusa·amoebaorder 실사용) | 네 훅을 전부 건드린다 | 브리지는 **기존 동작의 상위 추상화**일 뿐. 로더 계약 테스트 + 무회귀 확인이 W1 완료 조건 |
| 2 | `usePurchaseSignal`·`useLauncherReport` | 앱에서는 의미 없음 | 브리지가 "네이티브 호스트"를 구분해 보고를 생략 |
| 3 | 위젯 번들 크기 | 브리지 + 앱 모드 분기 | 수십 줄 수준 |
| 4 | `?mode=app` | 새 URL 파라미터 | 없으면 지금과 동일 |
| 5 | 오리진 허용목록(S1) | WebView는 `parent_origin`이 없다 | 미전송 → 기존 규약대로 통과(관측 모드). 앱은 도메인 개념이 없으므로 **신원 서명이 방어선** |
| 6 | `packages/shoptalk-rn` | 새 워크스페이스 패키지 | 빌드에서 제외(참조 구현), CI 부담 없음 |

## 4. 테스트·검증

**자동**
- U-1 브리지: 부모 프레임 있음 → postMessage 사용
- U-2 브리지: `window.ReactNativeWebView` 있음 → 그쪽으로 전송
- U-3 브리지: `webkit.messageHandlers` / Android 인터페이스 각각
- U-4 브리지: 호스트 없음(standalone) → 아무 데도 보내지 않고 조용
- U-5 `window.__shoptalkHost(json)` 수신 → 핸들러 호출, 잘못된 JSON은 무시
- U-6 **웹 무회귀**: 기존 로더 계약 테스트 전부 통과
- U-7 앱 모드: 런처 미표시·패널 열림·닫기가 `ivy:close-request`를 보냄

**수동(시뮬레이터 페이지)**
- `apps/widget/public/webview-test.html` — 네이티브 호스트를 흉내 내어 `identify`·`open`·
  `close-request`를 주고받는다. 실기기 없이 계약을 눈으로 확인하는 용도.

**한계(정직하게)**: 실기기·실앱 검증은 못 한다. RN 컴포넌트는 타입 검사와 계약 테스트까지가
한계이고, **실제 통합은 go2joy 앱에서 처음 확인된다.** 그 전제로 가이드에 체크리스트를 넣는다.

## 5. 와이어프레임

### 5.1 호스트 앱에서의 흐름

```
go2joy 앱                                   ShopTalk WebView
┌─────────────────────┐                    ┌─────────────────────┐
│  마이페이지          │   [문의하기] 탭 →  │ ← 뒤로   IVY 고객센터│
│                     │                    ├─────────────────────┤
│  ┌───────────────┐  │                    │ 안녕하세요!          │
│  │   문의하기     │──┼───────────────────▶│      ┌────────────┐ │
│  └───────────────┘  │                    │      │ 예약 문의   │ │
│                     │  ◀── close-request │      └────────────┘ │
│                     │      (X 눌림)      │ [메시지 입력]   [전송]│
└─────────────────────┘                    └─────────────────────┘
        ShopTalk.identify({userId, hash})는 화면 진입 시 1회
```

### 5.2 앱 모드에서 없어지는 것

```
웹 임베드                        앱 모드(?mode=app)
┌──────────────────┐            ┌──────────────────┐
│  데모 스토어프론트 │            │                  │
│                  │            │   채팅 패널       │
│           ( 💬 ) │  ←런처      │   (전체화면)      │
└──────────────────┘            └──────────────────┘
   런처·스토어프론트 없음, 패널이 처음부터 열림
```

## 6. 승인 요청

| 항목 | 계획값 |
|---|---|
| 방식 | WebView 래퍼(REQ Q-5 결정) — 네이티브 UI 재구현 없음 |
| 핵심 | 위젯의 **호스트 채널 추상화**(웹 iframe / RN / iOS / Android 공용) |
| 프로토콜 | 웹과 **동일한 메시지 타입** 유지 |
| 앱 모드 | 런처 없음 · 패널 열림 · 닫기는 호스트에 요청 |
| 신원 | S2 서명 그대로. **앱에 시크릿을 넣지 않는다** |
| 산출물 | 브리지 + 앱 모드 + RN 참조 컴포넌트 + 계약 문서 + 시뮬레이터 |
| 비범위 | 네이티브 SDK 패키지, npm 발행, 푸시, 실기기 자동화 |

위 내용으로 **구현 착수 승인**을 요청합니다.
