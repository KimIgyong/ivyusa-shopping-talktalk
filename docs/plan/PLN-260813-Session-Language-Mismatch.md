## 0. 무엇을 바꾸는가

```
[시작]   위젯 진입 시 브라우저 언어(지원 3종일 때만) → locale 힌트
[대화 중] 고객 메시지 언어가 세션 언어와 다르고, 그 언어가 연속 2회 나오면 → 세션 언어 갱신
[예외]   고객이 언어 선택기로 직접 고른 세션은 자동 갱신하지 않음
```

바뀌는 것은 **시스템 문구가 어느 언어로 나가는가**입니다. AI 답변은 지금도 고객 언어를 따라가므로 손대지 않습니다 — **둘의 판단 시점을 맞추는 작업**입니다.

---

## 1. 단계별 계획

### P1 — 언어 감지 유틸 (D1·D5)

`apps/api/src/global/util/detect-language.util.ts` 신설. **모델 호출 없음, 문자 범위만.**

| 규칙 | 내용 |
|---|---|
| KO | 한글 음절(`가-힣`)이 **1자 이상** → 한국어. 한글은 다른 지원 언어와 겹치지 않으므로 확정적 |
| ES | 라틴 문자 중 스페인 고유 기호(`ñ`·`¿`·`¡`·`á é í ó ú ü`)가 있으면 스페인어 |
| EN | 위 어느 것도 아니고 라틴 문자가 대부분이면 영어 |
| **판정 보류(null)** | 의미 글자 **4자 미만**(`ok`·`ㅇㅇ`·`?`), 숫자·기호만, 어느 쪽도 아님 |

> ES/EN은 문자만으로 완전히 갈리지 않습니다. **고유 기호가 없는 스페인어 문장은 EN으로 읽힙니다** — 알면서 받아들이는 한계이며, 오탐(영어를 스페인어로 판정)보다 미탐이 안전하다는 판단입니다. 스페인어 사용자는 언어 선택기로 확정할 수 있고, 그 선택은 D3으로 보호됩니다.

### P2 — 세션 언어 갱신 (D2)

| 항목 | 설계 |
|---|---|
| 위치 | `chat.service` — 고객 메시지 저장 **직후**, 응답 생성 **이전**(그 턴의 시스템 문구부터 새 언어) |
| 조건 | 직전 고객 메시지 2건(현재 턴 포함)의 감지 결과가 **모두 같고**, 세션 언어와 **다를 때** |
| 데이터 | 저장된 메시지 본문을 다시 감지 — **새 컬럼 없음**(감지는 정규식이라 비용 0) |
| 제외 | `sessions.language_locked = 1`이면 갱신하지 않음(D3) |
| 기록 | 갱신 시 `logger.log` + 시스템 메시지는 **남기지 않음**(언어가 바뀐 사실 자체는 고객에게 알릴 일이 아님) |

**연속 2회를 요구하는 이유**: 한국어 대화 중 `ok` 한 마디로 영어로 뒤집히면 그 뒤 모든 안내가 영어가 됩니다. 다만 `ok`는 D5로 이미 보류되므로, 2회 조건은 **"짧지 않은 영어 문장이 두 번 연속"** 일 때만 전환한다는 뜻입니다.

### P3 — 수동 선택 잠금 (D3)

| 항목 | 설계 |
|---|---|
| 마이그레이션 | `sessions.language_locked TINYINT(1) NOT NULL DEFAULT 0` |
| 설정 시점 | `POST /session/language`(위젯 언어 선택기) 호출 시 **1** |
| 효과 | 이후 자동 감지가 그 세션의 언어를 바꾸지 않음 |

서버가 "이 값은 고객이 직접 골랐다"를 알 방법이 지금 없어서 컬럼 하나가 필요합니다. 위젯은 이미 `localStorage`로 자기 UI를 보호하고 있지만, **시스템 문구는 서버가 결정**하므로 서버에도 같은 사실이 있어야 합니다.

### P4 — 위젯 시작값 (D4)

- 스토어 기본값 `'en'` 하드코딩 → **`navigator.language`가 지원 언어(en/es/ko)면 그 값**, 아니면 기존대로 서버 판단(테넌트 타임존)에 맡김
- 수동 선택 이력(`localStorage`)이 있으면 그것이 최우선 — 현행 규칙 유지

## 2. 화면 설계

**UI 변경 없음.** 언어 선택기는 그대로이고, 달라지는 것은 **어떤 언어의 문구가 나가는가**입니다.

```
── 지금 ─────────────────────────      ── 이후 ─────────────────────────
고객:   뉴욕 날씨 알려주시오            고객:   뉴욕 날씨 알려주시오
system: We're outside our support…      AI:    날씨는 도와드리기 어렵지만…
고객:   배송 언제 오나요?               고객:   배송 언제 오나요?
system: We're outside our support…      system: 지금은 상담 가능 시간이 아니에요…
        ↑ AI는 한국어, 시스템은 영어           ↑ 2턴째에 세션 언어가 KO로 전환
```

## 3. 영향 범위

| 영역 | 영향 | 조치 |
|---|---|---|
| **시스템 문구 전반** | 이관·오프아워·재위임·방치·종료 안내가 감지 언어로 | 의도한 변화 |
| **오프아워 이메일** | 갱신 이후 발송분부터 새 언어 | 이미 보낸 메일은 그대로(R4) |
| **위젯 UI** | 서버 언어를 따라감(수동 선택 없을 때) | 기존 동기화 규칙 그대로 |
| **동의 고지** | 고지를 받은 언어와 대화 언어가 달라질 수 있음 | **재고지하지 않음**(D6) — 법무 확인 항목으로 기록 |
| **외부 메신저 채널** | `languageForChannel`이 이미 힌트를 처리 | 이번 변경은 위젯 세션에 한정 |
| **통계·감사** | 영향 없음 | |

## 8. 승인 요청

두 가지를 짚어둡니다.

1. **스페인어는 완전하지 않습니다.** 고유 기호(`ñ`·`¿`·악센트)가 없는 스페인어 문장은 영어로 읽힙니다. 문자 범위 감지(D1)의 구조적 한계이며, 정확도를 원하면 감지 모델이 필요합니다 — 지금은 **미탐이 오탐보다 안전**하다고 보고 수용했습니다.
2. **동의 고지 언어**는 바뀌지 않습니다(D6). 고객이 영어 고지에 동의한 뒤 대화가 한국어로 전환될 수 있는데, 동의 자체는 유효하나 **법무 확인이 필요한 항목**으로 남깁니다.
