# REQ-260828 go2joy 노션 연동 — 구현 여부 확인 및 작업 항목 분석서

- 작성일: 2026-08-28
- 요청: go2joy 테넌트의 노션 연동(토큰 등록 → 데이터 수집 → 분석 → 지식 등록)이 **현재 구현되어 있는지 확인**하고, 구현이 필요하다면 **작업 항목을 조사·분석**하라.
- 조사 방법: 코드 전수 추적(자격증명→소스→동기화→변환→등록→임베딩→검색) + 스테이징 DB/로그 실측(2026-08-28).

## 1. 결론 요약

| 질문 | 답 |
|---|---|
| 파이프라인이 구현되어 있는가? | **예 — 전 구간 구현·배포 완료**(PR #331, 2026-08-21). 토큰 등록(AES-256-GCM)·소스 생성·동기화·블록→텍스트 변환·kb_documents 등록·자동 임베딩·RAG 검색까지 이어짐. 스텁 없음 |

| 추가 구현이 필요한가? | 핵심 기능은 불필요. **운영 조치 1건(노션 공유) + E2E 검증**이 최우선이고, 조사에서 드러난 개선 항목(실패 사유 콘솔 미표시 등)은 §6에 우선순위로 정리 |

## 2. 현재 구현 상태 (AS-IS — 전부 기구현)

1. **토큰 등록**: `PUT /knowledge/notion/credential` — `integration_credentials(provider='notion')`에 AES-256-GCM 암호화 저장, 형식 검증(30~300자·URL 거부), 콘솔 표시는 끝 4자 마스킹. 감사 기록에 토큰 미포함.
2. **연결 테스트**: `POST /knowledge/notion/test` — 토큰만(`/users/me`) 또는 대상 포함(DB→페이지 폴백 프로브, 휴지통·미공유 안내 문구까지 구현). ⚠️ Sources 카드의 [연결 테스트]는 **토큰 전용**, 대상까지 검사하는 테스트는 **소스 추가 모달에만** 있음.
3. **소스 생성**: type `notion` + `config_json.targetId`(notion.so/app.notion.com URL·UUID·32hex 모두 파싱). 생성 시 ID 형식·토큰 존재/복호화 가능 검증. `supported` = gdrive·notion.
4. **동기화**: `POST /knowledge/sources/:id/sync` (수동 전용) — DB 타깃=행별 1문서, 페이지 타깃=자신+직계 하위 페이지(1단계). 가드: 350ms 페이싱, 429 1회 재시도, 요청 30s 타임아웃, 목록 상한 1,000, **회당 200페이지**(초과=dropped), 페이지당 요청 30회(초과=truncated), 블록 중첩 3단, 본문 30,000자.
5. **변환**: 문단·제목·리스트·토글·인용·콜아웃·코드·표를 마크다운형 텍스트로. 이미지·파일·임베드 등은 skipped 집계(로그만).
6. **등록**: `kb_documents`에 upsert(`externalKey='page:<id>'` — 제목 변경에도 안정), 재동기화 시 변경분만 갱신, **사라진 페이지는 삭제 아닌 숨김(active=0)**, 빈 목록 가드(연결 끊김=0건일 때 숨김 거부·failed 처리 — 핵심 안전장치).
7. **임베딩**: 동기화 직후 같은 요청에서 자동 — Voyage 임베딩→Qdrant 업서트, `status=embedded`. 실패 시 pending 유지→다음 동기화가 재시도.
8. **검색(RAG)**: embedded+active+소스 지정 유지 문서가 위젯 답변 인용에 참여.

## 4. "분석하여 지식으로 등록"의 실제 의미 — 기대치 정렬

- 현재: 페이지 원문(텍스트화) → 문서 1건으로 등록 → 벡터 임베딩 → 의미+키워드 하이브리드 검색으로 상담 답변에 인용. 카테고리는 **소스 이름이 그대로** 붙음.
- **AI에 의한 요약·Q&A 추출·카테고리 자동 분류는 하지 않음.** 이는 gdrive·CSV 등 다른 소스와 동일한 설계(원문 보존, RAG가 검색 시점에 활용). "분석"이 AI 가공을 의미한다면 그것은 신규 기능(§6 D — 선택).

## 5. 실 워크스페이스 미검증 항목 (TCR-260821 E1~E7 — go2joy가 첫 검증 기회)

노션 코드는 57개 유닛 테스트가 있으나 전부 mock — **실 워크스페이스 동기화 성공 사례가 0건**이다.
E1 DB 타깃 행별 문서화 · E2 페이지+하위 수집 · E3 100건 초과 커서 · E4 미공유 404 안내(이번에 **실증됨** ✅) · E5 연결 해제 시 빈 목록 가드 · E6 실문서 블록 변환 품질 · E7 200페이지 레이트리밋 실측. go2joy 연동 성공 = E1/E2/E3/E6 자연 검증.

## 6. 작업 항목 (우선순위)

### A. 즉시 — 운영 조치 (코드 변경 없음, go2joy 측 협조 필요)
1. 노션에서 대상 페이지 우상단 ⋯ → **Connections → "Truc connection" 추가**(하위 페이지는 자동 상속). 토큰 워크스페이스와 페이지 워크스페이스가 같은지 확인.
2. 콘솔 소스 추가 모달의 **대상 포함 테스트**로 도달 확인 → 소스 7 재동기화 → 문서 생성·embedded 확인 → 위젯에서 해당 지식 인용 확인.
3. 결과를 E1~E3/E6 검증 기록으로 남김(RPT). 필요 시 go2joy용 안내 가이드(GUIDE — 공유 방법 스크린샷, 베트남어 병기) 작성.

### B. P1 — 소규모 개선 (이번 실패가 직접 드러낸 갭)
1. **동기화 실패 사유를 콘솔에 표시**: 현재 `last_sync_status='failed'`만 저장되고 에러 메시지는 서버 로그 전용. `last_sync_result`에 사유(200자 클램프) 저장 + 소스 행에 표시. "미공유 404"는 이미 준비된 안내 문구로 매핑.
2. **Sources 카드 [연결 테스트]에 대상 검사 결합**: 카드 테스트=토큰 전용이라 이번처럼 "테스트 200 + 동기화 404"가 동시에 발생 — 테넌트의 노션 소스가 있으면 그 대상까지 프로브.

### C. P2 — 백로그 (기존 RPT-260821 잔여 + 이번 조사 추가)
1. 카테고리 정합: 동기화가 만든 카테고리(소스명)가 `kb_categories`에 미등록(드리프트)이고 **에이전트 스코프가 전체 공개** — go2joy처럼 파트너/게스트 에이전트가 분리된 테넌트는 동기화 후 카테고리 스코프 지정 필요(운영) 또는 `ensure()` 자동 등록(코드, 스코프 덮어쓰기 함정 주의).
2. `source='knowledge_store'` 하드코딩 — 노션 문서가 문서 목록 출처 필터에서 구분 불가.
3. 주기 자동 동기화 없음(수동 전용) · 동기화가 HTTP 요청 동기 실행(동시 클릭 락 없음, 200페이지≈70s+).
4. 페이지 상한(200)·요청 예산 설정화, config_json 수정 불가(오타 시 소스 재생성).

### D. 선택 — 신규 기능 (요구 확인 필요)
- AI 가공 등록(요약/Q&A 추출/자동 분류). 현 설계는 의도적 원문 보존 — 도입 시 별도 REQ/PLN.

## 7. 권고 진행 순서

**A(운영 조치·오늘 가능) → 성공 확인 후 B를 1PR로(스키마 무변경) → C는 운영 관측 후 판단.** 구현 대공사는 불필요 — 파이프라인은 완성돼 있고, go2joy는 노션 공유 한 번이면 첫 실 워크스페이스 검증 사례가 된다.
