# AI 설정 화면 기능 설명서 (`/ai-setting`)

| | |
|---|---|
| Doc ID | CHATWIDGET-GUIDE-AISETTING-1.0.0 |
| 작성일 | 2026-08-03 |
| 대상 화면 | 테넌트 콘솔 → **AI 설정** (`https://shoptalk.amoeba.site/ai-setting`) |
| 대상 독자 | 테넌트 운영자(마스터/디렉터), CS 운영 담당 |
| 관련 코드 | `apps/web/src/domain/ai-settings/` · `apps/api/src/domain/ai-engine/` · `apps/api/src/domain/moderation/` |

이 화면은 **해당 테넌트의 챗봇 AI 동작 전반**을 구성합니다. 5개 섹션(봇 페르소나 · 응답 규칙 ·
시나리오 버튼 · AI 기능 · 모더레이션 규칙)으로 이루어져 있습니다.

## 0. 공통 사항

- **접근 권한**: `ai_settings` 권한 — 테넌트 **마스터/디렉터** 랭크만 접근·수정 가능.
- **적용 범위**: 모든 설정은 **테넌트 단위**입니다. 다른 테넌트에는 영향이 없습니다.
- **반영 시점**: 저장 즉시 DB에 반영됩니다. 단, 페르소나·응답 규칙과 모더레이션 규칙은
  성능을 위해 **최대 60초 캐시**되므로, 진행 중인 대화에는 최대 1분 내에 반영됩니다.
  (저장 시 캐시를 비우므로 보통은 즉시 반영됩니다.)

---

## 1. 봇 페르소나 (Bot Persona)

**무엇인가**: AI 어시스턴트의 말투·성격·행동 원칙을 서술하는 자유 텍스트입니다.

**어디에 쓰이나**: 고객 질문에 AI가 지식(KB) 기반으로 답할 때마다(RAG 응답) **시스템 프롬프트의
맨 앞**에 삽입됩니다. 즉, 모든 AI 답변의 톤과 태도를 결정합니다.

**기본값**(비워두면 적용):
> "You are IVY USA's friendly, concise customer-support assistant. Be helpful and accurate, and only answer from the provided knowledge."

**작성 팁**
- 브랜드 톤(친근/정중), 답변 길이, 호칭, 금지 표현 등을 서술형으로 적습니다.
- 언어는 영어로 작성해도 됩니다 — 고객 응답 언어는 세션 언어(en/es/ko)를 따로 따르므로
  페르소나 언어와 무관하게 현지화됩니다.
- "정책서 §0 AI 답변 기준"류의 행동 규칙(처리 완료 표현 금지 등)은 아래 **응답 규칙**에
  항목별로 넣는 것이 관리에 유리합니다.

## 2. 응답 규칙 (Response Rules)

**무엇인가**: AI가 답변할 때 반드시 지켜야 할 규칙의 목록(한 줄 = 규칙 1개)입니다.

**어디에 쓰이나**: 페르소나 바로 뒤에 `Response rules:` 블록으로 붙어 모든 RAG 응답
프롬프트에 포함됩니다.

**사용법**: [규칙 추가]로 행을 늘리고, X로 삭제, 빈 행은 저장 시 자동 제거됩니다.

**예시 규칙**
- "환불·재배송 등 처리 완료를 단정하지 말고 Customer Support 확인이 필요하다고 안내"
- "특정 날짜 도착을 보장하지 않기"
- "의료적 효능을 보장하는 표현 금지"

## 3. 시나리오 버튼 (Scenario Buttons)

**무엇인가**: 고객용 채팅 위젯 하단 메뉴에 노출되는 빠른 실행 버튼입니다.
**여기서 정한 순서 그대로** 위젯에 표시됩니다(↑/↓로 순서 변경).

**필드**
- **라벨**: 버튼에 표시될 문구(최대 60자). 비우면 저장 시 그 버튼은 제거됩니다.
- **액션**: 버튼을 눌렀을 때의 동작(아래 표).
- **사용**: 체크 해제 시 위젯에 노출되지 않습니다(삭제하지 않고 잠시 숨길 때 사용).

**액션 7종 상세**

| 액션 | 위젯 동작 |
|---|---|
| 배송 조회 (delivery_status) | 배송 정책 **스크립트 응답**(3개 언어 준비된 고정 답변) + 후속 칩(주문 조회 등) 표시 |
| 취소 / 환불 (cancel_refund) | 취소·환불·반품 **스크립트 응답** + 후속 칩(주문 취소/환불 정책/교환·반품/상담원 연결) |
| 상품 도움말 (product_help) | **서브메뉴** 열림(사용법·성분·교환·재입고 문의 등) |
| 고객 지원 문의 (contact_support) | 문의 남기기(연락처) 인라인 폼 열림 — 상담원 연결 경로 |
| 내 주문 (my_orders) | 로그인(본인 확인) 후 **주문 탭**으로 이동. 미인증 시 인증 유도 |
| 제휴 (affiliate) | 제휴(어필리에이트) 안내 카드 표시 |
| 메시지 보내기 (message) | **버튼 라벨을 그대로 채팅 메시지로 전송** → AI가 지식(KB) 기반으로 답변. **커스텀 질문 버튼**을 만들 때 사용 (예: 라벨 "무료배송 기준이 뭐예요?") |

**기본 구성**(커스텀 저장 전): 배송 조회 / 취소·환불 / 상품 도움말 / 고객 지원 문의 / 제휴 / 내 주문 6종.

**주의**: 스크립트 응답(배송/취소환불)은 3개 언어로 고정 문구가 준비된 결정형 답변입니다.
정책이 바뀌면 이 스크립트 문구와 지식(KB) 내용이 함께 갱신되어야 합니다(개발팀 요청 필요).

## 4. AI 기능 (AI Functions)

**무엇인가**: AI가 사용되는 기능별로 **어떤 엔진(모델)** 을 쓸지, 생성 파라미터를 무엇으로
할지 정합니다. 엔진 목록은 플랫폼 관리자가 등록한 것 중 선택합니다.

**기능 5종이 각각 쓰이는 곳**

| 기능 | 실제 용도 |
|---|---|
| 채팅 (chat) | 고객 메시지의 **의도 분류**(주문조회/취소환불/일반문의) 등 대화 제어용 호출 |
| RAG / 검색 (rag) | **지식(KB) 기반 답변 생성** — 고객이 보는 AI 답변의 본체 |
| 요약 (summary) | 대화 요약 생성(상담 이력·핸드오프 요약) |
| 상담원 지원 (assist) | 상담원 콘솔의 AI 추천 답변/보조 |
| 모더레이션 (moderation) | 발신 메시지의 **문맥 분류기**(아래 §5의 context 규칙이 있을 때 LLM 판단) |

**파라미터**
- **온도(Temperature, 0~1)**: 낮을수록 일관·보수적, 높을수록 다양·창의적.
  CS 답변(rag)은 **0.2~0.4 권장**. 미입력 시 기본 0.3.
- **최대 토큰(Max tokens)**: 응답 길이 상한. 미입력 시 기본 1024. 챗 답변은 512~1024면 충분.

**폴백 동작**: 선택한 엔진이 꺼져 있거나 키가 없으면 테넌트 기본 엔진 → 플랫폼 기본 엔진 →
**스텁(무키 데모 응답)** 순으로 자동 강등되어 대화가 끊기지 않습니다.

**참고 — 임베딩(벡터 검색)은 이 화면에 없습니다**: 지식 검색용 임베딩 모델(voyage-4)은
모든 테넌트가 하나의 벡터 공간을 공유해야 하므로 **서버 환경변수로 전역 관리**합니다
(`VOYAGE_API_KEY`/`VOYAGE_MODEL`). 자세한 내용: `docs/analysis/AN-Voyage-Cost-Simulation-20260802.md`.

## 5. 모더레이션 규칙 (Moderation Rules)

**무엇인가**: AI와 상담원이 **내보내는 모든 메시지**를 발송 전에 검사하는 콘텐츠 필터입니다
(FR-069/POL-020 — 비우회, 오류 시 안전하게 **차단**).

**규칙 구성**
- **유형(Type)**: 단어/문구(포함 매칭, 대소문자 무시) · 정규식(예: `\bbadword\b`) ·
  **문맥(LLM)** — 패턴 대신 "무엇을 차단해야 하는지" 프롬프트를 적으면 모더레이션 엔진(LLM)이
  메시지마다 판정합니다(§4의 moderation 기능 엔진 사용).
- **적용 대상(Scope)**: AI만 / 상담원만 / 둘 다.
- **작업(Action)** — 실제 파이프라인 동작:

| 작업 | 실제 동작 |
|---|---|
| 차단 (block) | 메시지를 **전달하지 않음** (고객에게 미표시, 로그 기록) |
| 마스킹 (mask) | 매칭된 부분만 ▇▇▇로 치환 후 전달 |
| 재작성 (rephrase) | LLM이 안전한 문장으로 재작성 후 전달 |
| (레거시) 경고 warn | 과거 데이터용 — 현재 구현상 **차단과 동일**. 신규 생성 옵션에서 제외됨 |

> 2026-08-03 이전에 존재하던 제약(규칙 추가 모달 400, 패턴 컬럼 공백, flag 무동작 옵션)은
> 수정 배포로 해소되었습니다. `flag`로 저장된 기존 규칙이 있다면 삭제 후 재생성하세요.
