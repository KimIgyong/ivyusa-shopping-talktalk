# REQ-260829 — Smart Knowledge Board (지식 큐레이션 계층) 요구사항 분석

- 작성일: 2026-08-29
- 요청 유형: [요구사항] — **기존 프로세스와의 충돌 확인 + 최선안 제시**가 1차 산출물
- 선행 맥락: REQ-260829 지식 페이지 5종(PR #435~#443) 당일 완결 상태에서의 신규 요구

## 1. 요구사항 원문 요지

1. 모든 테넌트에 기본 1개의 **Smart Knowledge Board** 생성.
2. Board 문서 속성: 그룹 / 1차·2차 카테고리 / 제목 / 작성팀 / 작성자 / 작성·수정일 /
   수정자 / 내용(수정 히스토리) / 코멘트 / 관련자 태그 / 옵시디언 기능 / 태그 /
   마크다운+리치 에디터 / 외부 FAQ·Q&A 게시판 임포트 / 멀티파일 업로드(50MB,
   pdf·docs·xlsx·csv·png·jpg·webp·zip·rar) / 구글드라이브 링크.
3. **Board가 에이전트 지식의 기본 소스** — Board 문서를 운영자가 KB-Document로
   채택할지 판단.
4. 외부 자료: 분석 → 1차 Board 저장 → 관리자 선택분만 KB-Document.
5. 운영자 수기 작성도 Board 먼저 → **시뮬레이션(답변 생성 + 정확성 수치)** 확인 후
   KB-Document 채택.

## 2. 충돌 분석 — 기존 프로세스 대조

| # | 기존 | 신규 요구 | 판정 |
|---|---|---|---|
| C1 | **board 소스 타입을 어제(1차, PR #435) 폐기** — "글 쓸 화면이 없어 전부 빈 깡통"이 폐기 사유. `kb_board_posts` 테이블은 드랍 보류 중 | Board 재도입 | **충돌 아님 — 정합**. 폐기된 것은 "작성 화면 없는 파이프"였고, 이번 요구가 바로 그 빠져 있던 절반(작성·협업 화면)임. 단 `kb_board_posts` 스키마(제목/본문뿐)는 요구 필드에 크게 부족 → 재사용 불가, 신규 테이블 + 구 테이블 드랍 |
| C2 | **3차 AI 인제스트**(PR #439~): 초안이 메모리 잡에만 있고 승인 시 **KB-Document 직행** | 외부 자료는 1차 **Board 영속 저장** 후 선택 채택 | **경미한 충돌 — 개선 방향 일치**. 인제스트 승인 타깃을 KB → **Board 게시**로 재타깃하면 요구와 정확히 정렬. 초안 휘발성(서버 재시작 유실) 문제도 함께 해소. 파이프라인(추출·분할·검수 모달)은 그대로 재사용 |
| C3 | **Add KB-Document / 일괄등록**: KB 직행 | "운영자도 바로 저장하지 않는다" | **정책 충돌 — 결정 필요**. 강제 차단 vs 권장 동선. 권고: 콘솔 기본 동선을 Board 작성으로 바꾸되, KB 직행(단건 추가·일괄등록)은 **유지**(긴급 핫픽스·이관 작업용). 채택되지 않은 KB 직행 문서는 목록에 '직접 등록' 뱃지로 구분 |
| C4 | **카탈로그 동기화·상품 CSV**: 상품 2,000+건 KB 직행 | "모든 외부 자료 Board 경유" 문면 | **예외 필요**. 대량 구조화 상품 지식은 건별 큐레이션·시뮬레이션이 무의미(물량·갱신 주기). 권고: **product 그룹은 Board 경유 대상에서 제외** 명시 |
| C5 | gdrive/notion **동기화**: KB 직행(designated 게이트로 제외만 가능) | Board 경유 | **결정 필요**. 권고: P1은 현행 유지(이미 '지정 소스' 게이트 존재), P2에서 "동기화 → Board 미러 + 채택 규칙"을 별도 검토 — 동시 개편은 과대 범위 |
| C6 | `kb_categories` = 그룹 × **1계층** | Board는 1차/2차 **2계층** | **충돌 아님 — 축 분리로 회피**. Board는 자체 2계층 분류(board 전용)를 갖고, **채택 시 KB 카테고리로 매핑**(기본: 2차 카테고리명 → KB 카테고리, 편집 가능). KB 스키마 무변경 |
| C7 | 시뮬레이션 기반 없음? | 답변 생성 + 정확성 수치 | **기반 이미 존재 — 조립 문제**. ① `/knowledge/ask`가 답변+confidence+인용별 유사도 반환 ② **골든셋 회귀 인프라**(ai-coach: GoldenQuestion/GoldenRun — 등록 질문 일괄 실행·채점)가 이미 있음. "후보 문서를 임시 포함한 ask + 골든셋 실행"으로 요구 충족 가능. 단, **'정확성'의 자동 절대 측정은 불가** — 수치는 confidence·후보 인용 유사도·골든셋 통과율이라는 *판단 보조 지표*이고 최종 판단은 운영자(요구 문면과 일치) |
| C8 | 인제스트 파일 15MB·4종(분석용) | 50MB·9종(zip/rar/이미지 포함) | **축 분리로 해소**. Board 첨부는 "자료 보관"(50MB·9종, zip/rar은 보관만·분석 없음), AI 분석 대상은 기존 4종 15MB 유지. 이미지(png/jpg/webp)는 본문 삽입용 |
| C9 | 문서 편집권: KB-Document 편집 화면 존재 | 원본은 Board | **동기화 규칙 필요**. 권고: 채택 문서는 `BRD-{id}` 키로 역링크, Board 개정 시 KB에 "개정 미반영" 뱃지 + [재채택] 버튼. KB측 직접 편집은 허용하되 "Board 원본과 분기됨" 경고(강제 잠금은 기존 수정 흐름 7종과 충돌) |

**결론: 근본 충돌은 없음.** 이 요구는 이번 주에 만든 조각들(인제스트 검수 게이트,
그룹/카테고리 축, kb_files, 골든셋, ask 패널)을 **한 층 위의 큐레이션 계층으로 묶는
설계**이며, 대부분 "직행 경로를 어디까지 Board 경유로 강제하나"의 정책 결정 문제다.

## 3. 최선안 (권고 아키텍처)

```
                 ┌────────────── Smart Knowledge Board (테넌트당 1개 자동) ──────────────┐
 수기 작성 ─────▶│ board_documents: 그룹·1차/2차분류·제목·작성팀(job_label)·태그        │
 파일 업로드 ───▶│  본문(MD, 리치에디터)·리비전 히스토리·첨부(50MB·9종)·GDrive 링크      │
 (AI 분석 초안) │  [[위키링크]]·백링크 · 코멘트 · @멘션                                  │
 FAQ/Q&A 임포트▶│  상태: draft → published → (promoted | rejected)                       │
 YouTube ──────▶└──────────────┬────────────────────────────────────────────────────────┘
                               │  [시뮬레이션] 후보 문서 가상 포함 ask
                               │   → 답변 미리보기 + confidence + 후보 인용 유사도
                               │   → (선택) 골든셋 실행 통과율
                               ▼  운영자 판단
                        [KB-Document 채택(promote)]
                external_key=BRD-{id}, 카테고리 매핑, 기존 임베딩 파이프라인
                 ── 예외: product 그룹(카탈로그·상품CSV)은 종전대로 직행 ──
```

핵심 재사용: 인제스트 파이프라인(승인 타깃만 Board로), bulk import 파서(FAQ/Q&A
임포트), kb_files(첨부 확장), 골든셋(정확성 수치), ask(시뮬레이션), 리비전 패턴
(kb_document_revisions 동형), job_labels(작성팀), 알림 시스템(멘션 P2).

## 4. 단계 제안 (규모: 이번 주 5종 합계 이상 — 분할 필수)

| 단계 | 범위 | 비고 |
|---|---|---|
| **B1** Board 코어 | 테이블 4종(documents/revisions/attachments/tags)+자동 프로비저닝(기존 테넌트 백필 포함), 2계층 분류, MD+리치 에디터, 히스토리, 첨부 50MB·9종, GDrive 링크 필드, 목록/필터 콘솔 | 스키마 신설(SQL 선적용), `kb_board_posts` 드랍 동반 |
| **B2** 채택+시뮬레이션 | promote(BRD-키·카테고리 매핑·재채택), 시뮬레이션 패널(후보 포함 ask + confidence/유사도, 골든셋 실행 연동), KB 목록 '직접 등록/채택' 뱃지, 인제스트 승인 타깃 Board 전환(C2) | 요구의 핵심 가치 |
| **B3** 협업 | 코멘트, @멘션(+알림), [[위키링크]]+백링크 패널, Add KB-Document 동선 개편(C3) | |
| **B4** 임포트 | 외부 FAQ/Q&A 임포트(CSV/일괄등록 파서 재사용, 범용 게시판 HTML은 범위 정의 후), YouTube/파일 인제스트와 Board 완전 통합 | |
| 보류 | 그래프 뷰, 실시간 공동편집, zip/rar 내부 분석, 동기화(gdrive/notion) Board 경유(C5-P2), 정확성 자동 채점 | 과대 범위 방지 |

## 5. 결정 요청 (PLN 진행 전)

- **D-1 (C3)**: KB 직행 경로 = 유지+뱃지 구분(권고) vs Board 경유 강제.
- **D-2 (C5)**: gdrive/notion 동기화 = P1 현행 유지(권고) vs 즉시 Board 경유.
- **D-3 (C7)**: 정확성 수치 구성 = confidence+후보 인용 유사도(B2) + 골든셋 통과율(B2 포함 권고 — 인프라 기존재).
- **D-4 (C4)**: product 그룹 직행 예외 확정.
- **D-5**: 리치 에디터 선택 — MD 원문 저장 + 위지위그는 MD 호환 에디터(예: 툴바형 MD 에디터) 권고. 완전 리치(HTML 저장)는 옵시디언 기능·임베딩 텍스트 품질과 상충.
- **D-6**: 단계 승인 — B1→B2→B3→B4 순, 각 단계 PLN 별도.
