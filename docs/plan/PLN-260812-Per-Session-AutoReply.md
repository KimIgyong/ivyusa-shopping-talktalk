# PLN-260812-Per-Session-AutoReply

세션별 자동응답 + 채널 기본값 표기 + 인입 결함 2건 작업계획서.

- 근거: `REQ-260812-Per-Session-AutoReply`
- **승인 필요** — 승인 전 구현 착수 금지(CLAUDE.md §7)
- 규모: PR 1건, 스키마 변경 1건

## 0. 제안 결정

| ID | 제안 | 이유 |
|---|---|---|
| D-1 | 세션 전환 UI = **대화 헤더** | 대화를 보면서 판단할 일이다. 목록에는 상태 뱃지만 |
| D-2 | 켠 직후 **소급 응답 없음** | 30분 전 질문에 지금 답하는 건 안 하느니만 못하다. 대신 "다음 메시지부터"를 화면에 쓴다 |
| D-3 | **3상태**(`기본값 따름`/`켬`/`끔`) | 채널 기본값을 바꿨을 때 따라오게 하려면 "따름"이 필요하다. 2상태면 모든 세션이 즉시 고정된다 |

## 1. 스키마 (`sql/migration_session_auto_reply.sql`)

```sql
-- 세션별 자동응답 의사. inherit = 채널 기본값을 따른다.
ALTER TABLE sessions ADD COLUMN auto_reply_mode VARCHAR(8) NOT NULL DEFAULT 'inherit' AFTER alias;
```
롤백: `ALTER TABLE sessions DROP COLUMN auto_reply_mode;`

## 2. 백엔드

**S1. 판정 한 곳으로 모으기** (`domain/messenger`)
```ts
/** 상담원 점유 > 세션 설정 > 채널 기본값. */
export function resolveAutoReply(channelAutoReply: boolean, sessionMode: string): boolean {
  if (sessionMode === 'on') return true;
  if (sessionMode === 'off') return false;
  return channelAutoReply;
}
```
- `messenger-ingest.service.ts`가 이 함수로 판단(현재 `channel.autoReply === 1` 직접 비교를 대체)

**S2. B-1 이관 중복 제거**
- 자동응답 OFF 경로에서 **이미 이관된 대화(`escalated === 1`)면 `escalate()`를 호출하지 않는다.**
  지금은 메시지마다 호출돼 같은 대화로 상담원 알림이 반복 발생한다(인입 400건 / 대화 37건).

**S3. B-2 언어 폴백**
- 채널 세션 생성 시 `플랫폼 locale 힌트 → 테넌트 기본(타임존) → EN`.
  `SessionService`의 기존 타임존 매핑을 재사용한다(중복 구현 금지).
- 이미 만들어진 EN 세션은 건드리지 않는다(과거 발송 문구를 소급 수정할 방법은 없고, 다음 세션부터 정상).

**S4. 세션 설정 API** (`domain/agent`)
- `PATCH /agent/conversations/:id/auto-reply` — body `{ mode: 'inherit'|'on'|'off' }`,
  `@RequireCapability(CONVERSATION_HANDLE)`, 대화→세션 해석(테넌트 스코프), 세션 캐시 무효화, 감사 기록(값 포함)
- 목록/상세 응답에 `autoReplyMode`(세션 값)와 `autoReplyEffective`(실제 적용 결과) 동봉
  - `effective`까지 주는 이유: `inherit`만 보여주면 상담원이 지금 AI가 답하는지 알 수 없다.
    채널 기본값은 세션 행에 없으므로 서버가 합쳐서 내려준다(목록은 채널 1회 조회로 배치).

## 3. 콘솔

**S5. 대화 헤더 전환 + 상태 뱃지**
- 헤더에 3상태 셀렉트(`기본값 따름 (현재 켬/끔)` / `켬` / `끔`) + `AI 응답 중` / `상담원 응대` 뱃지
- 목록 행에는 **뱃지만**(전환은 헤더에서) — 행은 이미 별칭·채널·상태로 붐빈다
- 변경 시 토스트, 목록·대화 쿼리 무효화

**S6. 설정 카드 문구**
- 채널 카드/모달의 자동응답 옆에 **"새로 수신되는 메시지부터 적용됩니다. 대화별로 따로 켜고 끌 수 있습니다."**
  — 이번 제보의 절반은 이 문장이 없어서 생겼다.

## 5. 사이드 임팩트

| 영역 | 영향 | 판단 |
|---|---|---|
| 위젯 대화 | `auto_reply_mode` 기본 `inherit`, 위젯에는 채널 기본값 개념이 없어 **동작 불변** | 무영향 |
| 기존 채널 | 채널 토글 의미 그대로(기본값), 세션 override만 추가 | 하위호환 |
| 상담원 알림 | B-1 수정으로 **감소**(중복 제거) | 개선 |
| 언어 | B-2 수정으로 신규 채널 세션이 테넌트 기본 언어 사용 | 개선 |
| 목록 성능 | 채널 조회 1회 추가(페이지당) | 무시 가능 |

## 6. 테스트 / 배포

- **단위**: `resolveAutoReply` 6종(on/off/inherit × 채널 on/off), 상담원 점유 시 무조건 침묵,
  이관 중복 방지(이미 escalated면 재호출 없음), 언어 폴백 3종(힌트/테넌트/EN),
  API의 잘못된 mode 400·타 테넌트 404·캐시 무효화
- **통합**: 채널 OFF + 세션 ON → AI 응답 / 채널 ON + 세션 OFF → 침묵+이관 1회
- **스테이징**: 릴레이 카카오 대화 하나를 세션 ON으로 두고 실제 인입 → AI 응답 확인
  (⚠️ 최근 인입이 06:39에 멈춰 있어 **실메시지 유입이 있어야 검증 가능**)
- **Migration**: `sql/migration_session_auto_reply.sql`을 **코드 배포 전** 스테이징에 선적용
