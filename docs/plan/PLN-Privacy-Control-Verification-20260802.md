## 1. 작업 원칙

- 확인 결과가 없는 항목은 **충족으로 추정하지 않고 미확인**으로 기록한다.
- 코드 구현만으로 계약·백업·운영 절차가 충족됐다고 판단하지 않는다.
- 개인정보 원문, 비밀값, 접근 토큰, 계약 전문을 저장소나 점검 결과에 기록하지 않는다. 증빙은 문서 식별자, 스크린샷 보관 위치, 실행 시각, 승인자만 남긴다.
- 실제 운영 데이터 조회는 최소 권한의 승인된 담당자가 수행하며, 결과에는 집계값·마스킹값만 남긴다.

## 2. 역할 및 증빙 형식

| 역할 | 책임 |

| 서비스 운영 담당자 | 권한 재검토, 보존 작업 기록, 사고 대응 훈련, opt-out 처리 기록 |

## 3. 확인 작업 목록

### 3.1 목적 및 고지

| ID | 확인 내용 | 확인 방법 | 필수 증빙 | 완료 기준 |
|---|---|---|---|---|
| PCV-01 | 최소 수집과 목적 제한 | API DTO, DB 엔티티, Shopify/AI/알림 데이터 흐름을 대조 | 데이터 인벤토리 초안, 필드별 목적·법적 근거 | 모든 수집·전송 필드가 목적과 수신자에 연결됨 |
| PCV-02 | 고객 고지의 완전성 | 위젯 배너/설정 화면과 실제 개인정보처리방침을 검토 | 공개 URL, 버전, en/es/ko 화면 캡처 | 목적·항목·보유기간·처리자·국외이전·권리 행사 방법이 확인됨 |
| PCV-03 | 목적 외 처리 차단 | `pending/granted/declined` 세션별 채팅·AI·상담원·알림 API를 테스트 | 요청/응답 마스킹 기록, 자동화 테스트 결과 | 법적 근거가 동의인 처리는 `GRANTED` 외 상태에서 저장·외부 전송되지 않음 |

## 4. 실행 순서와 의존성

1. **사전 준비**: 개인정보 책임자가 적용 법역과 활성 처리자 목록을 확정하고, 증빙 대장 접근권한을 부여한다.
2. **데이터 흐름 확인**: PCV-01, 02, 04, 07, 08을 먼저 완료한다. 이후 동의·opt-out·암호화 점검의 기준이 된다.
3. **기술 검증**: PCV-03, 05, 06, 09~15를 비운영 또는 승인된 staging 환경에서 마스킹된 데이터로 수행한다.
4. **운영 검증**: PCV-10, 11, 12, 16의 정책·훈련·계약·백업 증빙을 책임자가 승인한다.
5. **판정 회의**: 미확인/부분 충족/미충족 항목은 P0/P1 개선 티켓으로 분해하고 담당자·기한·재검증 방법을 지정한다.

## 5. 사이드 영향 및 통제

| 영향 영역 | 위험 | 통제 |
|---|---|---|
| 운영 DB/Shopify | 점검 중 PII 노출 또는 변경 | 읽기 전용·승인 계정 사용, 샘플은 마스킹, 쓰기 테스트는 staging 전용 |
| 고객 알림 | opt-out 시험 중 실제 발송 | mock channel 또는 격리 테스트 고객을 사용하고 외부 발송을 사전 차단 |
| 백업 복구 | 운영 데이터 덮어쓰기 | 복구는 격리된 DB로만 수행하고 대상·종료 후 파기를 기록 |
| 계약 문서 | 계약/개인정보의 과다 공유 | 보관소 링크·문서 ID만 기록하고 전문·비밀값은 저장소에 넣지 않음 |
| 점검 결과 | 미확인 항목의 오판 | 증빙 부재는 미확인으로 판정하고 책임자 승인 전 “충족” 표기 금지 |

## 6. 승인 요청

이 계획은 확인 작업만 정의하며 제품 동작을 변경하지 않는다. 승인 후 PCV-01부터 증빙 대장을 작성하고, 발견된 코드·UI·인프라 변경은 영향도별 후속 PLN을 별도로 제출한다.
