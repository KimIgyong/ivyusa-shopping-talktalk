# PLN-260819-Widget-Hide-On-Login

로그인 화면에서 챗위젯을 mount 하지 않는다.

- 작성일: 2026-08-19
- 선행: `docs/analysis/REQ-260819-Widget-Hide-On-Login.md`
- 변경 파일: `apps/widget/public/embed.js` (그리고 테스트 1개) — **그게 전부다**

## 1. 접근

판정을 `embed.js` **최상단**에 둔다. 이유는 REQ §3에 있다 — reopen 플래그를 읽기 전에
빠져나가야 로그인 복귀가 살아나고, iframe을 만들기 전에 빠져나가야 게스트 세션이 안 생긴다.

서버에 묻지 않는다(REQ C-1). 테넌트 설정은 위젯 iframe 뒤에 있어서, 물어보는 동안 런처가
먼저 떠버린다. 로그인 화면에 0.3초 떴다 사라지는 런처는 안 뜨느니만 못하다.

## 3. 변경 상세

### P-1. 우리가 연 Cafe24 로그인 팝업에서는 mount 하지 않는다

```js
if (window.name === 'ivy_cafe24_auth') return;
```

기존 가드는 `ivy_auth_popup`(Shopify)만 검사한다(REQ §2-2). Shopify 팝업은 "끝났다"를
알리고 스스로 닫혀야 하지만, Cafe24 팝업은 **아직 진행 중**이라 닫으면 안 된다 —
그래서 같은 블록에 합치지 않고 별도 조기 반환으로 둔다.

### P-2. 로그인·회원가입·계정찾기 화면에서는 mount 하지 않는다

경로 **접두사** 목록으로 판정한다. 정규식이 아니라 접두사인 이유는 이 값이 몰마다
덮어써질 수 있는 설정이기 때문이다(P-3) — 설정에 정규식을 받으면 오타가 조용한 오작동이 된다.

| 플랫폼 | 기본 목록 |
|---|---|
| Cafe24 | `/member/login` `/member/join` `/member/agreement` `/member/id/` `/member/passwd/` |
| 그 외(Shopify 등) | `/account/login` `/account/register` `/account/reset` `/account/activate` `/challenge` |

⚠️ 접두사가 **일부러 좁다.** `/member/mall_agreement`(이용약관)와 `/member/privacy`
(개인정보처리방침)는 `/member/agreement`·`/member/`에 걸리지 않는다. 약관 읽다가 문의하는
사람에게서 위젯을 뺏지 않기 위해서다(REQ S-2). 같은 이유로 `/member/modify`
(회원정보수정, 로그인 상태)도 목록에 없다.

**Cafe24 판별**은 호스트가 `*.cafe24.com`이거나 `cfg.loginPath`가 `/member/`로 시작할 때다.
후자는 **커스텀 도메인 몰**을 위한 것이고, 새 설정을 요구하지 않는다 — 콘솔 설치 가이드가
이미 내주는 Cafe24 스니펫에 `loginPath: "/member/login.html"`이 들어 있다.

### P-3. 오버라이드

```js
window.IVY_WIDGET_CONFIG = { …, hideOnPaths: ["/signin"] }   // 목록 교체
window.IVY_WIDGET_CONFIG = { …, hideOnPaths: [] }            // 기능 끄기
```

스킨을 고쳐 로그인 경로가 다른 몰, 혹은 이 동작을 원치 않는 몰을 위한 탈출구다(REQ C-2).
콘솔 UI는 **추가하지 않는다** — 스니펫에 키 하나 더 붙이는 일이고, 이걸 쓸 몰은 이미
스니펫을 손대고 있는 몰이다. 설정 화면을 늘릴 만한 빈도가 아니다.

## 4. 부수 영향

| 영역 | 영향 |
|---|---|
| 배포 | `embed.js`는 우리 origin에서 서빙 → **위젯 재배포만으로 전 테넌트 적용.** 몰 스킨 무수정 |
| 다른 테넌트 | Shopify 테넌트도 `/account/login`에서 위젯이 사라진다. 같은 플래그 소실이 거기서도 일어나고 있었다(REQ S-3) |
| DB / API | 없음. 스키마 변경 없음, 마이그레이션 없음 |
| i18n | 없음. 새 문구 없음 |
| 위젯 번들 | 없음. `apps/widget/src`는 건드리지 않는다 |
| 로그인 성공률 | 개선 방향. 로그인 폼을 가리던 요소가 사라지고 복귀 동작이 살아난다 |

**되돌리기**: 이 커밋 revert 후 위젯 재배포. 상태가 남지 않는다.

## 5. 테스트

`apps/widget`에는 지금 테스트 하네스가 **없다**. 여기서 jsdom을 새로 들이는 대신
Node 내장 `node --test` + 최소 DOM 스텁으로 **실제 배포되는 `embed.js` 파일 자체**를
실행해 검증한다. 규칙을 테스트용으로 복제하지 않는다 — 복제된 규칙은 FIX-260819 §G-6에서
이미 한 번 사고를 냈다.

| # | 케이스 | 확인 |
|---|---|---|
| T-1 | Cafe24 로그인 경로 | iframe 미생성 |
| T-2 | Cafe24 로그인 경로에서 **reopen 플래그가 남아 있다** | 복귀 동작 보전 — 이 요구사항의 핵심 |
| T-3 | 상품 페이지 | 정상 mount (회귀 없음) |
| T-4 | `/member/mall_agreement`·`/member/privacy` | 정상 mount (일부러 안 숨김) |
| T-5 | `window.name = 'ivy_cafe24_auth'` | iframe 미생성 |
| T-6 | Shopify `/account/login` | iframe 미생성 |
| T-7 | 커스텀 도메인 + `loginPath: /member/login.html` | Cafe24 규칙 적용 |
| T-8 | `hideOnPaths: []` | 어디서도 안 숨김 (탈출구 동작) |

전체 `npm run test` / `typecheck` / `build` 회귀 확인.

## 6. 이 계획이 하지 않는 것

- 로그인 **후** 숨기지 않는다(REQ S-4). 요청은 로그인 화면에 대한 것이다
- Cafe24 popup 모드 실동작 검증은 **tenant 3 재연결 후**에만 가능하다
  (`FIX-260819` §8 — 자격증명이 아직 `annehearts`를 가리킨다). T-5는 단위 테스트로 덮는다
