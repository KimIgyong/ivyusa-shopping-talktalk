`https://shoptalk.amoeba.site/live-chat`

3. **대화창에 대화 시간 표시**

## 2. AS-IS (코드·데이터 확인)

### 2.1 진행중 대화가 목록에 없다 — 설계상 제외

`AgentService.listSessions`는 `status IN ('waiting','agent')`만 조회한다. 즉 **상담사 개입이 필요한
대기열**이지 "대화 목록"이 아니다. AI가 응대 중인 `ai_active` 대화는 **정의상 한 건도 안 나온다**.

스테이징 실측(2026-08-06 기준 최신 8건):

| 대화 | 상태 | 고객 | 목록 노출 |
|---|---|---|---|
| **94** (15:58, 최신) | `ai_active` | id 4 (**이름 있음**) | ❌ 안 나옴 |
| 93 (13:26) | `waiting` | id 9 (이름 없음/이메일만) | ✅ |
| 92 (13:18) | `waiting` | id 9 | ✅ |
| 91 (11:54) | `waiting` | 없음 | ✅ |
| 87~90 (09:3x) | `ai_active` | 없음 | ❌ |

→ 사용자가 "가장 최근 대화(94)가 없다"고 본 것이 정확하다. 게다가 94는 **이름이 매핑된 로그인 고객**과의
대화라 요구 2와도 직결된다.

부가 확인: 정렬이 `id DESC`(생성 순)라 **마지막 대화 활동 순서가 아니다**. 오래 전에 열려 계속
대화 중인 스레드가 아래로 밀린다.

### 2.2 고객 이름

목록은 `customerName ?? '(Session xxxxxx)'`를 출력한다. 이름 매핑은 세션→고객→`customers.name`
경로로 이미 동작하지만(94번은 이름 보유), **이름이 없는 고객**(이메일만 남긴 오프아워 문의자 = 93번)은
여전히 `Session 93…`만 보인다. 세션 라벨과 고객명이 **함께** 보이지 않는 점도 요구와 다르다.

### 2.3 대화 시간

- 목록 행: 개설/마지막답변 시간은 **이미 표시**(2026-08-04 반영).
- **대화창(스레드) 내부: 메시지별 시간 표시가 전혀 없다**(발신자 라벨 + 본문만 렌더).
  → 요구 3은 스레드 내부 메시지 시각을 뜻하는 것으로 해석한다.

## 4. 제약·고려

- 이름·이메일은 **암호화 저장(PRV-M6)** — 목록 조회는 이미 복호화 경로를 쓰므로 추가 비용은 이메일 1필드뿐.
- 이메일 노출 범위: 상담사 콘솔은 이미 고객 패널에서 이메일 전체를 보므로 목록 표기도 동일 수준.
- `ai_active`를 포함하면 목록 건수가 크게 늘 수 있다(스테이징에도 다수) → 기본 필터·정렬·페이지 크기 재검토 필요.
- `ended` 대화는 기본 제외(종료된 상담까지 섞이면 대기열 성격이 사라짐).
