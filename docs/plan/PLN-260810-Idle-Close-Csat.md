## 0. 상태 흐름

```
                     ┌───────────────── 고객이 답함 ─────────────────┐
                     │                                              │
 agent / waiting ──30분 무응답──▶ [확인 질문 발송]──1분 무응답──▶ ended
        │                         idle_prompt_at 기록                 │
        │                                                             ▼
        └── reply_channel='email' 이면 제외 ──────────▶      "만족하셨나요?" + ☆☆☆☆☆
                                                                      │
                                                        클릭 → csat_rating 저장
                                                        닫기 → 아무것도 저장 안 함
```

**두 개의 타이머가 아니라 두 개의 상태**입니다. 확인 질문을 보낸 시각(`idle_prompt_at`)만 기록해 두면, 스케줄러는 매 틱마다 "30분 지난 대화"와 "확인 질문 후 1분 지난 대화" 두 집합을 조회하면 됩니다. 프로세스가 죽어도 상태는 DB에 있으므로 재시작 후 이어서 동작합니다.

## 1. 단계별 계획

### P1 — 스키마 + 방치 감지·자동 종료

| 항목 | 설계 |
|---|---|
| 마이그레이션 | `conversations`에 3열 추가 — `idle_prompt_at datetime NULL`, `csat_rating tinyint NULL`, `csat_rated_at datetime NULL` (+ `idx_conv_idle (status, idle_prompt_at)`) |
| 스케줄러 | `IdleConversationService` — `onModuleInit` + `setInterval(30초)` + `unref`, 간격은 `IDLE_SWEEP_INTERVAL_SEC`(0=비활성). 기존 sync 스케줄러와 동일 패턴 |
| 임계값 | `IDLE_PROMPT_AFTER_MIN=30` · `IDLE_CLOSE_AFTER_SEC=60` — **요구값을 기본으로, 운영 중 조정 가능** |
| 대상 | `status ∈ {agent, waiting}` **AND** `reply_channel IS NULL` **AND** `idle_prompt_at IS NULL` **AND** 마지막 메시지가 30분 경과 |
| 확인 질문 | 시스템 메시지 1건 + `idle_prompt_at = NOW()`. **1회만**(컬럼이 곧 멱등 장치) |
| 자동 종료 | `idle_prompt_at`이 60초 지났고 그 이후 고객 메시지가 없으면 → `ended` + `endedAt`, 배정 released, 이슈 종결 훅 호출 |
| 타이머 해제 | 고객이 답하면 `idle_prompt_at = NULL` (`chat.service`의 고객 메시지 처리 경로에서 초기화) |
| 소급(D7) | 마지막 메시지가 **7일 이내**면 확인 질문, 그보다 오래된 방치는 **질문 없이 조용히 종료** |
| 알림 | 확인 질문은 **푸시 미발송**(D8) |
| 감사 | `chat.idle_prompted` · `chat.idle_closed` (actorType `system`) |

문구(EN/ES/KO 기본 제공, `handoffConfig`처럼 테넌트 편집 가능):
> KO 확인: "혹시 더 도와드릴 일이 있으실까요? 없으시면 잠시 후 상담을 마칠게요."
> KO 종료: "상담에 만족하셨나요? 별점으로 알려주시면 큰 도움이 됩니다."

### P2 — 만족도 제출 API

| 항목 | 설계 |
|---|---|
| API | `POST /chat/csat` · `@Public()` — `{ session_token, conversation_id, rating (1..5) }` |
| 인증 | 세션 토큰이 그 대화의 세션과 일치해야 함(`escalate`와 동일한 소유 검사) |
| 기한 | `endedAt` 기준 **24시간 이내**만 허용(D5), 초과 시 409 |
| 재제출 | 마지막 값으로 **갱신**(D6) |
| 집계 | 대화의 마지막 담당 상담원 기준으로 `agent_daily_stats.csat_avg` 갱신 — **이미 있으나 아무도 쓰지 않던 컬럼**을 이번에 채웁니다 |
| 동의 | 별점은 개인정보가 아니므로 동의 게이트 없음. 단 세션 소유 검사는 유지 |

### P3 — 위젯 UI

| 항목 | 설계 |
|---|---|
| 표시 조건 | `status === 'ended'` **AND** `csatRating == null` **AND** 종료 24시간 이내 |
| 동작 | 별 클릭 → 즉시 제출 → "평가해 주셔서 감사합니다"로 교체 |
| 무시 | `[닫기]` → 저장 없이 카드만 사라짐. **다시 열어도 재표시하지 않음**(localStorage에 대화 id 기록) |
| 접근성 | 별은 라디오 그룹(키보드 1~5, `aria-label`) |
| 언어 | 세션 언어 |

## 3. 영향 범위

| 영역 | 영향 | 조치 |
|---|---|---|
| **오프아워 이메일** | 회신 약속된 대화를 종료하면 약속이 사라짐 | `reply_channel='email'` **제외**(D3), 테스트로 고정 |
| **이슈 워크플로우** | 자동 종료도 `onConversationEnded` 훅을 타야 함 | 고객 종료 경로와 동일하게 호출 |
| **재대화** | 종료 후 고객이 말하면 새 대화 생성 | 기존 `getOrCreateConversation` 그대로 — 별도 작업 없음 |
| **상담원 콘솔 목록** | 방치 대화가 자동으로 사라짐 | 의도된 변화. 작업로그에 `chat.idle_closed`로 남음 |
| **통계** | `csat_avg`가 처음으로 값을 가짐 | 매퍼·화면은 이미 준비돼 있음 |
| **위젯 번들** | 별점 컴포넌트 추가 | 소규모 |
| **retention 퍼지** | 종료 대화가 늘어남 | 보존 정책 그대로(365일) |

## 5. 검증 계획

| # | 항목 | 기준 |
|---|---|---|
| V1 | 확인 질문 | 30분 경과 대화에 시스템 메시지 1건 + `idle_prompt_at` 기록, **두 번 보내지 않음** |
| V2 | 고객 응답 시 해제 | 1분 내 답하면 종료되지 않고 `idle_prompt_at`이 비워짐 |

| V5 | 소급 | 7일 넘은 방치는 질문 없이 종료, 7일 이내는 질문 후 종료 |
| V6 | 별점 저장 | 위젯에서 4점 클릭 → `csat_rating=4`, 감사 문구로 교체 |

| V9 | 통계 | `agent_daily_stats.csat_avg`에 반영, 콘솔에서 '—'가 아닌 값 |
| V10 | 기존 7건 | 스케줄러 1회 순회 후 전부 정리, 답 없던 고객 메시지 10건 해소 |

## 6. 승인 요청

D1~D8을 위 전제대로 진행할지 확인 부탁드립니다. 특히 **요구에 없어서 제가 정한 값** 두 가지입니다.

1. **D1 방치 판정 = 30분** — 요구에는 "상담원 응답 없으면"만 있었습니다. 15분은 응대 중 오발동 위험, 60분은 방치가 너무 오래 갑니다
2. **D7 소급 범위 = 최근 7일만 확인 질문** — 40일 전 대화(현재 최고령 방치)에 갑자기 "더 도와드릴까요?"라고 말을 거는 건 이상하므로, 오래된 건 조용히 종료합니다
