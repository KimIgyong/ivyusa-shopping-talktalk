# REQ-260812-Per-Session-AutoReply

채널 자동응답(전체 설정) + **세션별 자동응답 여부** 요구사항 분석, 그리고 "릴레이 자동응답 on/off가 동작하지 않는다" 제보의 원인 규명.

- 작성일: 2026-08-12
- 원 요구: "설정에서 btbz messenger relay - ai auto-reply on/off 기능동작안함 /
  전체 설정은 여기서 처리하고 각 세션별로 자동응답 진행여부는 세션에서 설정해야 함"

## 1. 제보 원인 규명 (스테이징 실데이터)

**토글 자체는 정상 저장됩니다.** DB는 `messenger_channels(id=1, tenant 3) auto_reply=1, active=1`입니다.

| 관측 | 값 |
|---|---|
| 채널 자동응답을 켠 시각 (`updated_at`) | **2026-08-12 06:56:19** |
| 채널 스레드의 마지막 인입 (`last_inbound_at`) | **2026-08-12 06:39:34** |
| 채널 대화의 메시지 구성 | user 400 · system 91 · agent 4 · **ai 0** |
| system 91의 내역 | 동의 안내 37 · 자동종료/CSAT 안내 52 · 이관 1 · 핸드백 1 |

→ **인입 400건은 전부 자동응답이 꺼져 있던 동안 들어왔고, 켠 뒤로는 새 메시지가 한 건도 오지 않았습니다.**
AI가 답할 기회 자체가 없었습니다. 즉 "저장은 되는데 아무 일도 일어나지 않는다"는 관측은 사실이지만,
원인은 토글 고장이 아니라 **켜기 전에 쌓인 대화에는 소급 적용되지 않는데 화면이 그 사실을 말해주지 않는 것**입니다.

### 1.1 같이 드러난 실제 결함 2건

| ID | 결함 | 근거 |
|---|---|---|
| **B-1** | 자동응답 OFF 경로가 **메시지마다 이관을 재호출**한다 — 이미 이관된 대화에도 매번 상담원 알림이 나간다 | `messenger-ingest.service.ts` — `escalate()`를 무조건 호출. 인입 400건 대비 대화 37건 |
| **B-2** | 채널 세션이 **테넌트 기본 언어를 무시**하고 항상 EN이 된다 | 카카오톡 한국어 대화방인데 `sessions.language`가 37건 전부 `EN` → 동의 안내·이관 안내가 영어로 발송됨. 릴레이는 locale 힌트를 주지 않는데 `resolveLanguage`가 테넌트 기본(타임존 기반) 대신 EN으로 떨어짐 |

## 2. AS-IS

- 자동응답 스위치는 **채널 1개 = 값 1개**(`messenger_channels.auto_reply`)뿐이다.
- 인입 파이프라인은 `channel.autoReply === 1 && !humanOwnsThread`이면 AI 응답, 아니면 저장 후 이관.
- **대화(세션) 단위로 끄고 켤 방법이 없다.** 진상 고객 한 명 때문에 채널 전체 자동응답을 끄거나,
  반대로 조용한 채널에서 특정 대화만 AI에 맡기는 선택이 불가능하다.
- 콘솔 어디에도 "이 대화는 지금 AI가 답하는 중인지"가 표시되지 않는다.

## 5. 정책

- 우선순위: **상담원 점유 > 세션 설정 > 채널 기본값**. 상담원이 잡은 대화에 AI가 끼어들지 않는 규칙은 유지한다.
- 세션 설정은 대화가 아니라 **세션**에 저장한다(별칭과 동일 — 같은 사람이 여는 다음 대화에도 유지).
- 비공식 채널(릴레이)의 채널 기본값은 계속 OFF로 둔다. 개별 대화만 명시적으로 켜는 운용을 기대한다.
- 권한은 대화 처리 권한(`CONVERSATION_HANDLE`)과 동일. 감사 기록 남김(값 포함 — PII 아님).
