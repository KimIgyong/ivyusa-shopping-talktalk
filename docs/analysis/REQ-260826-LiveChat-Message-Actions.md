# REQ-260826 라이브챗 — 대화방 핀 고정 · 고객 메시지 단위 액션 4종 (번역/지식조회/답글/이슈)

- 작성일: 2026-08-26
- 요청 유형: [요구사항] — /live-chat 상담원 작업 도구 강화 (핀 1 + 메시지 액션 4)
- 참조: 아메바 로비채팅 번역(실구현은 ambManagement `amoeba-talk` 모듈 — 호버 액션열의 번역 버튼·팝오버·인라인 서브버블, REQ-260302-AmoebaTalk동시번역)

## 0. 요구사항 원문

대화방 리스트에서, AI 자동응답이 아닌 상태의 고객 대화에:
- **pin** — 중요 대화라 상단에 핀 고정, **3개까지** 지정 가능
- **번역 콘솔 버튼** (아메바 로비채팅 참조)
- **지식참조답변 버튼** — 우측 Knowledge lookup에 입력
- **답글달기 버튼**
- **이슈등록 버튼** — 전체 대화가 아니라 **특정 대화(메시지)를 이슈로 등록하는 모달** + **메모 추가** 기능

## 1. 요구 해석·구체화 (확정 제안)

| # | 기능 | 단위 | 노출 위치·조건 |
|---|---|---|---|
| R1 | 핀 고정 | **대화방(목록 행)** | 목록 행 호버 시 핀 토글 — 항상 사용 가능(자동응답 여부 무관, 리스트 관리 기능이므로) |
| R2~R5 | 번역·지식조회·답글·이슈 | **고객 메시지(버블)** | 트랜스크립트에서 `sender=user` 버블 호버 시 액션 4종 — **AI 자동응답 중이 아닌 대화에서만**(아래 판정식) |

**"AI 자동응답이 아닌 상태" 판정**: `!(status === 'ai_active' && autoReplyEffective)` — 즉 상담 대기(waiting)·상담원 응대(agent)·종료(ended), 또는 세션 자동응답 OFF인 대화. AI가 실시간으로 자동 응답 중인 대화에서는 상담원이 끼어들 일이 없으므로 미노출(요구 조건 그대로).

## 2. AS-IS

- **핀**: `conversations`에 핀 관련 컬럼 없음. 목록 정렬은 "최신 메시지 우선"(상관 서브쿼리 MAX(message id)) 고정 — 중요 대화가 새 메시지에 밀려 내려감.
- **트랜스크립트 버블**: 메시지별 액션/호버 어포던스 전무. 우측 Knowledge lookup 카드에는 "마지막 고객 메시지" 버튼 1개만(특정 과거 메시지를 넣을 방법 없음, `setKbQuestion` 상태 기주입 배선은 존재).
- **번역**: 콘솔에 메시지 번역 기능 없음. 온디맨드 LLM 번역 선례는 브리핑 번역(PLN-260824 R3 — ASSIST 함수, 언어 검증, 저장) 기구현.
- **답글**: `messages`에 reply_to/스레딩 없음. 컴포저는 단일 draft 문자열.
- **이슈**: 대화 단위 수동 등록(PLN-260825 R8-③, `createManual`)만 존재 — **메시지 특정 불가, 메모 입력 불가**. 단 `issue_events.note`(text)와 `ISSUE_EVENT_TYPE.MEMO`가 기존재하고 IssuePanel 타임라인이 메모 이벤트를 렌더함. `uk_issue_conv`로 이슈는 대화당 1개.
- 다음 에러코드 블록: **E5060~**.

## 3. TO-BE

### R1. 대화방 핀 고정 (최대 3)
- `conversations.pinned_at`(datetime NULL) + `pinned_by`(bigint NULL) 컬럼 추가. NULL=핀 없음.
- **테넌트 공유 핀**(상담원 개인별 아님 — 인계·협업에서 "우리 팀의 중요 대화"가 목적). 테넌트당 활성 핀 **최대 3개** — 4번째 시도는 **E5060 거부 + "기존 핀을 해제하세요" 안내**(자동 해제는 다른 상담원의 핀을 몰래 지우는 것이라 배제).
- 목록 정렬: **핀 우선(핀끼리는 최근 핀 순) → 기존 최신 메시지 순**. 스코프 탭·채널·에이전트 필터는 그대로 적용(핀이어도 필터에 걸리면 미표시 — 정렬만 우선). 그룹 탭 제외.
- UI: 행 호버 시 핀 아이콘 토글, 핀된 행은 상단 고정 + 핀 배지. 상세 헤더에도 핀 토글.
- API: `PATCH /agent/conversations/:id/pin {pinned}` — CONVERSATION_HANDLE, 감사 기록.

### R2. 메시지 번역 (번역 콘솔 — 아메바 로비채팅 미러)
- **아메바 실구현 확인 결과**(ambManagement amoeba-talk): 버블 호버 액션열의 번역 아이콘 → 위로 열리는 팝오버(상단 모드 토글 [번역/번역 기록] + **원클릭 언어 목록**) → 원문 버블 아래 **틴트 서브버블**로 번역 표시(언어별 스택, 라벨 "{lang}(으)로 번역됨", X 닫기), 로딩 스피너 필수(LLM 1~3초), 번역은 메시지 단위 캐시.
- **채택안**: 동일 문법의 팝오버 — 언어 목록(시스템 6종, 기본 선택=콘솔 UI 언어) 원클릭 번역 → 버블 아래 인라인 서브버블(원문 유지, X 닫기, 언어별 스택). 캐시는 react-query(메시지 id+언어) — 새로고침 시 소실은 아메바와 동일한 수용 한계(대화는 흘러가는 데이터).
- **의도적 차이**: 아메바의 "번역 기록"(번역을 대화에 메시지로 게시) 모드는 **미채택** — 우리 대화 상대는 팀원이 아니라 **고객**이라 내부 번역을 고객 채팅에 게시하는 것은 부적절. 콘솔 전용 인라인만. 컴포저 동시번역(발송문 자동 병기)도 범위 밖 백로그.
- 서버: `POST /agent/messages/:id/translate {lang}` — 메시지→대화→테넌트 소유 검증, 브리핑 번역 패턴(ASSIST·언어 검증·실패 E5055) 재사용. 평문 응답이라 아메바의 JSON 펜스 파싱 함정은 해당 없음.

### R3. 지식참조답변 (Knowledge lookup 연동)
- [지식조회]: 해당 메시지 본문을 우측 Knowledge lookup 입력창에 주입 + 카드로 스크롤/포커스. 이후 흐름(조회→고객 전달/편집 후 전달)은 기존 기능 그대로. **프런트 전용**(기존 '마지막 고객 메시지' 버튼의 메시지별 일반화).

### R4. 답글달기 (인용 회신)
- [답글]: 컴포저에 **인용 블록**(원문 발췌 최대 ~80자, `> ` 프리픽스 + 줄바꿈) 프리셋 후 포커스 — 상담원이 이어서 답변 작성, 발송 메시지에 인용이 포함되어 고객도 어떤 질문에 대한 답인지 인지.
- `messages.reply_to` 스키마/스레딩 UI는 범위 밖(위젯 렌더까지 파급 — 백로그). 인용 프리픽스는 무스키마로 전 채널(위젯·메신저)에서 동일하게 동작.

### R5. 메시지 단위 이슈 등록 (+메모)
- [이슈] → 모달: **대상 메시지 발췌**(읽기 전용) + **유형 선택**(6종) + **메모 입력**(선택, ≤500자).
- 서버 `createManual` 확장 — `message_id`·`memo` 수용:
  - 대화에 이슈가 **없으면** 생성하고 CREATED 이벤트 note에 `[메시지 #id] 발췌 · 메모` 기록.
  - **이미 있으면**(uk_issue_conv 1:1 유지) 기존 이슈에 **MEMO 이벤트** 추가(동일 note 형식) — "같은 대화의 다른 발화도 이슈에 축적"이라는 실무 흐름을 제약 변경 없이 수용.
- IssuePanel 타임라인에 즉시 표시. native 게이트(E5059)·고객 무통지(기존 결정) 유지.

## 4. 사용자 플로우

1. 상담원이 중요 대화 3개를 핀 → 새 메시지가 쏟아져도 항상 목록 최상단.
2. 베트남어 고객 메시지에 [번역] → 버블 아래 한국어 번역 인라인 표시 → 문맥 파악.
3. 과거 메시지의 질문에 [지식조회] → 우측 패널에서 KB 답변 확인 → [고객에게 전달].
4. 특정 질문에 [답글] → 인용이 담긴 컴포저에서 답변 작성·발송.
5. 클레임 발화에 [이슈] → 유형 '환불' + 메모 "3회째 동일 클레임" → 이슈 생성(또는 기존 이슈에 메모 축적) → 이슈 보드에서 추적.
