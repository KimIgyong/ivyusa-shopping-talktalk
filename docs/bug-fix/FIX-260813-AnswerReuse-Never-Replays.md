# FIX-260813 — 답변 재사용이 한 번도 재생되지 않는다 (원인 규명)

- 발견: 위젯 스모크 **E5** 실측 중 (2026-08-13, 스테이징 `82639cc`)
- 대상: `apps/api/src/domain/answer-reuse/answer-reuse.service.ts` (PLN-260808)
- 상태: **원인 확정 · 수정 미적용** (수정 방향은 §4, 사용자 판단 필요)

---

## 1. 증상

답변 재사용 기능이 배포돼 있고 저장도 되는데, **재생이 한 번도 일어나지 않았다.**

```
answer_reuse 5건 — ai 1 / agent 4
전부 hit_count = 0, last_hit_at = NULL
```

콘솔 `/ai-setting` 재사용 목록이 계속 "저장된 재사용 답변이 아직 없습니다"로 보였던 것도 같은 뿌리다
(목록 API는 별개지만, 기능이 실효하지 않는다는 신호였다).

## 2. 재현

저장된 항목과 **완전히 같은 질문·같은 언어·같은 출처**로 물었는데도 재생되지 않았다.

| 시도 | 질문 | 세션 언어 | 결과 |
|---|---|---|---|
| 1 | `환불계좌 변경하는 방법` (id=2, agent, KO) | KO | 재생 없음 — 주문 조회로 분류되어 **설계상 재사용 제외**(`needsOrderData`) |
| 2 | `오늘 환율 알려줘` (id=5, agent, **EN**) | KO | 재생 없음 — 조회가 **언어별로 분리**됨 |
| 3 | **`Can you tell me more about this product?`** (id=1, ai, EN) | **EN** | **재생 없음, 8.4초 소요, `hit_count` 0 유지** |

3번이 결정적이다. 조건이 완전히 일치하는데 매칭되지 않았다.

## 3. 원인 — 저장과 조회의 임베딩 종류가 다르다

| 경로 | 코드 | 임베딩 |
|---|---|---|
| 저장 | `answer-reuse.service.ts:262` | `this.ai.embed([question], **'document'**)` |
| 조회 | `answer-reuse.service.ts:60` | `this.ai.embed([question], **'query'**)` |

Voyage는 `input_type`에 따라 **다른 벡터**를 만든다(비대칭 임베딩). 스테이징에서 실측:

```
동일 문장 'Can you tell me more about this product?'
query 벡터 · document 벡터 내적 = 0.6139
재사용 임계값 THRESHOLD = 0.92  →  통과 불가
```

즉 **완전히 같은 문장이어도 0.61밖에 안 나오므로, 0.92 임계값을 넘는 일은 구조적으로 없다.**
Qdrant 컬렉션(`reuse_questions`, 1024차원, Dot)에 벡터 5건이 정상 색인돼 있음도 확인했으므로
색인 누락이 아니라 **벡터 공간이 어긋난 문제**다.

⚠️ 비대칭 임베딩은 검색 품질을 위해 의도된 것이다. 문제는 **"질문↔질문" 유사도를 재면서 한쪽만
document로 넣은 것**이다. RAG 본체(`kb_documents`)는 문서를 document로, 질문을 query로 넣으므로
올바르다 — 재사용만 질문을 문서 취급했다.

## 4. 수정 방향 (미적용 — 판단 필요)

| 안 | 내용 | 비고 |
|---|---|---|
| **A (권장)** | 저장도 `'query'`로 임베딩 | 질문끼리 비교하므로 양쪽을 같은 종류로. **기존 5건은 재색인 필요** |
| B | 임계값을 0.6 근처로 낮춤 | ❌ **위험**. 어긋난 공간에서의 0.6은 "비슷함"을 뜻하지 않아 **엉뚱한 답을 재생**할 수 있다 |
| C | 저장·조회 모두 document | 동작은 하나 의미상 부자연스럽고 A와 차이 없음 |

**A를 권한다.** 함께 볼 것:

- **포착 임계값 0.75도 재검토 대상.** AI 답변 454건의 신뢰도는 **평균 0.619 / 0.75 이상은 21건(4.6%)**
  이다. 신뢰도 척도(= 최고 유사도, 0.5~0.95로 클램프)를 감안하면 0.75는 상위 5%만 통과시킨다.
  의도한 보수성인지, 아니면 척도를 잘못 가정한 것인지 확인이 필요하다.
- 수정 후에는 **재생이 실제로 일어나는지**(hit_count 증가)를 회귀 검증 대상으로 넣어야 한다.
  지금까지 "저장은 되는데 재생은 0"인 상태가 배포 5일간 아무에게도 보이지 않았다.

## 5. 예방 패턴

> **비대칭 임베딩(query/document)을 쓰는 저장소에서 "같은 종류끼리" 비교할 때는 양쪽 input_type이
> 같아야 한다.** 검색(질문→문서)에서 옳은 설정을 유사도 매칭(질문→질문)에 그대로 복사하면
> 조용히 실패한다 — 에러도 없고, 그냥 **아무것도 매칭되지 않을 뿐**이다.

그리고 이 결함이 5일간 드러나지 않은 이유는 **실패가 정상 동작과 구분되지 않기 때문**이다.
재사용이 안 되면 그냥 LLM이 답하고, 사용자는 아무 이상을 못 느낀다.
→ **"작동하면 빨라지는" 최적화 기능은 반드시 적중률 지표를 노출해야 한다.** hit_count가 0이라는
사실 자체가 화면 어딘가에 보였다면 5일이 걸리지 않았다.
