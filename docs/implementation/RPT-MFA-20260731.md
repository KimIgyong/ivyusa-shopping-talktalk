## 2. 구현 요약

**M1 백엔드** (`apps/api`)
- `totp.util.ts`: RFC 6238(HMAC-SHA1/30s/6자리/±1 스텝), base32 자체 구현 — **신규 의존성 0**
- `mfa.service.ts` + 엔티티 2종: 시크릿 AES-256-GCM(`crypto.util`), 복구 코드 10개 bcrypt 저장, `last_used_step` 재사용 방지, `LoginRateLimitService` scope `mfa` 재사용
- step-up: 로그인 → `{mfaRequired, mfaToken}`(5분 purpose-limited JWT) → `POST /auth/mfa/verify` → 로그인 동형 응답. 가드가 purpose 토큰의 일반 API 사용을 401 거부
- 관리자 리셋 2경로: `/users/:id/mfa-reset`(USER_INVITE), `/tenants/:uuid/users/:id/mfa-reset`(@AdminOnly)
- 에러 E1010(M3 예약→사용)/E1011/E1012, 감사 5종(ip·request_id 자동 주입)

**M2 웹** (`apps/web`)
- 공용 `MfaChallengeForm`(6자리/복구 코드 전환) — 테넌트·관리자 로그인 양쪽
- 마이페이지 보안 카드 `MfaSettings`: QR(qrcode.react@4.2.0)+수동키 → 확인 코드 → 복구 코드 1회 표시+다운로드+저장 확인 → 해제 모달
- 사용자 관리 2곳(테넌트 `/users`, 관리자 테넌트 사용자) MFA 리셋 버튼, en/es/ko 전체

**M3 집행** (`apps/api` + `apps/web`)
- `MFA_ENFORCE_FROM`(ISO env, 미설정=비활성) 3상태: 비활성 → **유예**(응답 플래그+웹 배너) → **강제**(`mfaPending` 클레임 + 가드 E1010 락아웃 — SEC-M2 `pwdPending`과 동일 메커니즘, 요청당 DB 조회 없음)
- 필수: 관리자 전체 + master/director(`MFA_REQUIRED_USER_RANKS`). 허용 라우트 `@AllowPendingMfa`(등록 3종+change-password/logout/me)
- 활성화 응답에 fresh 토큰 동봉 → 웹 즉시 교체(재로그인 불필요). refresh/change-password는 등록 상태 재조회로 플래그 재계산
- 웹: 강제 모달(비밀번호 강제 변경과 스택 방지), 유예 배너(마감일+마이페이지 링크)

## 4. 운영 안내

- **2026-08-14부터** staging의 관리자·master/director는 미등록 시 콘솔이 등록 화면으로 제한된다(그 전까지는 배너 안내). 등록: 마이페이지 > 2단계 인증
- 복구 코드 분실+앱 분실 시: 관리자(admin@)가 사용자 관리에서 "MFA 리셋" → 다음 로그인에서 재등록. 관리자 본인 계정은 상위 관리자가 리셋
- `MFA_ENFORCE_FROM` 오타 등 파싱 불가 값은 집행 비활성(fail-open)+경고 로그 — 전면 잠금 사고 방지 설계
