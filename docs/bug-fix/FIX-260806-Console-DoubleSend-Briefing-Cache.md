# FIX — 상담사 답변 중복 발송 + 콘솔 응답 지연 (2026-08-06)

## 1. 증상 (오프아워 이메일 검증 중 발견)

사용자가 콘솔에서 대화 #93에 답변 1회 전송 → 서버에는 **동일 답변 2건**(msg 461·462) 기록,
"이메일로 발송되었습니다" 시스템 메시지도 2건(463·464) → **고객에게 같은 메일 2통**.
또한 콘솔 API 응답이 **5~10초**(GET conversation 6~10s, POST message 7~8s).

## 2. 근본 원인

### 2-1. 중복 발송

콘솔 전송 버튼은 `disabled={send.isPending}`로 막혀 있으나, **Enter 키 핸들러에는 가드가 없었다**
(`onKeyDown={(e) => e.key === 'Enter' && onSend()}`). 게다가 `setDraft('')`가 **await 이후**에 실행돼
7초 넘는 요청 동안 입력값이 그대로 남아 있었다 → Enter를 한 번 더 누르면 같은 본문이 재전송.
오프아워 스레드에서는 이것이 곧 **중복 이메일**이다.

### 2-2. 5~10초 지연

`GET /agent/conversations/:id`가 매 호출마다 **AI 브리핑을 새로 생성**한다(`AgentService.briefing` →
모델 호출). 콘솔이 열린 대화를 **5초마다 폴링**(PLN-260804에서 도입)하므로, 변한 것이 없는 대화에
대해 5초마다 요약 모델 호출이 발생 — 지연의 주범이자 불필요한 토큰 비용.

## 3. 조치

1. **중복 전송 차단**: `onSend`에 `send.isPending` 가드 추가(버튼·Enter 공통 경로), 입력값은
   **요청 전에 비우고** 실패 시 복원.
2. **브리핑 캐시**: `agent:briefing:{conversationId}:{lastMessageId}` 키로 Redis 캐시(TTL 15분).
   새 메시지가 생기면 키가 바뀌어 자동 재생성 — 즉 **실제로 대화가 변했을 때만** 모델을 호출한다.

## 4. 검증

- `npm run typecheck` 통과, agent 스위트 통과.
- 배포 후: 콘솔에서 Enter 연타 시 1건만 전송·메일 1통, 열린 대화 폴링 응답이 첫 호출 이후 즉시 반환.

## 5. 예방 패턴

**진행 중 상태 가드는 "버튼"이 아니라 "액션"에 건다.** 버튼 disabled만으로는 Enter·단축키·중복 클릭
경로가 남는다. 또 낙관적 입력 비우기(선-clear, 실패 시 복원)가 함께 있어야 느린 요청에서 재전송이
원천 차단된다. 부수 효과가 외부(이메일 발송)로 나가는 액션일수록 이 가드는 필수다.

**폴링 주기를 줄일 때는 그 엔드포인트가 하는 일을 함께 본다.** 5초 폴링 자체는 옳았지만, 해당
엔드포인트가 모델 호출을 품고 있어 비용·지연이 5초마다 재발생했다. 폴링 대상 엔드포인트는
"값이 변했을 때만 비싼 계산"이 되도록 캐시 키를 데이터 버전(여기서는 마지막 메시지 id)에 묶는다.
