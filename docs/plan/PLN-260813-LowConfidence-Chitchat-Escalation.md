## 0. 판단 순서

```
고객 메시지
   │
   ├─ 정책 키워드                                   → 이관
   ├─ 상담원 요청 (PLN-260813 P1)                    → 이관
   ├─ ★ 질문이 아님 (smalltalk / out_of_scope / unintelligible, 신뢰도 ≥ 0.6)
   │      └→ 검색하지 않고 페르소나로 응답. 이관 없음
   │         3회 연속이면 답변 끝에 상담원 연결 제안 (자동 이관 아님)
   ├─ 모더레이션 차단                                → 이관
   └─ 저신뢰(< 0.45)                                → 이관   ← 지식 공백 15건은 여기 그대로
```

**질문이 아닌 말은 검색조차 하지 않습니다.** 인사에 벡터 검색을 돌려 "닮은 문서가 없다"는 결론을 얻고 그것을 이관 사유로 삼는 것이 지금의 구조입니다.

## 1. 단계별 계획

### P1 — 의도 집합 확장 (D1)

`rag.service.classifyIntent`의 닫힌 집합에 3종을 추가합니다.

```
order_status | delivery | cancel_refund | product_inquiry | agent_request
| smalltalk      ← 인사·감사·칭찬·잡담
| out_of_scope   ← 쇼핑몰과 무관 (날씨·환율·뉴스)
| unintelligible ← 의미를 읽을 수 없는 입력
| other
```

프롬프트에 각 값의 판정 기준을 한 줄씩 붙입니다. 특히 **"인사말 뒤에 실제 질문이 붙으면 그 질문의 의도로 분류"** 를 명시합니다(R2).

> 모델 호출은 늘지 않습니다 — 이미 매 턴 도는 분류에 값만 추가됩니다.

### P2 — 비질문 응답 경로

| 항목 | 설계 |
|---|---|
| 발동 조건 | `intent ∈ {smalltalk, out_of_scope, unintelligible}` **AND** `confidence ≥ 0.6` **AND** `!fallback` |
| 위치 | 상담원 요청 분기 **다음**, 검색 **이전** |
| 응답 생성 | **지식 없이 페르소나만으로** 1회 생성(D2) — 종류별 짧은 지시문 |
| 모더레이션 | 기존 AI 발신과 동일하게 통과(비우회 원칙) |
| 이관 | **없음.** 알림도, 대기열도 발생하지 않음 |

종류별 지시문(모델에 전달, 고객에게 보이는 문구가 아님):

| 의도 | 지시 |
|---|---|
| `smalltalk` | 짧고 따뜻하게 응대하고, 도울 일이 있는지 한 문장으로 물을 것 |
| `out_of_scope` | 쇼핑몰 밖의 주제임을 정중히 알리고 도울 수 있는 범위를 제시할 것. **없는 정보를 지어내지 말 것** |
| `unintelligible` | 이해하지 못했음을 알리고 다시 말해달라고 요청할 것 |

**비용은 오히려 줄어듭니다.** 지금은 임베딩 + 벡터 검색 + 큰 프롬프트로 RAG를 돌리는데, 이 경로는 짧은 프롬프트 1회로 끝납니다.

### P3 — 3회 안전망 (D5)

| 항목 | 설계 |
|---|---|
| 판정 | 직전 고객 메시지 **3건이 연속으로 비질문 의도**일 때 |
| 데이터 | `messages.intent`가 이미 저장돼 있음 → **마이그레이션 불필요** |
| 동작 | 응답 끝에 **상담원 연결 제안 한 문장**을 덧붙임. **자동 이관은 하지 않음**(D5) |
| 근거 | 고객이 계속 겉도는 말을 한다면 실제로 사람이 필요한 상황일 수 있음. 다만 판단은 고객에게 남김 |

### P4 — 계측

- 이관을 건너뛴 턴을 `logger.log`로 남김(의도·신뢰도) → 오분류 여부를 실데이터로 검증
- 배포 전후 **`agent_alerts` 중 `low_confidence` 비중** 비교(현재 33/48 = 69%)

## 3. 영향 범위

| 영역 | 영향 | 조치 |
|---|---|---|
| **상담원 알림** | `low_confidence` 알림 감소(의도한 변화) | P4로 계측 |
| **고객질문 통계** | 의도 렌즈에 3개 버킷 신설 | 오히려 정돈됨 — "무엇이 잡담이었는지"가 보임 |
| **AnswerReuse** | 비질문 경로는 재사용 대상이 아님 | 재사용 조회를 타지 않도록 분기 위치를 앞에 둠 |
| **모더레이션** | 새 응답 경로도 검사 대상 | 기존 AI 발신과 동일 경로 사용 |
| **비용** | RAG 1회 → 짧은 생성 1회 | 감소 |
| **오프아워** | 잡담이 이메일 회신 요청으로 가지 않음 | 부담 감소 |

## 5. 리스크와 대응

| # | 리스크 | 대응 |
|---|---|---|
| **R1** | **진짜 질문을 잡담으로 오분류** → 고객이 인사만 받고 사람도 못 만남 | 신뢰도 **0.6** + 폴백 배제 + **3회 안전망**(P3) + 계측(P4). 오분류가 보이면 임계를 먼저 올림 |
| R2 | "안녕하세요, 배송 언제 오나요?" | 프롬프트에 **인사+질문은 질문 의도로** 명시. V4로 검증 |
| R3 | `out_of_scope` 응답이 없는 정보를 지어냄 | 지시문에 금지 명시 + 기존 "지어내지 말 것" 규칙이 그대로 적용 |
| R4 | 무의미 입력 반복으로 고객이 갇힘 | P3 안전망이 3회째에 상담원 연결을 제안 |
| R5 | 잡담 판정이 언어마다 다르게 동작 | ko/en/es 각각 검증(V2) |

## 6. 검증 계획

| # | 항목 | 기준 |
|---|---|---|
| V1 | **인사** | `hello` · `안녕하세요` · `hi there` → **이관 없음**, AI가 자연스럽게 응대 |
| V2 | 감사·칭찬 | `상담원분 친절하시네요 감사합니다` → 이관 없음 |
| V3 | 범위 밖 | `뉴욕 날씨 알려줘` · `오늘 환율 알려줘` → 이관 없음, 정중한 안내 |
| V4 | **인사+질문** | `안녕하세요, 배송 언제 오나요?` → **이관 없이 배송 답변**(잡담 처리 금지) |
| V5 | **회귀** | `리뷰는 어떻게 남기나요?` · `성분이 뭔가요?` → **여전히 이관** |
| V6 | 무의미 | `qzxv 7781 plkj` → 되묻기, 이관 없음 |
| V7 | 안전망 | 비질문 3회 연속 → 3번째 응답에 상담원 연결 제안 문장 포함 |
| V8 | 임계·폴백 | 신뢰도 0.6 미만 또는 `fallback`이면 기존 동작(이관) |
| V9 | 모더레이션 | 새 경로 응답도 모더레이션을 통과 |
| V10 | 알림 감소 | 배포 후 `low_confidence` 알림 비중이 실측으로 감소 |

## 7. 구현 순서

```
P1 의도 확장  →  P2 비질문 응답  →  P3 안전망  →  P4 계측
     │              │                 │            │
  프롬프트만     새 응답 경로       기존 컬럼 활용   배포 후 실측
```

P1~P3은 **한 PR**입니다 — 의도만 늘리고 분기가 없으면 아무 일도 일어나지 않고, 분기만 있고 안전망이 없으면 R1이 방치됩니다.

## 8. 승인 요청

이 계획대로 진행할지 확인 부탁드립니다. 짚어둘 것 하나입니다.

**이 변경의 실패 방향은 지금과 반대입니다.** 현재는 부르지 않아도 될 때 사람을 부르고, 잘못 고치면 불러야 할 때 부르지 않습니다. 후자가 더 나쁩니다. 그래서 임계·폴백 배제·3회 안전망·계측을 함께 넣었고, **배포 후 오분류가 보이면 기능을 되돌리기 전에 임계부터 올리는 것**을 기본 대응으로 잡았습니다.
