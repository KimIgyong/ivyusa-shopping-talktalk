# REQ-260818-Widget-Orders-Tab

챗위젯 주문탭에 로그인 고객의 주문이 노출되지 않는 문제와, 주문 상태·배송 상태 화면 정비.

- 작성일: 2026-08-18
- 대상: `ambshop-dev.myshopify.com` (tenant 1, ivyusa) — 전 테넌트 공통 코드
- 요청: "주문탭에서 로그인한 사용자의 주문정보가 노출되지 않음 / 주문정보 노출하고
  해당 주문 상태 - 배송상태 화면 체크 필요"

## 1. 결론 먼저

**데이터 문제가 아니다.** tenant 1에 주문 7건이 캐시돼 있고, 로그인 시 Shopify 백필도
정상 동작한다(8/18 09:31·10:05·10:08 백필 로그 3건). **주문탭이 주문을 안 그리는 것이
원인이며, 원인은 세 겹이다.**

| # | 원인 | 결과 |
|---|---|---|
| C-1 | 주문탭이 **`결제` 칩에서 시작**하고, 그 칩은 주문이 아니라 **알림 피드**를 그린다 | tenant 1에 `payment` 알림이 **0건**이라 모든 고객에게 빈 화면 |
| C-2 | 주문 목록은 **`배송` 칩에서만** 렌더된다(`ShipmentList`) | "주문탭 = 주문 목록"이라는 기대와 어긋남 |
| C-3 | 그 목록마저 `isShipmentish`로 **배송중/배송완료만 통과**시킨다 | **결제완료(Confirmed) 주문은 위젯 어디에도 안 보임** |

C-3이 이번 제보의 핵심이다. 재현 계정이 특정된다 — 고객 `id=8`
(`shopify_customer_id 7822269251664`, 오늘 백필됨)의 유일한 주문
`#1004 / Confirmed / $749.95 / 2026-08-10`은 **결제 칩(알림 0건)에도, 배송 칩
(shipment 필터 탈락)에도 나오지 않는다.**

## 2. AS-IS

### 2.1 화면 구조
주문탭(`OrdersTab`)은 12줄짜리 껍데기이고 실제 렌더는 `NotificationsTab tab="orders"`가 한다.
칩 4개(`결제`·`배송`·`리뷰`·`문의`) 중 **`배송`만** 주문 API를 읽고, 나머지 셋은 알림 피드
또는 이슈 피드를 읽는다.

```
주문탭 → [결제] [배송] [리뷰] [문의]
          └ 알림   └ 주문   └ 알림  └ 이슈
            피드     목록     피드    피드
          ^^^^^^ 최초 진입 칩
```

### 2.2 데이터 (staging, tenant 1)
```
orders_cache      7건 (customer_id 1,2,4,5,6,8)
notifications     payment 카테고리 0건  ← 결제 칩이 항상 비는 이유
                  shipping 25건, chat 28건, review 1건
로그인 백필       정상 (ShopifySyncService, 8/18 3회)
```

### 2.3 API
- `GET /orders` (`@Public()` + 세션 토큰) → `orders_cache`를 `customer_id`로 조회.
  위젯은 `size=10`, `days=30` 고정으로 호출한다.
- `GET /orders/:id`, `GET /orders/:id/tracking` — 상세·배송추적. **구현은 이미 완비**
  (`OrderDetailView`: 상태 뱃지·품목·금액·`TrackingStepper`·리뷰 작성·상담 연결).
- 즉 **백엔드와 상세 화면은 있고, 목록 진입로만 없다.**

### 2.4 부수 관찰
- `listForSession`의 쿼리가 `customer_id`로만 필터한다. `customer`가 이미 테넌트 종속이라
  현재 유출 경로는 아니지만, CLAUDE.md §2의 "tenant_id로 필터" 규약과는 어긋난다.
- `days=30` 고정: 30일보다 오래된 주문은 조회 불가. 시드 주문 6건은 `ordered_at`이 NULL이라
  `created_at`으로 대체 평가된다.

## 3. TO-BE

**주문탭은 로그인 고객의 주문 목록을 그 자체로 보여준다.**

1. 주문탭 최초 진입 = **주문 목록**(알림 피드 아님). 상태와 무관하게 최근 주문을 모두 나열
   (결제완료·배송중·배송완료·취소/환불).
2. 각 행에 **주문번호 · 주문일 · 대표 품목 · 금액 · 상태 뱃지**. 배송중 주문은 행 안에서
   배송 단계를 바로 보여준다(현행 `TrackingStepperH` 재사용).
3. 행을 누르면 **주문 상세**(기존 `OrderDetailView`) — 품목·금액·배송추적·리뷰·문의.
4. 기존 칩(`결제`/`배송`/`리뷰`/`문의`)이 제공하던 알림·이슈 피드는 **없애지 않는다.**
   주문탭이 목록을 갖고, 알림 성격 칩은 그 위/아래에 유지하거나 알림탭으로 흡수한다
   — 배치는 PLN에서 결정.
5. 비로그인 고객은 현행대로 로그인 유도, 주문 0건이면 빈 상태 문구.

위젯 열기

  └ 로그인
      └ 주문탭 진입
          ├ 주문 있음 → 목록(최신순). 배송중 행은 단계 표시

## 7. 비고

- `orders_cache.status_ui`는 Shopify 표기를 그대로 담고 있어 값 집합이 몰마다 다를 수 있다.
  상태 매핑은 **미지의 값이 와도 원문을 그대로 보여주는** 폴백이 필요하다.
- 이번 변경은 PLN-260817(탭 구성)과 PLN-260818(테마)이 만든 구조 위에 얹는다.
  주문탭 자체는 이미 테넌트가 끌 수 있으므로, 끈 경우 칩 흡수 규칙과 충돌하지 않는지
  PLN에서 확인한다.
