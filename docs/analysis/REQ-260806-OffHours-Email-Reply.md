# REQ — 오프아워 이메일 회신 + 상담 운영시간 테넌트 설정화 (2026-08-06)

## 1. 요구사항 원문

1. 업무시간 09~18시 / 타임존 뉴욕 / 오프아워 12~13시 / 회신 메일 `help@ivyusa.com`
2. **테넌트 설정 메뉴에서 관리 가능하게** 처리
3. 회원에게 **"회원이 등록한 이메일로 회신하겠습니다"라고 안내**하고, **상담(회신)을 회원 이메일로 발송**.
   **회원 이메일이 아직 없으면 이메일을 입력받아 저장**
4. SMTP: `smtp.gmail.com:587`, 계정 `no-reply@amoeba.site` (앱 비밀번호 제공)

### 2.3 기술적 제약 (확인됨)

- 고객 이메일은 **AES-256-GCM 암호화 저장**(`customers.email_enc` + `email_hash` 블라인드 인덱스).
  기존 `CustomerService.createFromLead`가 이메일 기준 upsert + **삭제요청(Erasure) 억제 검사**를 이미 수행 —
  위젯 입력 경로도 이 검사를 반드시 통과해야 함(PRV-H2).
- 위젯 세션은 고객 미바인딩(게스트)일 수 있음 → 이메일 저장 시 고객 행 생성·연결 필요.
- 이메일 수집은 개인정보 수집이므로 **동의 상태(GRANTED) 이후에만** 가능해야 함(현행 채팅 게이트와 동일 원칙).

## 3. TO-BE

1. **테넌트 설정 화면에서 운영시간 관리**: 업무시간·타임존·요일 + **휴게시간(점심)** + 오프아워 회신 메일함.
2. **오프아워 접수 흐름**:
   - 고객 이메일을 아는 경우 → "○○@example.com 으로 회신드릴게요" 안내
   - 모르는 경우 → 위젯에서 이메일 입력 → 저장 → 동일 안내
3. **회신 발송**: 오프아워로 접수된 대화에 상담사가 콘솔에서 답변하면 **그 답변이 고객 이메일로 발송**된다.
   (운영 메일함 알림은 현행 유지 — 상담사가 접수 사실을 인지하는 경로)

## 5. 결정이 필요한 사항 (PLN에서 제시)

- D1 설정 화면 위치: `/settings`로 이동 vs `/ai-setting` 유지 + 링크
- D2 휴게시간 표현: 단일 구간 vs 복수 구간 배열
- D3 회신 이메일 발송 시점: 상담사 답변 시(권고) / 접수 즉시 확인메일 병행 여부
- D4 이메일 수집 UI 위치: 채팅 인라인 카드(권고, AuthGate 패턴 재사용) vs 별도 모달
- D5 고객 이메일 저장 시 개인정보 고지 문구 및 동의 전 차단 범위

## 6. 제약·리스크

- Gmail SMTP는 발신 한도(계정당 일 500통 수준)와 스팸 분류 리스크가 있음 → 초기 물량은 문제 없으나
  운영 전환 시 전용 발신 도메인/서비스 검토 필요.
- 고객에게 나가는 메일은 **모더레이션 대상**(FR-069/POL-020) — 상담사 답변도 예외 없이 통과해야 함.
- 이메일 회신은 단방향(수신 처리 없음) — 고객이 메일에 회신해도 시스템은 읽지 못함.
  안내 문구에 "회신은 위젯에서" 또는 발신 주소 정책을 명시해야 함(PLN D3에서 확정).
