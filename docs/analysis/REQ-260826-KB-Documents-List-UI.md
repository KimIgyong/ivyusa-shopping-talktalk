# REQ-260826 지식 문서(KB-Documents) 목록 UI 개편 — 제목 중심 행 + 필터/정렬

- 작성일: 2026-08-26
- 요청 유형: [요구사항] — `/knowledge` KB-Documents 목록 재배치 + 필터링/정렬 신설

## 0. 요구사항 원문

현재 `제목|카테고리|노출|출처|상태|수정일|삭제버튼` 1줄로 되어 있는 것을
**`카테고리 | 제목 | 수정일 | 더보기(노출/출처/상태/삭제)`** 로 변경하여 제목이 가운데 80% 정도 차지하게 처리.
대신 **제목(가나다순/역순), 노출(on/off), 출처(셀렉트), 상태(선택), 수정일(정순/역순) 필터링** 구현.

## 1. AS-IS

- 컬럼 8개(제목·카테고리·노출토글·출처·상태·수정일+stale·원본링크·삭제)가 한 줄에 몰려
  **제목이 좁게 잘리고** 부가 정보가 시야를 지배함. 목록의 주 용도(문서 찾기·열기)와 배치가 어긋남.
- 필터: 그룹 탭(전체/상담/상품) + 좌측 카테고리 내비게이터만. **제목 정렬·노출·출처·상태·수정일 정렬 전무.**
- 서버 `GET /knowledge/documents`: `source_id`/`category`/`group` where + `ORDER BY id DESC` 고정.
  `active`/`status`/`source`/정렬 파라미터 없음 → 페이지네이션이 서버에 있으므로 **클라 정렬·필터는 불가**(페이지 단위만 정렬되는 오류).
- `kb_documents.source` 실측 값: `knowledge_store` / `google_drive` / `knowledge_gap` (+향후 어댑터 추가 가능) —
  고정 enum이 아니라 **테넌트마다 실재 값이 다름**.
- 노출 토글·삭제·상세열기·원본링크는 기존 기능 그대로(위치만 이동 대상).

## 2. TO-BE

### R1. 행 재배치 — 제목 중심
- 컬럼 4개: **카테고리(배지, 고정폭) | 제목(잔여폭 전부 ≈80%, 클릭=상세) | 수정일(+stale 배지) | 더보기(⋯)**.
- **더보기(⋯) 팝오버**: 노출 토글(현 상태 표시+전환) · 출처 배지 · 상태 배지(+pending 힌트) · 원본 링크(있을 때) · 삭제.
  기존 기능 5종을 전부 수용 — 기능 제거 없음, 위치만 이동.

### R2. 필터/정렬
- 테이블 위 필터 행: **노출**(전체/노출/숨김) · **출처**(전체+실재 값 셀렉트) · **상태**(전체/embedded/pending) 셀렉트 3종.
- **정렬은 컬럼 헤더 클릭**: 제목(가나다순↔역순), 수정일(정순↔역순). 화살표 표시, 미지정 시 기존 최신순(id DESC) 유지.
- 모두 **서버 측** 구현(페이지네이션 정합): `ListDocumentsQuery`에 `active`/`source`/`status`/`sort`/`order` 추가.
- 출처 셀렉트 옵션은 **서버 DISTINCT 조회**(신규 `GET /knowledge/documents/facets` — sources·statuses) —
  고정 목록으로 만들면 새 값이 UI에서 조용히 사라짐([[invisible-fallback-trap]] 예방).
- 기존 그룹 탭·카테고리 내비게이터·페이지네이션과 **병행 적용**(AND 결합), 필터 변경 시 1페이지로.

## 3. 사용자 플로우
1. 상담 그룹 → 카테고리 'faq' → 상태 'pending' 필터 → 임베딩 대기 문서만 확인.
2. 제목 헤더 클릭 → 가나다순으로 훑으며 중복 제목 탐지.
3. 행의 ⋯ → 노출 off 전환 / 삭제 — 본문 열람 없이 목록에서 바로 처리.

## 4. 제약·전제
- 스키마 변경 없음(쿼리 파라미터·facet 조회만). 마이그레이션 불필요.
- 제목 가나다순은 MySQL utf8mb4 콜레이션 기본 동작 사용(별도 콜레이션 지정 없음).
- i18n 6언어(필터 라벨·더보기 항목), 멀티테넌시 tenant 술어 유지, 유닛(쿼리 조립·facet) 추가.
- 범위 밖: 제목 검색어 입력(백로그 — 요구는 정렬), 다중 선택 일괄 노출/삭제.
