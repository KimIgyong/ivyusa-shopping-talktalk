## 3. 설계에서 중요한 판단 4가지

### 3.1 오리진 허용목록은 보안 경계가 아니라고 코드에 적었다
`parent_origin`은 브라우저가 보내는 값이고 `curl`은 무엇이든 보낼 수 있다. 이 장치가 막는 것은
**브라우저에서의 무단 임베드와 오설치**다. 신원 증명은 서명(S2)이, 남용 방지는 레이트리밋이
담당한다. 유틸 파일 상단에 이 문장을 남긴 이유는, 허용목록을 인증으로 착각한 채 그 위에 기능을
얹는 것이 가장 위험하기 때문이다.

### 3.2 NULL을 "전부 허용"이 아니라 "스토어프론트"로 해석했다
`widget_tabs`와 같은 규약이다. 덕분에 컬럼이 **백필 없이** 배포되고, 지금 임베드 중인
스토어프론트가 끊기지 않으면서도 기본값이 느슨하지 않다.

### 3.3 관측 모드를 기본값으로 배포했다
실몰(amoebaorder)이 이미 붙어 있어 바로 차단하면 끊긴다. 위반을 통과시키되 `warn`으로 남긴다 —
4xx는 서버 로그에 남지 않으므로 이 줄이 차단을 켜도 되는지 판단할 유일한 근거다.

### 3.4 서명 대상은 사용자 ID 하나로 좁혔다
프로필(이름·이메일·전화)은 서명하지 않는다. 서명하면 고객사 서버가 프로필 수정마다 재서명해야
한다. 대신 프로필은 **빈 항목만 채우고 기존 값을 덮지 않는다** — 서명되지 않은 값이 검증된
기록을 고쳐 쓰는 일을 막는다.

## 4. 리뷰가 잡은 실제 결함 (커밋 `dc9c135`)

**내가 만든 새 설치 경로가 그 자신의 문서대로 설치하면 동작하지 않았다.** 셋 다 같은 종류의
실수 — 읽히는 순서대로 짰고, 브라우저가 실행하는 순서대로 짜지 않았다.

| 결함 | 왜 치명적이었나 |
|---|---|
| **iframe URL이 `init()` 전에 굳었다** | `frame.src`를 스크립트 로드 시점에 만들어서, `ShopTalk.init({shop})`만 쓰는 설치(=콘솔 스니펫과 가이드가 안내하는 그 방식)는 **shop 없이** 부팅했다 |
| **첫 명령이 유실됐다** | `open()`이 아직 로드되지도 않은 iframe에 postMessage → `init()` 직후 `open()`이 아무 일도 하지 않았다. 이제 `ivy:ready`까지 큐에 담고 순서대로 재생한다 |
| **설치 스니펫 자체가 예외를 던졌다** | `defer` 스크립트 아래의 인라인 `ShopTalk.init(...)`이 **먼저** 실행된다. 큐 스텁 방식으로 교체 |

그 외 반영: `logout()`이 세션 없이 남기던 문제(effect가 재실행되지 않음), 동시 최초
`identify()`의 유니크 키 경합(패자는 승자 행을 재조회), 감사 쓰기 실패가 **이미 회전된**
시크릿을 500으로 만들어 운영자가 평문을 영영 못 보게 되던 문제, placeholder i18n.

**반영하지 않은 것**: 빈 허용목록을 클라이언트에서 `null`로 보내라 — 서비스가 이미 빈 배열을
NULL로 매핑하므로 결과가 같다. 가이드 파일명 규칙 — `docs/guide`는 이 리포에서 접두사를 쓰지 않는다.

## 7. 예방 패턴 (일반화)

- **읽히는 순서가 아니라 실행되는 순서로 짜라.** iframe URL·명령 전송·설치 스니펫 세 곳 모두
  "위에서 정의했으니 준비되었을 것"이라는 가정이었다. 로더처럼 빌드도 타입검사도 없는 코드에서는
  이 가정을 검증해 줄 도구가 아무것도 없다.
- **내가 문서에 적은 설치 방법을 실제로 실행해 보라.** 세 결함 모두 "새 방식으로 설치한 첫 고객"이
  겪었을 것이고, 기존 고객에게는 보이지 않았을 것이다.
- **NULL의 의미를 정하면 백필이 사라진다.** "미설정 → 규약된 기본값"으로 읽으면 컬럼은 마이그레이션
  한 줄로 끝나고, 나중에 기본값을 바꿔도 손대지 않은 테넌트에 자동으로 반영된다.
- **이미 일어난 일을 감사 실패로 되돌리지 마라.** 시크릿은 회전됐고 응답이 평문의 유일한 출처인데,
  감사 쓰기 실패로 500을 내면 운영자는 "아무 일도 없었다"고 읽는다.
