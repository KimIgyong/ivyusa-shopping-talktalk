# PLN-260903 — 기본 대화내용·시나리오 버튼 설정 화면

REQ: `docs/analysis/REQ-260903-Conversation-Defaults-Console.md` · 브랜치 `session/agent-copy-scenarios`
스키마 변경 **0건**(기존 `tenant_ai_config.scenario_overrides` JSON·`tenants.widget_copy` 재사용) · **UI 변경 있음**

## D. 설계 결정

| # | 결정 | 근거 |
|---|---|---|
| D1 | 기본값은 **서버가 내려준다** — `GET /ai-config/defaults`(스크립트 7종 원문·버튼 6종·위젯 문구 기본) | 콘솔에 상수를 복제하면 배포 시점부터 어긋나고 그 어긋남이 화면에 안 드러난다 |
| D2 | 편집 모델은 **override 유지**, 다만 UI가 기본 원문을 **채워서 보여주고** [기본값으로 되돌리기] 제공. 저장 시 기본과 동일한 필드는 override에서 **제거** | "빈칸=기본" 규약은 저장 구조로는 옳다. 문제는 화면이지 저장이 아니다. 동일값 제거로 설정 비대화 방지 |
| D3 | **결함 수정 = 버튼→스크립트 매핑을 서버가 알려준다.** `SCENARIO_SCRIPT_BY_ACTION = { delivery_status: 'shipping_policy', cancel_refund: 'cancel_refund' }`를 한 곳에 두고 콘솔·런타임이 같은 표를 쓴다 | 콘솔이 `delivery_status`로 저장하고 런타임이 `shipping_policy`로 읽던 것이 원인. 양쪽이 각자 알고 있으면 또 어긋난다 |
| D4 | `product_help`는 편집 대상에서 **제거**(스크립트 없음) | 죽은 설정을 살리는 것보다 없애는 쪽이 정직하다. 이 버튼은 RAG 채팅으로 동작한다고 화면에 표시 |
| D5 | 스크립트 7종 **전부** 노출(follow-up 전용 4종 포함), "직접 버튼 / 후속 칩" 구분 표기 | 안 보이면 못 고친다(G1) |
| D6 | 다국어 라벨(G2)은 **S3로 분리** — `label: string \| LocalizedText` 하위호환 확장 | 위젯·API 계약 변경이라 위험도가 다르다. S1·S2와 별도로 승인·검증 |
| D7 | 대사 override는 **테넌트 단위 유지**(에이전트별 분리 안 함) | REQ §5. 설정 축을 늘리는 대신 "이 에이전트에 적용되는 값"을 보여주는 것으로 해결 |
| D8 | 메뉴 신설 없이 `/ai-setting` 내 재구성 | 메뉴 신설은 제공메뉴·권한 매트릭스까지 파급 |

## S1 — 결함 수정 + 기본값 노출 (핵심)

**백엔드**
1. `chat/scenario.service.ts` — `SCENARIOS`를 export 가능한 형태로 정리하고 **버튼 액션 → 스크립트 액션
   매핑표**를 신설(독립 모듈 `scenario-scripts.ts`로 분리 — 서비스 파일에서 상수를 export하면 순환
   import 부팅사 전례가 있다).
2. `ai-config.service.ts` — `getScenarioOverride(tenantId, action)` 호출 전에 매핑 정규화.
   기존 저장분 중 `delivery_status` 키가 있으면 **읽기 시 `shipping_policy`로도 조회**(백필 없이 회복).
3. 신규 `GET /ai-config/defaults` — 스크립트 7종(utterance/reply/followUps × 6언어) + 기본 버튼 6종 +
   위젯 문구 기본값 + 액션↔스크립트 매핑 + 각 스크립트의 도달 경로(button|follow-up).
4. 저장 시 정규화: `scenario_overrides`에서 기본과 동일한 필드 제거, `product_help` 키 폐기.

**프런트(`/ai-setting`)**
5. `ScenarioButtonsSection` — 각 행에 실행 스크립트 배지(`→ shipping_policy`)와 "RAG 채팅" 배지 표시.
6. `ScenarioReplyEditor` — 기본 원문을 **값으로 채워** 표시, [기본값으로 되돌리기], 언어 탭에 기본/수정
   상태 점 표시. `SCRIPTED_ACTIONS` 하드코딩 제거 → 서버 목록 사용.
7. 신규 `ScriptLibrarySection` — 스크립트 7종 목록(도달 경로·수정됨 여부)에서 편집기 열기.

## S2 — 에이전트 관점 보기 + 위젯 문구 기본값

8. `AgentEffectiveSection` — 선택 에이전트에 실제 적용되는 인사말·페르소나·응답규칙·노출 버튼을
   읽기 전용 요약으로 모아 보여주고, 각 항목에서 소유 섹션으로 이동.
9. `/settings` 위젯 문구 입력칸에 기본 문구를 placeholder가 아닌 **표시값**으로 노출 + 되돌리기.

## S3 — 다국어 라벨 (분리 승인)

10. `ScenarioButton.label`을 `string | LocalizedText`로 확장(문자열이면 전 언어 동일 — 하위호환),
    콘솔은 언어 탭 편집, 위젯은 세션 언어로 선택.

## S4 — 검증·문서

11. 단위: 매핑 정규화(저장키↔조회키), 기본값 API 응답에 7종 전부·6언어 존재, 동일값 제거,
    레거시 `delivery_status` override 회복, `product_help` 폐기.

13. 스테이징: go2joy에서 `shipping_policy` 대사를 호텔 문구로 바꾸고 **위젯에서 실제 반영 확인**
    (지금까지 반영되지 않던 경로 — 이번 수정의 증거).
14. TCR·RPT.

## 부수 영향

| 영역 | 영향 |
|---|---|
| 스키마 | 없음(기존 JSON 컬럼) |
| 기존 override | `delivery_status` 키로 저장된 값이 있으면 **이제 실제로 적용되기 시작한다** — 지금까지 무시되던 문구가 살아나므로 배포 전 테넌트별 저장값 점검 필요 |
| 위젯 | 런타임 동작 무변경(대사 출처만 정상화) |
| 다른 채널 | 시나리오 버튼은 위젯 전용 — 릴레이/메신저 무영향 |
| 권한 | 기존 `/ai-setting` 메뉴 권한 그대로 |

## 리스크

- **R1** `delivery_status` override가 살아나면서 기존 테넌트의 위젯 문구가 갑자기 바뀔 수 있다 →
  배포 전 `scenario_overrides`에 해당 키를 가진 테넌트를 조회해 값 확인, RPT에 명시.
- **R2** 기본 원문을 UI에 채우면 운영자가 "저장"만 눌러도 전량 override로 굳을 수 있다 →
  D2의 동일값 제거로 방지(저장해도 기본과 같으면 override 없음).
