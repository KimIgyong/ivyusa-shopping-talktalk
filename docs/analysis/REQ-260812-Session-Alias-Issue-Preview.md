# REQ-260812-Session-Alias-Issue-Preview

Live Chat **세션 별칭**과 Issue Board **카드 미리보기 모달** 요구사항 분석.

- 작성일: 2026-08-12
- 원 요구: "Live Chat - Sessions 세션명 별칭 추가 기능 — 각 세션별 별칭 작성 가능(세션명을 뒤에 표현) /
  Issue board — 관련 세션번호 및 별칭 표시 필요, 카드뷰 클릭 시 모달창으로 내용 미리보기,
  모달창에서 관련 세션으로 이동하기 처리 (현재 바로 라이브챗-세션으로 이동하는데 미리보기하여 내용만 확인하고 닫기 필요)"

## 1. AS-IS

### 1.1 Live Chat 세션 목록
| 축 | 현황 | 근거 |
|---|---|---|
| 행 표시명 | `customerName || customerEmail || "Session {id 앞 6자}"` — **운영자가 붙이는 이름은 없음** | `LiveChatPage.tsx` |
| 행 응답 | id(=**conversation id**), status, channel, escalated, 고객명/이메일, 미리보기, 시각 | `agent.mapper.ts toSessionResponse` |
| 세션 엔티티 | token/channel/tenant/customer/identity/language/consent — **별칭 컬럼 없음** | `session.entity.ts` |
| 이름 없는 대화 | 위젯 익명 방문자, 외부 메신저(텔레그램·카톡·SMS) 상당수가 이름 없이 `Session a1b2c3`으로만 구분됨 | 운영 관찰 |

> **선례**: btbz 릴레이(KSR)는 같은 문제를 `relay_conversation.display_name_override`로 풀었다 —
> 운영자 지정 이름이 자동 이름을 이기고, 비우면 자동 이름으로 되돌아간다. 같은 규약을 따른다.

### 1.2 Issue Board
| 축 | 현황 | 근거 |
|---|---|---|
| 카드 내용 | `#이슈번호 · 유형 · SLA 뱃지 · 재오픈 수 · 담당 라벨/이름 · 이동 셀렉트 · 우선순위 토글` | `IssueBoardPage.tsx` |
| **세션 정보** | **없음** — 카드 응답에 `conversationId`만 있고 세션번호·별칭·본문 미리보기 없음 | `issue.mapper.ts IssueCardResponse` |
| 카드 클릭 | **즉시 이동** `navigate('/live-chat?conversation={id}')` — 미리보기 없이 화면이 바뀜 | `IssueBoardPage.tsx:159` |
| 엔티티 | `issues`에 `conversation_id`(unique) + **`session_id` 이미 보유** | `issue.entity.ts` |

- 딥링크 자체는 정상이다(`?conversation=`를 Live Chat이 초기 선택값으로 읽음). **문제는 "확인만 하려 해도 무조건 이동한다"는 점.**
- 보드에서 이슈를 훑는 동안 내용을 보려면 매번 라이브챗으로 나갔다가 뒤로 돌아와야 하고, 그 사이 보드의 스크롤·필터 상태가 사라진다.

## 2. TO-BE (요구 기능)

| ID | 요구 | 우선순위 |
|---|---|---|
| FR-1 | **세션 별칭 작성·수정·해제**. 운영자가 세션마다 짧은 별칭을 붙인다(예: "강남점 사장님"). | P0 |
| FR-2 | 목록·대화 헤더에서 **별칭이 주 표시, 세션명은 뒤에** 보조로 노출. 별칭이 없으면 지금과 동일. | P0 |
| FR-3 | Issue Board 카드에 **관련 세션번호 + 별칭** 표시. | P0 |
| FR-4 | 카드 클릭 → **미리보기 모달**: 이슈 메타 + 세션 정보 + 최근 대화 내용. | P0 |
| FR-5 | 모달에서 **[관련 세션으로 이동]** / **[닫기]** — 닫으면 보드 상태(스크롤·필터) 그대로 유지. | P0 |
| FR-6 | 별칭은 대화가 새로 열려도 **같은 세션이면 유지**된다. | P1 |
| FR-7 | i18n(en/es/ko), 저장/실패 토스트(dev-kit §4.3 무음 성공 금지). | P0 |

## 3. 갭 분석

| ID | 갭 | 해소 방향 |
|---|---|---|
| G1 | 별칭을 담을 컬럼이 없음 | `sessions.alias VARCHAR(60) NULL` 신설 → **마이그레이션 필요** |
| G2 | 콘솔은 conversation id만 알고 세션 id를 모름 | 목록·상세 응답에 `sessionId` 동봉, 별칭 API는 conversation id로 받아 서버가 세션 해석 |
| G3 | 이슈 카드 응답에 세션·본문 정보 없음 | `sessionId`·`sessionAlias`·`preview`(최근 고객 발화 발췌) 추가 |
| G4 | 카드 클릭이 곧 이동 | 클릭 → 모달, 이동은 모달 안의 명시적 버튼으로 |
| G5 | 미리보기도 **대화 내용 열람** | 기존 `GET /agent/conversations/:id`를 재사용해 **PII 접근 감사(PRV-H4)를 그대로 남긴다** — 미리보기라고 감사에서 빠지면 안 됨 |
| G6 | 별칭은 운영자가 실명을 적을 수 있어 **PII가 될 수 있음** | 로그·감사 메타에 **값을 남기지 않는다**(설정/해제 여부만). 고객 데이터 삭제(DSAR) 시 세션과 함께 지워짐 |

## 4. 사용자 흐름 (TO-BE)

```
[상담원] Live Chat 목록 → 이름 없는 행 → 별칭 아이콘 클릭 → "강남점 사장님" 입력 → 저장
        → 행이 "강남점 사장님 · Session a1b2c3"으로 표시, 같은 세션의 다음 대화에도 유지

[상담원] Issue Board → 카드에 "#12 · 배송 · Session a1b2c3 · 강남점 사장님"
        → 카드 클릭 → 미리보기 모달(이슈 메타 + 최근 대화 10건)
        → 내용만 확인하고 [닫기] → 보드 그대로
        → 대응이 필요하면 [관련 세션으로 이동] → 해당 대화 열림
```

## 5. 제약·정책

- 별칭 길이 60자 이내, 앞뒤 공백 제거, 빈 값이면 **해제**(자동 표시명으로 복귀).
- 별칭 수정 권한은 대화를 다루는 권한(`CONVERSATION_HANDLE`)과 동일 — 별도 권한 신설 없음.
- 멀티테넌시: 세션·대화 조회는 기존과 같이 tenant 스코프. 타 테넌트 대화 id는 404.
- 미리보기 모달은 **읽기 전용** — 상태 변경·답장은 기존 경로(보드의 이동 셀렉트, 라이브챗)에서만.
