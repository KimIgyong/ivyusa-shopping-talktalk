### 0-1. ⚠️ 착수 전 확인 — 서비스 계정이 아직 없습니다

```
integration_credentials:  shopify(204B), cafe24(236B) 2건뿐 — google_drive 없음
integration_status:       google_drive 'connected'  ← 시드 데이터일 뿐 실제 연결 아님
```

**구현·테스트는 전부 진행할 수 있지만, 실제 드라이브 연동 검증은 아래가 준비돼야 합니다.**

1. GCP 프로젝트에서 서비스 계정 생성 + **Drive API 활성화**
2. JSON 키 발급
3. 대상 폴더를 서비스 계정 이메일에 **뷰어로 공유**

1~3은 계정 소유자(사용자)의 작업입니다. 키 등록도 사용자가 콘솔에서 직접 붙여넣습니다 —
제가 자격증명을 대신 입력하지 않습니다.

## 2. G1 — 자격증명 저장

### 2-1. ⚠️ 컬럼 크기 — 실측으로 확인한 함정

`secret_enc`는 현재 `VARBINARY(2048)`인데 **서비스 계정 JSON 전체는 들어가지 않습니다.**

| 저장 방식 | 평문 | AES-GCM 후 | 결과 |
|---|---|---|---|
| 전체 JSON | 2,379 B | ~2,407 B | **❌ 2048 초과** |
| 최소 필드(`client_email` + `private_key`) | 1,863 B | ~1,891 B | ✅ 수용(여유 157 B) |

여유 157 B는 RSA 4096 키 하나면 사라집니다. **두 가지를 함께** 합니다.

- 컬럼을 `VARBINARY(4096)`으로 확장 (추가 전용, 기존 204B·236B 행 영향 없음)
- 붙여넣은 JSON에서 **필요한 두 필드만 추출해 저장** — 보관 정보를 최소화

> 이전에 `external_key VARCHAR(128)`를 평균값 기준으로 잡았다가 실데이터에서 거부당한 적이
> 있습니다. 이번엔 실제 키 형태로 크기를 재고 시작합니다.

### 2-2. 저장 형태

`provider = 'google_drive'`, `secret_enc = AES-GCM(JSON.stringify({client_email, private_key}))` —
기존 `encryptSecret`/`decryptSecret`을 그대로 씁니다(신규 암호화 코드 없음).

## 3. G2 — 구글 인증 + Drive 클라이언트

**새 의존성을 추가하지 않습니다.** 레포가 이미 `fetch`를 쓰고, Node 20의 `node:crypto`로
RS256 서명이 가능합니다.

```
JWT 생성(RS256, scope=drive.readonly, 만료 1h)
   → POST oauth2.googleapis.com/token (grant_type=jwt-bearer)
   → access_token 캐시(만료 60초 전 갱신)
   → GET drive/v3/files?q='<folderId>' in parents and trashed=false
   → Docs: GET drive/v3/files/{id}/export?mimeType=text/plain
     txt/md: GET drive/v3/files/{id}?alt=media
```

- **읽기 전용 스코프**(`drive.readonly`)만 요청합니다. 쓰기 권한은 필요 없습니다.
- 토큰은 메모리 캐시. 실패는 재시도하지 않고 소스 상태를 `failed`로 남깁니다(S1 규약).

## 4. G3 — 어댑터 + 콘솔

`fetchAll`만 구현하면 업서트·건너뜀·숨김·배치 임베딩·이력은 **S1 파이프라인을 그대로** 씁니다.

| SourceItem | 매핑 |
|---|---|
| `externalKey` | `file:{fileId}` — 이름을 바꿔도 문서가 갈라지지 않게 |
| `title` | 파일 이름 |
| `content` | export/다운로드한 텍스트 |
| `sourceUrl` | `https://drive.google.com/file/d/{id}/view` |
| `category` | 소스 이름 |

빈 본문은 제외합니다(board 어댑터와 동일 규칙).

## 5. 마이그레이션

`sql/migration_gdrive_credential.sql`

```sql
ALTER TABLE integration_credentials MODIFY COLUMN secret_enc VARBINARY(4096) NULL;
```

확장 전용, 백필 없음, 기존 행(204B·236B) 영향 없음.
**롤백**: 4096→2048 축소는 google_drive 행을 지운 뒤에만 가능(그 전엔 데이터 잘림).

## 6. 사이드 임팩트

| 영역 | 영향 | 대응 |
|---|---|---|
| RAG 답변 | 드라이브 문서가 지식에 추가 | `doc_group='counsel'` — 정책 질의와 같은 축. 의도된 동작 |
| 충돌 스캔 | 드라이브 문서 ↔ 기존 정책 중복 가능 | 그룹 내 비교라 정상 동작. **오히려 이 기능의 목적에 부합** |
| 임베딩 비용 | 파일 수만큼 | 배치, 무변경 건너뜀 |
| `integration_status` | `google_drive: 'connected'`가 **거짓 표시 중** | 실제 자격증명 유무로 갱신 — 시드 거짓말 제거 |
| 폴더 권한 회수 | 공유가 끊기면 전체 문서가 사라진 것으로 보임 | ⚠️ **일괄 숨김 방지 가드**: 조회 결과가 0건이면 숨김을 실행하지 않고 `failed`로 기록 |
| 어드민 UI | 자격증명 입력란 신설 | 저장 후 재표시 안 함, 로그 마스킹 |

> 폴더 권한 회수 가드는 S1에 없던 규칙입니다. 게시판은 "글 0건"이 정상 상태일 수 있지만,
> 외부 API에서 0건은 **권한 상실과 구분되지 않습니다.** 그대로 두면 인증 문제 한 번에
> 지식 전체가 조용히 숨겨집니다.

## 7. 테스트 계획

- **JWT/토큰**: 서명 형식, 만료 60초 전 갱신, 캐시 재사용, 401 시 실패 처리
- **Drive 클라이언트**: 폴더 목록 페이지네이션, Docs export, txt/md 다운로드, 지원 외 MIME 제외
- **어댑터**: `file:{id}` 키 안정성(이름 변경), 빈 본문 제외, 하위 폴더 처리
- **가드**: **조회 0건이면 숨김 미실행 + `failed` 기록**
- **자격증명**: 전체 JSON에서 두 필드만 저장, 4096 경계, 미등록 시 소스 생성 차단
- **파이프라인 통합**: S1 규약(무변경 건너뜀·미색인 재색인·배치 임베딩) 재확인

## 8. 검증할 수 없는 것 (G4)

실제 드라이브 왕복은 자격증명 확보 후에만 가능합니다. **G1~G3 완료 시점에는
"코드는 완성, 실연동 미검증"으로 정직하게 보고**하고, S1처럼 실측 후 별도 RPT를 남깁니다.
