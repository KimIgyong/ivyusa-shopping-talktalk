# REQ — /live-chat 싱크 버튼 · 빠른 대화 로딩 · 모범답안 지식화 (2026-08-07)

## 1. 요구사항 원문

1. 대화방에서 바로 **최근 대화 가져오기(싱크) 버튼** 필요
2. 최초 대화방 오픈 시 대화 가져오는 데 시간이 걸림 → **최대한 빠르게**.
   전부 한 번에 가져오지 말고 **최근 10건 정도만** 먼저, 스크롤/더보기 시 나머지를 **블록 단위**로 검토
3. AI가 학습된 지식 밖이라 답하지 못한 건을 관리자가 골라 **모범답안을 작성해 지식으로 저장**
   (예: 세션 105 "한국 화장품 회사 제휴문의드립니다" → AI가 "이 채팅에서 도와드릴 수 없다"고 답변)

## 2. AS-IS

### 2.1 싱크 버튼 — 없음

대화창은 5초 폴링(PLN-260804)만 있고 **수동 갱신 수단이 없다**. 상담사가 "지금 최신인가?"를 확인할
방법도, 즉시 당겨올 방법도 없다.

### 2.2 최초 오픈 지연 — **원인은 대화량이 아니라 AI 브리핑**

스테이징 실측(2026-08-06):

| 대화 | 메시지 수 | 최초 오픈 응답 |
|---|---|---|
| 102 | 2건 | **7,969ms** |
| 97 | 2건 | 6,237ms |
| 100 | 2건 | 5,901ms |
| 105 | 6건 | 5,746ms |

**메시지가 2건뿐인 대화도 6~8초**가 걸린다. 즉 지연은 메시지 조회량이 아니라
`GET /agent/conversations/:id`가 응답 전에 **AI 브리핑(요약 모델 호출)을 기다리는 구조** 때문이다
(FIX-260806에서 캐시를 넣어 2회차부터 5ms로 떨어졌지만, **처음 여는 대화는 여전히 매번 5~8초**).

→ 요구 2의 제안(최근 10건만 로드)은 **현재 데이터에서는 체감 개선이 거의 없다**:
대화당 메시지가 2~6건이라 조회 비용이 사실상 0이다. 다만 대화가 길어지는 미래를 위한
페이지네이션 자체는 유효하므로 **2순위 과제**로 다룬다.

부가: `AgentService.listMessages`는 **limit 없이 전체** 조회한다(향후 긴 상담에서 문제).

### 2.3 모범답안 → 지식 저장 — 경로 없음

- KB 문서 생성 API는 존재: `POST /knowledge/documents` (title·category·content, `doc_group` 기본 counsel),
  생성 시 **동기 임베딩 후 Qdrant 업서트**, 실패 시 pending + 백오프 재시도(장애 시에도 500 없음).
- 그러나 **상담 화면에서 지식으로 보내는 수단이 전혀 없다**. 콘솔 지식 화면의 "문서 추가"는
  제목·분류·본문 빈 폼뿐이고, 대화 내용을 옮겨오는 연결이 없다.
- 대화 메시지는 안정적인 id를 가지므로(질문/답변 쌍 선택 가능) 화면에서 지목하는 데 문제는 없다.
- **권한 격차**: KB 쓰기는 `knowledge_source.manage`(MASTER/DIRECTOR)인데, 상담 처리는
  `conversation.handle`(MANAGER·STAFF 포함). 상담사 전원이 바로 저장할 수는 없다.
- 참고: 통계 화면에 "출처 없이 답한 질문(noSource)" 지표가 이미 있어, 지식 공백을 찾는 입구는 있으나
  거기서도 문서 생성으로 이어지지 않는다.

## 3. TO-BE

1. 대화창 헤더에 **싱크 버튼** — 누르면 즉시 최신 대화를 다시 불러온다(진행 표시 포함).
2. **대화창이 즉시 뜬다** — 메시지는 바로 렌더하고, AI 브리핑은 **별도로 나중에** 채운다.
   목표: 최초 오픈 5~8초 → **0.1초 수준**(브리핑은 자리표시자 후 도착 시 표시).
   더불어 메시지는 **최근 N건만** 먼저 주고 "이전 대화 더보기"로 블록 로드(긴 상담 대비).
3. 대화창에서 **질문/답변을 선택 → 모범답안 작성 → 지식으로 저장**.
   저장 즉시 임베딩되어 다음 유사 질문에 사용된다(현행 KB 파이프라인 그대로).

## 4. 사용자 플로우 (요구 3)

```
상담사/관리자가 대화창에서 문제의 답변을 발견
  → 해당 AI 답변의 [지식으로 저장] 클릭
  → 모달: 질문(고객 메시지, 자동 선택) / AI 답변(원문, 참고용)
           제목·분류 · 모범답안(편집 가능, 초기값 = AI 답변)
  → 저장 → KB 문서 생성 + 임베딩 → 다음 유사 질문에 반영
```

## 5. 결정 필요 (PLN에서 제시)

- D1 브리핑 분리 방식(별도 엔드포인트 vs 쿼리 플래그)
- D2 초기 메시지 건수(요구 10건 vs 30건) 및 더보기 단위
- D3 지식 저장 권한: 권한 있는 사용자에게만 버튼 노출 vs 상담사 제안 큐 신설
- D4 저장 문서의 분류·그룹 기본값과 출처 표기(대화 링크)
