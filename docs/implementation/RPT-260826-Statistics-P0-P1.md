## 2. 정정 — 제일 크게 짚었던 것이 틀렸습니다

점검 초안의 1번은 **"집계 작업을 아무도 돌리지 않는다"** 였습니다. **오판이었습니다.**
`QuestionStatsService`는 PR #90부터 스스로 스케줄합니다.

```
06:57:50  Question stats scheduled every 24h (first run in 10 min)
07:07:56  Question stats 2026-08-25: questions=287 rows=990 newClusters=0
```

제가 "결손"이라 부른 것도 결손이 아니었습니다 — 오늘치가 없는 건 어제치만 집계하니 정상,
08-23은 **그날 전 테넌트 고객 발화가 0건**, 테넌트 5·6은 08-19 이후 오늘까지 발화가 없었습니다.
화면만 보고 단정했고 **로그를 먼저 봤어야 했습니다.** AN 문서 D-1에 정정을 남겼습니다.

여기서 남은 진짜 문제는 작습니다: 집계가 **어제 하루만** 돌고 결손을 확인하지 않는다는 것,
그리고 **마지막 집계 시각이 어디에도 안 보인다**는 것(오판의 직접 원인). 후자는 P0에서 고쳤고
전자는 P2로 남겼습니다.

## 3. P0 — 지금 있던 숫자의 결함 2건

### ① 대시보드가 샌드박스를 고객으로 셌습니다
대화 검색은 `/ai-setting` 미리보기를 의도적으로 제외하는데(코드에 주석까지 있습니다) 같은
서비스의 대시보드는 세고 있었습니다. go2joy 대화의 26.2%가 미리보기였습니다.

**결과: tenant 1 총 대화 207 → 194.**

### ② "해결"의 정의가 셋이었습니다
대시보드는 `종료 & 이관 안 됨` — 고객이 그냥 나가버린 대화도 성공으로 셌습니다.
`classifyOutcome`을 `global/util/resolution.util.ts`로 옮겨 여정 리포트·대시보드·신규 처리 탭이
같은 함수를 읽습니다. 인자를 메시지 배열이 아니라 **마지막 비-시스템 발화자**로 바꿨습니다 —
판정에 쓰는 값이 그것뿐이고, 대시보드는 수천 건의 메시지를 읽을 수 없습니다.

**결과: 대시보드 AI 해결률 10% → 25%** (tenant 1). 카드에 정의 한 줄을 붙였습니다.

### ③ 집계 신선도 노출
`/analytics/questions`가 `lastAggregated`·`staleDays`를 함께 돌려주고, 2일 이상 밀리면 화면에
경고가 뜹니다. 배포 후 값: `lastAggregated 2026-08-25, staleDays 0`.

## 4. P1 — 신규 렌즈 4종 (스테이징 실측)

```
=== 채널 ===
  widget   대화 153  고객메시지 560  중앙값 3  평균 7.7  인계 34%

=== 상담원 ===
  AI    Default     대화 151  답변 450  해결 22%
  사람  Master Owner 대화   9  답변  28  만족도 4 (평가 2건)
  사람  seshin@…     대화   1  답변   2  만족도 5 (평가 1건)

=== 처리 ===
  종료 43 · 해결 33 · 77%
  open=110, agent_closed=17, customer_last=10, prompted_closed=10, csat_answered=6

=== 시간대 ===
  기준 UTC (테넌트 미설정) · 고객 메시지 560건 · 최다 07:00 (92건)
```

읽는 법 세 가지가 이 표에 그대로 드러납니다.

- **중앙값 3 vs 평균 7.7** — 평균은 긴 대화 몇 건이 끌어올린 값이고, 실제 대화는 3턴짜리입니다.
  카카오 채널이 붙은 테넌트에서는 이 차이가 3 대 131.7까지 벌어집니다.
- **만족도 "평가 2건"** — 평균 4.0을 점수처럼 띄우지 않습니다. CSAT는 전체 대화의 2.3%뿐입니다.
- **UTC (테넌트 미설정)** — 07:00 최다는 한국시간 16:00입니다. 라벨이 없으면 "새벽에 문의가
  몰린다"는 정반대 결론이 나옵니다.

## 5. 배포 후에만 드러난 결함 1건

`/analytics/agents`가 배포 직후 **500**이었습니다.

```
QueryFailedError: Unknown column 'NaN' in 'where clause'
```

`.select(['c.session_id', ...])` — TypeORM이 원하는 것은 **프로퍼티 경로**(`c.sessionId`)인데
컬럼명을 줬습니다. 컬럼은 읽히지만 엔티티 필드는 `undefined`로 남고, `Number(undefined)`가
NaN으로 바인딩되고, MySQL은 그것을 컬럼명으로 읽습니다.

**단위 테스트는 이걸 볼 수 없습니다** — 이 스위트의 더블은 테스트가 쓴 모양을 그대로 돌려주므로,
실제 DB만 만들 수 있는 실패입니다. `/analytics/channels`가 멀쩡했던 것은 그쪽 선택 이름이
우연히 프로퍼티명과 같았기 때문입니다.

세션 id는 유한값이 아니라 **`> 0`** 으로 거릅니다. `Number(null)`은 0이고, 0은 그럴듯해 보이는
id라서 세션 없는 대화를 전부 한 바구니에 모읍니다 — 회귀 테스트를 쓰다가 이걸 잡았습니다.
