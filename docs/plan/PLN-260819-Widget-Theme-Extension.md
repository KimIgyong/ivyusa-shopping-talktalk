## 0. 왜 지금 이 순서인가

REQ §4.1에서 미뤄둔 이유가 해소됐다: **런처는 iframe 바깥 크기·위치에 묶여 있고, 로더가 테마를
알아야 움직인다.** S3에서 로더가 `init()`·명령 큐·`ivy:ready` 핸드셰이크를 갖췄으므로, 이제
위젯이 로더에게 런처 형상을 알려줄 자리가 생겼다.

범위는 P0 셋으로 자른다. 서체·다크모드·패널 치수(FR-T3~T6)는 토큰을 더 얹는 일이라 같은
구조 위에서 나중에 붙는다.

## 1. 설계 개요

```
콘솔 (테마 카드)                          위젯                      로더(embed.js)
──────────────                          ────                      ─────────────
브랜드색·헤더  ← 기존                     session/ensure 응답에
로고 업로드    ← 신규 ────┐                widgetTheme 확장 수신
런처 위치·크기·아이콘 ←신규 ┤                  │
                          │                  ├─ CSS 변수 적용(기존)
미리보기(순수 렌더) ←신규   │                  ├─ 헤더 로고 렌더
   buildThemeVariables    │                  └─ ivy:launcher ─────▶ iframe 위치·크기 조정
   (@ivy/types 공유)      │                      {position,size}      + 부모 localStorage 캐시
                          └─▶ PATCH /tenants/widget-theme
                              (widget_theme JSON 확장 — 컬럼 추가 없음)
```

## 2. FR-T1 — 로고

### 2.1 저장: 새 테이블도, 새 컬럼도 만들지 않는다

`widget_theme` JSON을 확장한다.

```jsonc
{
  "brand": "#2B7FFF",
  "headerStyle": "white",
  "logo": { "id": "9f3a…", "ext": "png", "mime": "image/png", "width": 240, "height": 64 }
}
```

파일은 첨부와 같은 볼륨에, 대화와 무관한 경로에 둔다: `{UPLOAD_DIR}/{tenantId}/branding/{id}.{ext}`.

`message_attachments`를 재사용하지 않는 이유는 그 테이블이 **대화·메시지에 묶여 있고**
리텐션·DSAR·테넌트 삭제가 전부 그 축으로 지운다는 것이다. 로고는 고객 데이터가 아니라 **테넌트
자산**이라, 그 삭제 경로에 얹으면 보존기간이 지날 때 브랜드 로고가 사라진다.

### 2.2 서빙: 서명 URL이 아니라 공개 캐시

`GET /api/v1/public/widget-logo?shop={domain}&v={id}` — 인증 없음, `Cache-Control: public,
max-age=31536000, immutable`. 로고는 비공개 데이터가 아니고, 위젯은 익명 상태에서 첫 페인트에
이걸 그린다. 서명·만료를 붙이면 캐시가 죽고 만료된 로고가 깨져 보인다.

`v`는 캐시 무효화용이다(값이 바뀌면 URL이 바뀐다). `shop`으로 테넌트를 찾으므로 uuid만으로
남의 자산을 열거할 수 없다.

### 2.3 업로드

`POST /api/v1/tenants/widget-theme/logo` (master/director, multipart).

| 검증 | 값 |
|---|---|
| 형식 | png · jpg · webp · **svg 금지**(첨부 정책과 동일 — 자체 오리진 스크립트 실행 벡터) |
| 용량 | 1MB |
| 픽셀 | 최대 1000×400, 초과 시 축소 |
| 처리 | sharp 재인코딩(EXIF 제거) → 높이 64px 기준 정규화, 원본 비율 유지 |
| 실패 | E5049 — 조용히 무시하지 않는다 |

sharp가 없는 환경에서는 **거부**한다(첨부 HEIC 경로와 같은 fail-closed). 재인코딩이
EXIF 제거를 겸하고 있어서, 폴백 저장은 브랜드 이미지에 위치정보를 남긴다.

### 2.4 표시

위젯 헤더의 제목 자리(`WidgetPanel.tsx:84`)에 로고를 놓고, 로고가 있으면 텍스트 표시명은
`alt`로 내려간다. 로고가 없거나 로드 실패면 **지금과 동일하게** 텍스트로 되돌아간다.

## 3. FR-T2 — 런처

### 3.1 무엇이 어디에 있는지부터

| 요소 | 사는 곳 |
|---|---|
| 버튼 모양·색·아이콘 | **위젯 안**(`Widget.tsx:125`) — CSS 변수로 이미 테마 적용됨 |
| 버튼 여백(`bottom-5 right-5`) | 위젯 안, 하드코딩 |
| **iframe 크기·위치**(닫힘 96px, `right:0 bottom:0`) | **로더** |

즉 위치를 왼쪽으로 옮기려면 **두 곳이 동시에** 바뀌어야 한다. 한쪽만 바꾸면 버튼이 프레임
밖으로 잘린다.

### 3.2 저장

```jsonc
"launcher": { "position": "right" | "left", "size": "sm" | "md" | "lg", "icon": "chat" | "question" | "headset" | "logo" }
```

전부 **열거형이다.** 자유 입력(픽셀 여백, 임의 아이콘 URL)을 받지 않는 이유는 테마 1차에서
전경색을 산출로 만든 것과 같다 — 읽을 수 없는 위젯을 만들 수 있는 입력은 주지 않는다.
`icon: "logo"`는 업로드한 로고를 런처에 쓴다(정사각 크롭).

### 3.3 로더에 전달: 새 API 호출을 만들지 않는다

위젯은 이미 `session/ensure`로 테마를 받는다. 그것을 로더에게 넘긴다:

```
위젯 ──ivy:launcher {position,size}──▶ 로더
                                        ├─ frame.style.left/right 전환
                                        ├─ CLOSED 크기 조정(sm 80 / md 96 / lg 112)
                                        └─ localStorage[ivy:launcher:{shop}] 캐시
```

**첫 페인트 깜빡임**: 로더는 위젯이 뜨기 전에 프레임을 놓는다. 캐시된 값이 있으면 즉시 적용하고,
메시지가 오면 갱신한다 — 위젯이 테마를 캐시해 첫 페인트 색 튐을 없앤 것(PLN-260818 §2.5)과
같은 수법을, 이번엔 부모 오리진에서 한다.

패널이 열릴 때의 `OPEN` 치수는 **건드리지 않는다**(FR-T3, 다음 단계).

## 4. FR-T7 — 미리보기

### 4.1 위젯을 iframe으로 띄우지 않는다

가장 자연스러운 안은 콘솔에 실제 위젯을 iframe으로 띄우고 초안 테마를 postMessage로 주입하는
것이다. **채택하지 않는다**:

- 위젯이 뜨면 `session/ensure`가 돌아 **테마를 만질 때마다 게스트 세션이 생긴다.** 대화 목록과
  통계에 미리보기 잡음이 쌓인다.
- 미리보기 전용 부팅 모드를 만들면 위젯에 "진짜가 아닌 상태"라는 분기가 생긴다.

대신 콘솔에서 **순수 렌더 목업**을 그린다. 색이 어긋날 걱정은 없다 — 콘솔과 위젯이 이미
`buildThemeVariables()`(`@ivy/types`) **같은 함수**를 쓰기 때문이다. 목업은 헤더(로고 포함) ·
말풍선 2개 · 런처만 그린다.

한계는 명시한다: 목업은 근사이고, 실제 확인은 스테이징 위젯이다. 목업이 커지면 드리프트가
생기므로 **의도적으로 작게 유지**한다.

### 4.2 저장 전 반영

미리보기는 **폼 상태**를 그린다(저장된 값이 아니라). 저장 버튼을 누르기 전에 브랜드색·헤더·
로고·런처를 바꾸면 즉시 반영된다.

## 8. 테스트 개요

**단위**
- U-1 `normalizeWidgetTheme`: logo/launcher 정상·누락·잘못된 열거값 → 기본값, 브랜드색은 기존대로 전체 거부
- U-2 로고 업로드: png/jpg/webp 수용, **svg 거부**, 1MB 초과 거부, 1000×400 초과 축소
- U-3 로고 재인코딩으로 EXIF 제거(첨부 경로와 같은 회귀 고정)
- U-4 sharp 부재 시 업로드 거부(fail-closed)
- U-5 공개 로고 라우트: 존재하지 않는 shop → 404, 캐시 헤더 확인
- U-6 런처 열거값 정규화(position/size/icon)
- U-7 **회귀**: logo·launcher 없는 기존 테마 → 출력 동일

**통합**
- I-1 로고 업로드 → 위젯 헤더에 표시 → 삭제 → 텍스트로 복귀
- I-2 런처 왼쪽 전환 → 위젯 버튼과 iframe이 **함께** 이동(잘리지 않음)
- I-3 미리보기가 폼 상태를 즉시 반영(저장 전)

**스모크(스테이징)**
- S-1 실제 로고 업로드 후 위젯에서 확인(모바일 폭 포함)
- S-2 런처 좌/우·크기 3단 전환
- S-3 로고 교체 시 캐시가 갱신되는가(`v` 변경)
- S-4 **무회귀**: 테마를 건드리지 않은 테넌트(amoebaorder)의 위젯이 그대로인가

## 9. 승인 요청

| 항목 | 계획값 |
|---|---|
| 범위 | 로고(FR-T1) · 런처 위치/크기/아이콘(FR-T2) · 콘솔 미리보기(FR-T7) |
| 저장 | `widget_theme` JSON 확장 — **컬럼·테이블 추가 없음** |
| 로고 서빙 | 공개 URL + 1년 immutable 캐시(`v`로 무효화), 서명 없음 |
| 런처 | 열거형만(자유 픽셀·임의 아이콘 URL 없음) |
| 미리보기 | 콘솔 내 **순수 렌더 목업**(위젯 iframe 아님 — 세션 잡음 방지) |
| 신규 에러코드 | E5049(로고 업로드 거부) |
| 비범위 | 패널 치수·모서리·서체·다크모드(FR-T3~T6), 커스텀 CSS |

위 내용으로 **구현 착수 승인**을 요청합니다.
