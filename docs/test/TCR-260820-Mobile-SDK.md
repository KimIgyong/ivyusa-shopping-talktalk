## 3. 검증에서 나온 수정

| 발견 | 조치 |
|---|---|
| **구독 해제·마운트 전 호출이 예외**였다 | 네이티브 수신 전역을 모듈 로드 시 1회 설치하고 큐(최대 20건)를 둔다. 앱은 화면 진입과 동시에 `identify`를 보내므로 마운트보다 빠른 것이 정상이다 |
| 앱 모드인데 **런처 형상을 보고**하고 있었다 | 시뮬레이터 로그에서 발견 — 앱 모드에서는 보고하지 않는다 |
| 테스트끼리 모듈 인스턴스를 공유 | 브리지에 모듈 상태(구독자·큐)가 생겨서 — 테스트마다 새 인스턴스를 강제 |

## 4. 알려진 한계 (정직하게)

- **실기기·실앱 검증은 하지 않았다.** 시뮬레이터는 계약(메시지 교환)만 확인한다.
- WebView에서만 드러나는 것들 — **Android 파일 선택기**(구현 안 하면 사진 첨부가 조용히
  실패), 키보드 회피, 외부 링크 처리 — 은 RN 참조 구현에 포함했고 네이티브는 가이드에 스니펫으로
  실었지만, **동작 확인은 go2joy 앱에서 처음 이루어진다.**
- `packages/shoptalk-rn`은 타입 검사까지만 했다(RN 런타임 없음). 참조 구현이며 발행하지 않는다.
- 오리진 허용목록(S1)은 WebView에 적용되지 않는다(앱에는 도메인이 없다). 앱에서의 방어선은
  **서명 신원**이다.
