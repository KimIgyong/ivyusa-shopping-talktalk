## 0. 현행 (설계 근거)

| 영역 | 현행 | 이번 요구와의 간극 |
|---|---|---|
| `/knowledge` 화면 | 소스 카드 + 문서 목록(카테고리 **드롭다운** 필터, 20건 페이지네이션), 상세 모달은 **읽기 전용**(+노출 토글) | 질문·답변 기능 없음 · 상세에서 내용 수정 불가 · 카테고리 목록/건수 미제공 |
| 지식 검색 | `RagService.answer()` — 하이브리드 검색 후 `citations`(문서 id·제목·카테고리·유사도·스니펫) 반환 | 관리자용 진입점 없음(위젯 chat 경로뿐) |
| 문서 API | 목록·상세·생성·수정(PATCH: title/content/category/active)·삭제 | 카테고리 집계 없음 |

**핵심 판단**: 수정 API(PATCH)와 근거 데이터(citations)는 이미 있습니다. 이번 작업은
**관리자용 QA 진입점 + 근거→편집 연결 + 카테고리 탐색 UI**를 얹는 것이며 스키마 변경은 없습니다.

## 1. F1 — 지식 QA 에이전트 (우측 패널)

**목적**: 등록한 지식으로 실제 어떤 답이 나오는지 확인하고, **틀린 근거 문서를 즉시 찾아 고치는** 루프.

### 백엔드 — 신규 `POST /knowledge/ask` (`KNOWLEDGE_SOURCE_MANAGE`)
```
요청  { question: string, language?: 'en'|'es'|'ko' }
응답  { answer, confidence, blocked, sources: [{ id, title, category, similarity, snippet }] }
```
- 내부적으로 `RagService.answer(tenantId, question, language)` 호출 → 답변과 근거를 그대로 노출.
- **대화·세션을 만들지 않습니다**(`/ai-setting` 미리보기와 달리 대화 이력·이관과 무관한 순수 조회).
- 모더레이션(FR-069/POL-020)은 **우회하지 않고 통과시키되**, 차단된 경우 답변 대신
  `blocked: true`와 사유를 반환 — 관리자에게는 "이 답변은 모더레이션에 걸린다"는 사실 자체가
  진단 정보입니다.

### 화면 (와이어프레임)
```
┌ /knowledge ─────────────────────────────────┬─ 지식 QA ──────────────────┐
│ [소스]                                       │ 지식으로 답하기   [KO▾]    │
│ ┌ 카테고리 ─┬ 문서 목록 ─────────────────┐   │ ┌────────────────────────┐ │
│ │ 전체  236 │ 2.1.3 배송비    [노출][수정]│   │ │Q 배송비 얼마인가요?     │ │
│ │ 배송   26 │ 2.1.6 배송주소  [노출][수정]│   │ │A 최종 주문금액 $29.99…  │ │
│ │ 반품   24 │ …                          │   │ │  conf 0.54             │ │
│ │ 결제   18 │        ◀ 1/12 ▶            │   │ └────────────────────────┘ │
│ └───────────┴────────────────────────────┘   │ 근거 문서                  │
│                                              │ • 2.1.3 배송비    0.54 [수정]│
│                                              │ • 1.3.5 주문정보  0.47 [수정]│
│                                              │ [질문 입력_________] [전송] │
└──────────────────────────────────────────────┴────────────────────────────┘
```
- 근거 문서의 **[수정]** → 같은 화면의 문서 편집 모달을 그 문서로 열어 바로 고침 →
  저장 시 재임베딩(기존 PATCH 경로) → **같은 질문 재실행으로 즉시 재검증**.

## 2. F2 — 문서 편집 (상세 모달 확장)

현재 읽기 전용인 상세 모달에 **편집 모드**를 추가합니다.
- 편집 대상: 제목 · 카테고리 · 본문 (PATCH `documents/:id` 기존 계약 그대로).
- 저장 시 백엔드가 내용 변경을 감지해 **자동 재임베딩**(현행 `updateDocument` 동작) —
  QA 패널에서 바로 재확인 가능.
- 노출(활성/비활성) 토글은 현행 유지.

## 3. F3 — 카테고리 탐색 UI

### 백엔드 — 신규 `GET /knowledge/categories` (`KNOWLEDGE_SOURCE_MANAGE`)
```
응답 [{ category: 'policy_shipping', total: 26, active: 26 }, …]
```
- 단일 `GROUP BY` 쿼리(테넌트 스코프). 목록 성능에 영향 없음.

### 화면
- 드롭다운 → **좌측 카테고리 목록**(이름 + 건수, 선택 시 강조). "전체"가 기본.
- 카테고리 선택 시 페이지 1로 리셋(현행 필터 동작 유지), 목록은 기존 페이지네이션 그대로.
- 문서 행에 **카테고리 배지 + [수정]** 노출(현행 제목 클릭 = 상세도 유지).

| 단계 | 내용 | 규모 |
|---|---|---|

| K3 | 프런트: 상세 모달 편집 모드 + 근거→편집 연결(재검증 루프) | 0.5d |
| K4 | 테스트(ask 응답 계약·카테고리 집계·테넌트 격리) + 스테이징 배포 + RPT | 0.5d |

- **스키마 변경 없음 → 마이그레이션 없음.**
- PR 1~2개로 분할, CI 게이트 통과 후 머지.

## 5. 리스크·결정 필요

1. **QA 패널의 답변 품질은 AI 엔진 상태에 종속** — 스텁 어댑터면 문구가 스텁으로 나옵니다
   (근거·유사도는 실제). 운영 검증은 실제 엔진 키가 설정된 환경에서 해야 합니다.
2. **모더레이션 차단 표시** 방침(§1) — 답변을 감추고 차단 사실만 보여줍니다. 반대로 "차단 전
   원문도 보여달라"면 정책 판단이 필요합니다(기본안: 감춤).
3. 카테고리는 자유 문자열이라 오타 카테고리도 목록에 나타납니다 — 이는 데이터 실태를 드러내는
   것이 오히려 유용하다고 보아 **정규화하지 않습니다**(편집 모달에서 고칠 수 있음).
