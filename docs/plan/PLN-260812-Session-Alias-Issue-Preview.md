# PLN-260812-Session-Alias-Issue-Preview

세션 별칭 + 이슈 보드 미리보기 모달 작업계획서.

- 근거: `REQ-260812-Session-Alias-Issue-Preview`
- **승인 필요** — 승인 전 구현 착수 금지(CLAUDE.md §7)
- 규모: PR 1건(백엔드+콘솔), 스키마 변경 1건

## 0. 제안 결정 (승인 시 확정)

| ID | 제안 | 이유 |
|---|---|---|
| D-1 | 별칭은 **세션에 저장**(`sessions.alias`) | 요구가 "각 세션별". 대화는 종료 후 새로 열리는데, 외부 메신저(텔레그램·카톡)는 같은 사람이 여러 대화를 만든다 — 별칭이 사람을 따라가야 쓸모가 있다(FR-6) |
| D-2 | 편집 위치 = **목록 행 + 대화 헤더** | 별칭이 가장 필요한 순간은 목록에서 누가 누군지 구분할 때다. 헤더에만 두면 대화를 열어야만 붙일 수 있다 |
| D-3 | 미리보기 **최근 10건** | 카드 하나 훑는 데 필요한 맥락은 마지막 몇 턴이다. 더 필요하면 이동 버튼이 있다 |
| D-4 | 카드 표시 = **`Session a1b2c3` + 별칭** | 별칭이 없는 세션도 있으므로 식별자는 항상 있어야 한다 |

## 1. 스키마 (`sql/migration_session_alias.sql`)

```sql
-- 운영자가 붙이는 세션 표시명. 비우면 자동 표시명(고객명 → 이메일 → Session id)으로 복귀.
ALTER TABLE sessions ADD COLUMN alias VARCHAR(60) NULL AFTER identity_level;
```
롤백: `ALTER TABLE sessions DROP COLUMN alias;` (기존 컬럼 변경 없음)
엔티티는 nullable에 **명시 `type`** 필수(union 타입만 쓰면 부팅 크래시 — CLAUDE.md §2).

## 2. 백엔드

**S1. 별칭 읽기/쓰기** (`domain/agent`)
- `PATCH /agent/conversations/:id/alias` — body `{ alias?: string | null }`(snake 규약상 단일 필드), `@RequireCapability(CONVERSATION_HANDLE)`
  - 대화 → 세션 해석(테넌트 스코프), trim 후 60자 초과면 400(`VALIDATION_FAILED`)
  - 빈 문자열/null → `NULL` 저장(해제)
  - 세션 캐시 무효화(`sessionCacheKey`) — 별칭은 세션 행에 있으므로 30초 캐시가 남으면 옛 값이 보인다
  - 감사: `agent.session.alias` — **메타에 값은 넣지 않는다**(운영자가 실명을 적을 수 있음, REQ G6). `{ set: true|false }`만
- `toSessionResponse`에 `sessionId`, `alias` 추가 / 대화 상세 응답에도 동일 필드 추가
  - 목록은 이미 세션을 조회하지 않으므로 **conversation.session_id 기준 일괄 조회 1회**로 붙인다(N+1 금지, 기존 `contactsByConversation`와 같은 배치 패턴)

**S2. 이슈 카드에 세션·미리보기** (`domain/issue`)
- `IssueCardResponse`에 `sessionId`, `sessionAlias`, `preview` 추가
- `preview` = 해당 대화의 **마지막 고객 발화 120자**. 보드 목록에서 한 번에 배치 조회(카드 수만큼 쿼리 금지)

**S3. 미리보기 데이터**
- 신규 API 없음 — 모달은 기존 `GET /agent/conversations/:id?limit=10`을 재사용한다.
  그 경로는 PII 접근 감사를 남기는데(PRV-H4), **미리보기도 실제 대화 열람이므로 감사에서 빠지면 안 된다**(REQ G5).

## 3. 콘솔

**S4. Live Chat 별칭 편집**
- 목록 행: 별칭/이름 옆 연필 아이콘(행 hover·선택 시 노출) → 인라인 입력 → Enter 저장 / Esc 취소
- 대화 헤더: 같은 편집기
- 표시 규칙(요구 문구 그대로 "세션명을 뒤에"):
  - 별칭 있음 → **`{별칭}`** 굵게 + 뒤에 회색 `Session a1b2c3`
  - 별칭 없음 → 현행 그대로(`고객명 || 이메일 || Session a1b2c3`)
- 저장/실패 토스트, 목록 쿼리 무효화

**S5. Issue Board 미리보기 모달**
- 카드 클릭 → `navigate()` 대신 `setPreview(card)`
- 모달 내용: `#이슈번호 · 유형 · 상태 · 우선순위 · SLA` / `Session a1b2c3 · 별칭` / 담당 / 최근 10건 대화(발신자 구분) / 로딩·빈 상태
- 푸터: **[관련 세션으로 이동]**(기존 딥링크 `/live-chat?conversation={id}`) · **[닫기]**
- 드래그·이동 셀렉트·우선순위 토글은 기존처럼 `stopPropagation()` 유지 → 조작은 모달을 열지 않는다
- i18n en/es/ko

## 5. 사이드 임팩트

| 영역 | 영향 | 판단 |
|---|---|---|
| 위젯 | 없음(별칭은 콘솔 전용, 고객에게 노출 안 됨) | 무영향 |
| 기존 목록 응답 | 필드 **추가**만(`sessionId`,`alias`) | 하위호환 |
| 이슈 보드 조작 | 드래그·이동·우선순위는 그대로, 클릭 동작만 변경 | 의도된 변경 |
| 성능 | 목록/보드에 배치 조회 각 1회 추가 | 무시 가능 |
| 개인정보 | 별칭이 PII일 수 있음 → 로그·감사에 값 미기록, 세션 삭제 시 함께 삭제 | REQ G6 |
| DSAR | 세션 행에 붙으므로 기존 삭제 경로에 자동 포함 | 확인 필요(테스트 포함) |

## 6. 테스트 / 배포

- **단위**: 별칭 trim·60자 초과 400·빈 값 해제·타 테넌트 404·세션 캐시 무효화·감사 메타에 값 없음,
  목록 응답의 `sessionId`/`alias` 매핑, 이슈 카드의 `sessionAlias`/`preview` 배치 조회(N+1 없음)
- **통합**: 별칭 저장 → 목록·대화 헤더·이슈 카드 3곳에 반영 / 대화 종료 후 새 대화에도 유지(FR-6)
- **스테이징**: 콘솔에서 별칭 부여 → 보드 카드 확인 → 카드 클릭 시 **이동하지 않고** 모달, [닫기] 후 보드 상태 유지, [이동] 시 해당 대화 열림
- **Migration(필수)**: `sql/migration_session_alias.sql`을 **코드 배포 전** 스테이징 DB에 선적용(`DB_SYNCHRONIZE=false`).
  PR 본문에 `## Migration` 섹션(경로·환경별 체크박스·롤백) 필수
- **배포 검증**: 부팅 로그 `successfully started` · 컨테이너 STATUS · 신규 라우트 401

## 7. 리스크

| ID | 리스크 | 대응 |
|---|---|---|
| R-1 | 세션 캐시(30초)로 별칭이 늦게 반영 | 저장 시 캐시 무효화(S1), 목록은 캐시를 타지 않음 |
| R-2 | "세션"이라는 UI 표기가 실제로는 대화 id | 이번에 `sessionId`를 함께 노출해 구분 가능하게 함. 표기 통일(대화/세션 용어 정리)은 범위 밖 — 별도 과제로 남김 |
| R-3 | 미리보기가 감사 로그를 늘림 | 의도된 동작(열람은 열람). 보드에서 무심코 열지 않도록 모달은 클릭 시에만 조회 |
