# REQ-260824-Login-Password-Lock-Reset

- 작성일: 2026-08-24
- 요청: "비밀번호 잠금 해제 리셋"
- 대상: 테넌트 콘솔 사용자 계정 및 플랫폼 관리자의 테넌트 사용자 관리
- 관련: `apps/api/src/domain/auth/login-rate-limit.service.ts`, `apps/api/src/domain/user/user.service.ts`

## 1. AS-IS

사용자 로그인은 계정별 실패 5회 또는 IP별 실패 20회에 도달하면 Redis에서 15분 동안 차단한다.

```text
login:fail:acct:user:<email>  -> 5회 이상이면 E1008 / HTTP 429
login:fail:ip:user:<ip>       -> 20회 이상이면 E1008 / HTTP 429
```

팀 관리자는 `POST /users/:id/temp-password`로 임시 비밀번호를 발급할 수 있다. 이 기능은
비밀번호 해시를 새 값으로 바꾸고 `must_change_password=1`로 설정하며 감사 로그를 남긴다.
그러나 계정별 로그인 실패 카운터는 그대로 남는다. 따라서 비밀번호를 재설정해도 잠긴
사용자는 최대 15분 동안 새 임시 비밀번호로 로그인할 수 없다.

`/ivyusa`의 로그인 실패는 계정/비밀번호 거부(401) 뒤 계정 잠금(E1008, 429)으로 전이된
상태로 확인됐다. API health는 200이므로 서버 장애가 아니다.

## 2. TO-BE

권한 있는 운영자가 기존 "임시 비밀번호 발급"을 수행하면 다음을 하나의 복구 동작으로 처리한다.

1. 정책을 만족하는 일회성 임시 비밀번호를 발급한다.
2. 대상 사용자 계정의 `login:fail:acct:user:<email>` 카운터를 삭제한다.
3. 기존처럼 첫 로그인 뒤 비밀번호 변경을 강제한다.
4. 기존 `user.temp_password_issued` 감사 로그를 남긴다.

임시 비밀번호는 응답에서 한 번만 보이고, 운영자는 승인된 별도 채널로 사용자에게 전달한다.

로그인 보호 정책을 다음과 같이 변경한다.

```text
login:fail:acct:user:<email>  -> 10회 이상이면 E1008 / HTTP 429
login:fail:ip:user:<ip>       -> 20회 이상이면 E1008 / HTTP 429
Redis 실패 카운터 TTL              -> 10분
```

## 3. 범위와 보안 경계

| 항목 | 포함 여부 | 이유 |
|---|---:|---|
| 테넌트 사용자 계정 비밀번호 재설정 + 계정 잠금 해제 | 포함 | 현재 복구 흐름의 누락을 보완한다 |
| 플랫폼 관리자의 테넌트 사용자 재설정 | 포함 | 동일 `UserService` 경로를 사용한다 |
| IP 기반 잠금 해제 | 제외 | 공유 IP의 brute-force 보호를 관리자가 임의로 우회하면 안 된다 |
| 관리자(`/auth/admin/login`) 계정 재설정 | 제외 | 현재 임시 비밀번호 발급 대상이 tenant user뿐이며, 별도 복구 정책이 필요하다 |
| IP 실패 한도(20회) 변경 | 제외 | 공유 IP의 brute-force 보호를 유지한다 |
| 새 비밀번호를 이메일/SMS로 자동 전송 | 제외 | 민감정보 전달 채널과 수신 확인 설계가 별도로 필요하다 |

계정 잠금만 해제하므로 동일 IP가 IP 한도에 걸린 경우에는 계속 E1008이 반환될 수 있다. 이
경우 보호 우회가 아니라 15분 만료를 기다리거나 네트워크 운영자가 별도 조사해야 한다.

## 4. 사용자 흐름

```text
Master/Director 또는 System Admin
  -> 팀 사용자 목록에서 대상 선택
  -> 임시 비밀번호 재설정 확인
  -> 새 임시 비밀번호 1회 표시 + 계정 실패 카운터 삭제
  -> 승인된 별도 채널로 비밀번호 전달
  -> 사용자는 즉시 로그인 후 비밀번호 변경
```

## 5. 수용 기준

| ID | 기준 |
|---|---|
| AC-1 | 계정별 실패 한도는 10회, Redis 실패 카운터 TTL은 10분으로 적용된다. IP 실패 한도는 20회로 유지된다. |
| AC-2 | 권한 있는 사용자가 임시 비밀번호 발급을 완료하면 해당 tenant user의 계정별 실패 카운터가 삭제된다. |
| AC-3 | 새 임시 비밀번호 로그인은 `mustChangePassword=true`를 반환하고, 비밀번호 변경 전 보호된 라우트에 접근할 수 없다. |
| AC-4 | 대상 계정과 다른 테넌트의 계정은 재설정하거나 잠금 해제할 수 없다. |
| AC-5 | IP 기반 카운터는 삭제하지 않으며, IP 한도 상태는 계속 429를 반환한다. |
| AC-6 | 재설정은 기존 감사 이벤트 `user.temp_password_issued`를 남기고 평문 비밀번호를 로그에 기록하지 않는다. |
| AC-7 | 웹 콘솔은 성공 시 임시 비밀번호의 1회 표시와 명시적 성공 피드백을 유지한다. |
