## 1. 단계별 계획

### S1. 상태회신 발행 (native 테넌트, 백엔드)
- `IssueService` 전이 지점(생성/진행/해결/반려/종료/재오픈)에서 기존 알림 버스(`EVENTS.NOTIFICATION`)로
  고객 알림 발행 — **기존 알림 인프라(인앱+웹푸시, 채널 선호 반영) 전면 재사용, 신규 채널 없음**.
- 전이별 템플릿(EN/ES/KO 내장, REQ §5.4):
  | 전이 | 안내 |
  |---|---|
  | 접수(생성) | "문의가 접수되었습니다 (#N). 확인 중입니다." |
  | 진행/배정 | "담당자가 배정되어 처리 중입니다 (#N)." |
  | 해결 | "문의가 해결되었습니다 (#N)." (+resolution_note 있으면 첨부) |
  | 반려 | **사유별 문구**(정책상 불가/오분류/스팸 — 결정 3) + 대안 안내 |
  | 종료 | "처리가 완료되었습니다 (#N)." |
  | 재오픈 | "문의를 다시 확인하고 있습니다 (#N)." |
- 언어 = 세션 language(이슈 모듈에 Session repo 추가). 이관/배정 내부 이벤트는 고객 알림 제외(소음 방지).
- email: `replyChannel='email'` 대화의 해결/반려 시에만 기존 off-hours 메일러 경로 재사용(결정 6). SMS 없음.

### S2. 위젯 — 문의(이슈) 피드
- **공개 API** `GET /issues`(@Public, 세션 토큰): 세션 스코프 이슈 목록
  `[{issueNo, type, status, rejectReason, updatedAt}]` — 게스트 세션 포함(이슈는 세션 단위), 응답은 위젯이 i18n.
- 위젯 주문 탭 **'문의' 서브탭 개편**: 세션에 이슈가 있으면 **이슈 피드**(아래), 없으면 기존 주문 필터 유지(비-native 테넌트 무영향).
```
│ [결제] [배송] [문의*]                        │  * 뱃지: 진행중 이슈 수
│ ┌──────────────────────────────────────┐   │
│ │ #37 · 환불 문의            [진행중]    │   │
│ │ 담당자가 배정되어 처리 중입니다.        │   │  ← 상태별 안내문(i18n)
│ │ 2026-08-09 14:02                      │   │
│ ├──────────────────────────────────────┤   │
│ │ #35 · 배송 문의            [해결]      │   │
│ └──────────────────────────────────────┘   │
```
- 상태 변화 알림 자체는 기존 알림 탭+웹푸시로 자동 표시(S1) — 위젯 신규 폴링 없음(피드는 탭 진입 시 조회).

### S3. Gorgias L2 — 상태 회신 웹훅 (bridge 테넌트)
- SQL `sql/260809-issue-p3.sql`: `external_tickets ADD COLUMN status VARCHAR(16) NOT NULL DEFAULT 'open'`.
- `INTEGRATION_FIELDS.gorgias`에 `webhook_secret`(secret, optional) 추가 — 웹훅 인증 토큰.
- `POST /webhooks/gorgias`(@Public): 헤더/쿼리 토큰 = 저장된 webhook_secret 검증(불일치 401+warn) →
  payload의 ticket id/status로 `external_tickets` 매칭 → status 갱신,
  **closed 전이 시** 고객 알림 "문의 처리가 완료되었습니다"(S1 인프라 재사용).
  재-에스컬레이션(결정 12): ref status='closed'면 **append 대신 신규 티켓 생성**으로 L1 동작 보완.
- Gorgias 측 HTTP Integration(ticket-updated) 수동 설정 가이드 → `docs/guide/GORGIAS-CONNECTOR.md`.

## 2. 사이드 임팩트
| 영역 | 영향 | 판단 |
|---|---|---|
| 알림 | 기존 NOTIFICATION 버스·선호 채널 로직 재사용 — 신규 채널/스키마 없음 | 안전 |

## 3. 테스트/배포
- 단위: 전이→템플릿/언어/반려 사유별, 게스트 세션 피드 스코프, 웹훅 토큰 검증·closed 알림·closed 후 재에스컬=신규 생성.
- 스테이징: SQL 선적용 → 배포. E2E: amoebaorder deny 규칙 → 이슈 전이마다 위젯 알림+문의 서브탭 상태 변화 확인.
- Gorgias L2 실검증은 실 계정 등록 후(E5와 함께).
