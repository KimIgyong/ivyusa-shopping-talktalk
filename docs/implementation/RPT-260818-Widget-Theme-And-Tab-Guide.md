## 2. 설계에서 중요한 판단 4가지

### 2.1 색을 CSS 변수로 내렸다 — 번들은 그대로 하나
Tailwind 클래스는 빌드 시점에 hex로 굳는다. 전 테넌트 공용 번들 하나로 다른 색을 내려면
변수화가 유일한 길이었다. 채널 삼중값(`R G B`)을 쓴 이유는 `bg-primary-500/10` 같은
**알파 표기가 4곳** 있어서다 — hex를 변수에 넣으면 그 표기가 깨진다.

### 2.2 전경색을 고를 수 없게 만들었다
`primary-500` 위에는 흰 글씨가 올라간다. 테넌트가 노랑을 고르면 **읽을 수 없는 버튼**이
만들어진다. 그래서 전경색은 입력이 아니라 산출이다.

### 2.3 그런데 "대비 높은 쪽"은 디자인과 충돌했다 — 구현 중 발견
처음엔 흰/검 중 대비가 높은 쪽을 고르게 짰다. 그런데 **디자인 파랑(#2B7FFF) 위에서는
검정이 4.67:1로 흰색(3.76:1)을 이긴다.** 규칙대로면 기본 테마의 버튼 글씨가 검정으로
뒤집혀, 승인된 디자인이 조용히 바뀐다.

→ 규칙을 **"흰색을 쓰되 3:1 밑으로 떨어지면 잉크"** 로 바꿨다. 3:1은 WCAG의 UI 컴포넌트
   기준이며, 본문 텍스트 기준 4.5:1이 아니다. 이건 **의도적 절충이고 문서화했다**:
   중간 명도 브랜드는 3~4.5 구간에 들어갈 수 있다(D-10과 같은 계열).

### 2.4 램프 곡선을 브랜드 명도에 맞춰 이동시켰다 — 구현 중 발견
500만 입력값 그대로 두자 **어두운 브랜드에서 600이 500보다 밝아졌다.** 위젯의 모든 hover가
어두워지는 대신 밝아지는 상태다. 곡선 전체를 브랜드 명도만큼 이동시켜 단조성을 회복했다
(테스트 U-8이 이 회귀를 잡는다).

## 3. 요구 2 — 문서만으로는 부족했다

경로 자체는 있었다. 문제는 **카드 이름이 "위젯 동작"**, 설정이 카드 중간, 페이지에 카드 9개.

## 8. 코드리뷰(CodeRabbit, PR #308) 반영

19건 중 코드 6건 + 문서 4건 반영. 문서 전용 지적 나머지는 서술 보완이라 생략.

| # | 지적 | 판정 | 조치 |
|---|---|---|---|
| R-1 | **계산된 `--ivy-on-primary`를 컴포넌트가 안 쓴다** | ⭐ 유효·최대 | 위젯 전역에서 `bg-primary-*` 위 `text-white` **14곳**을 `text-on-primary`로 교체. 이게 없으면 자동 대비 기능 전체가 무효(노란 브랜드에서 흰 글씨 1.43:1) |
| R-2 | 본문 텍스트 대비는 3:1이 아니라 4.5:1 | 유효 | `MIN_ON_PRIMARY_CONTRAST` 3 → **4.5**. 기존 근거("4.5면 기본 위젯이 뒤집힌다")는 R-1 수정 전 잘못된 전제 — 미설정 테넌트는 이 함수를 타지 않는다. 중간 명도(L≈18%)에선 흰색·잉크 둘 다 4.47에서 막혀 **검정을 최후 후보로 추가**(모든 배경에 대해 최소 4.58 보장) |
| R-3 | 헤더 아이콘 `/60` 감광이 대비를 다시 깎음 | 유효 | `--ivy-header-dim` 변수화 — 흰 헤더는 0.6 유지(디자인), 브랜드 헤더는 1 |
| R-4 | 극단색에서 램프 역전(`#000`·`#FFF`) | 유효 | 클램프 2..98 → **0..100**, 단조성 회귀 테스트 추가 |
