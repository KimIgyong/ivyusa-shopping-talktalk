# 실전 교훈 카탈로그 (Lessons Learned)

> **버전**: 1.0 (2026-07-30)
> AMA 프로젝트에서 실제 발생한 장애·함정을 **증상 → 원인 → 재발 방지** 형식으로 정리한 카탈로그.
> 일반화된 규칙은 01~04 표준 문서에 이미 반영되어 있다. 이 문서는 **디버깅 시 유사 증상 매칭용** 사례집이다.

---

## A. 배포/인프라

### A-1. 스테이징 배포 후 전면 502 (API 무한 재시작)
- **증상**: 배포 exit 0, 그러나 외부 전 경로 502. `docker ps`에서 API 컨테이너 `Restarting`.
- **원인**: 엔티티 신규 컬럼을 `string | null` TS 타입 + `type` 미지정으로 추가 → TypeORM `Object` 추론 → DataSource 초기화 실패. `tsc`는 통과했음.
- **재발 방지**: 유니언 타입 컬럼 `type` 명시 MUST + 배포 전 실부팅 확인. 판별 조견: **502=API 죽음, 404=미배포, 401=정상 서빙**.

### A-2. 배포했는데 옛 코드가 돈다
- **원인 3종**: ① 프로덕션 deploy는 production 브랜치를 빌드(main만 머지된 코드는 미반영) ② 서버 작업 트리의 미커밋 핫픽스로 `git pull` abort → 스크립트는 exit 0 ③ 빌드 실패했지만 기존 컨테이너가 계속 동작.
- **재발 방지**: 배포 검증 3종 세트 — 컨테이너 나이(`docker ps` STATUS) + 신규 라우트 401/404 + 번들 grep. (04 문서 §4)

### A-3. deploy exit 1인데 실제로는 정상
- **원인**: 시드 서비스로 부팅이 길어 헬스체크 창 초과. 빌드/기동은 이미 성공.
- **재발 방지**: exit code 대신 `Nest application successfully started` 로그 + 웹 curl 200으로 판정. 스크립트 헬스체크 창 확대.

### A-4. 배포 후 특정 API만 500 — "relation does not exist"
- **원인**: 배포 스크립트가 SQL 마이그레이션을 자동 실행하지 않음 + PR에서 적용 계획 누락.
- **재발 방지**: 스키마 PR `## Migration` 섹션 MUST(03 §3.3) + 마이그레이션 선적용 런북(04 §3) + pre-deploy-check 스킬.

### A-5. Docker 빌드 실패 (캐시 prune 후 / 디스크 고갈)
- 04 문서 §5 참조. bcrypt/python, ENOSPC 3회 재발, ECONNRESET.

### A-6. 메일 서버 관리 API 전면 502 (서비스는 정상)
- **원인**: fail2ban이 Docker 게이트웨이 IP(172.20.0.1)를 포트스캔으로 오인해 무기한 차단. 리버스 프록시 경유 관리 API만 죽고 SMTP/IMAP 직결은 정상이라 원인 은폐.
- **재발 방지**: fail2ban류 도입 시 Docker 게이트웨이 IP를 AllowedIp 선등록. 해소는 차단 destroy + allowlist + 컨테이너 재시작까지 해야 완결.

### A-7. 스테이징 SSL 만료 방치
- **재발 방지**: 인증서 만료 모니터링을 헬스체크 항목에 포함(-106일까지 방치된 사례).

## B. DB/TypeORM

### B-1. submit 500 — duplicate key (문서번호)
- **원인**: 번호 생성은 법인별 시퀀스인데 유니크 제약은 전역 단일 컬럼 → 타 법인 간 충돌. 부가로 `count+1` 방식은 삭제 공백 시 충돌.
- **재발 방지**: `(ent_id, number)` 복합 유니크 + 최대 시퀀스+1.

### B-2. insert 시 FK가 NULL로 저장
- **원인**: 동일 FK 컬럼에 `@Column` + `@ManyToOne/@JoinColumn` 중복 매핑, 저장 시 관계 미지정.
- **재발 방지**: 중복 매핑 금지 또는 저장 시 관계 명시(01 §3.4-2).

### B-3. 삭제 API 500 — cascade
- **원인**: `softRemove(entity)`가 로드된 관계(반복일정 등)에 cascade.
- **재발 방지**: `softDelete(id)` 사용.

### B-4. psql heredoc 조용한 무실행
- **원인**: `ssh + docker exec`(non-`-i`) + heredoc → stdin 미전달, UPDATE 0에 에러도 없음.
- **재발 방지**: `docker exec -i` 또는 `-c "단일 CTE"`. 실행 후 영향 행 수 확인.

## C. 인증/멀티테넌시/권한 디버깅

"사용자 X가 법인 Z에서 안 됨" 류 조사 시 3대 함정:

### C-1. 이메일당 다중 계정
한 이메일에 법인별 별도 사용자 행 존재. 반드시 **해당 법인 계정의 usr_id + 그 계정의 역할**을 조회(홈 법인 계정 보고 오판 금지).

### C-2. 4xx는 로그에 없다
예외 필터가 500+만 기록. "로그에 에러 없음 ≠ 성공." 프론트가 4xx를 조용히 삼키면 사용자는 "그냥 실패"로 인지 → 프론트 에러 표출 + 가드 warn 로그 확인.

### C-3. 어드민엔 보이는데 로그인 불가 (EMAIL_NOT_FOUND)
로그인과 어드민 목록이 **서로 다른 정본**(users 테이블 vs 역할 테이블)을 봄. 역할만 있고 사용자 행이 없는 케이스. 해결: 사용자 행 복제 + 역할 재연결(원자적 CTE). 근본 방지: 역할 부여와 사용자 행 생성을 원자화(02 §2.2-3).

### C-4. 테마가 사용자별로 다르게 보임
darkMode 미설정 시 기본 `'media'`(OS 설정) — 코드상 법인/사용자별 테마 차이는 불가능. `dark:` 커버리지 불완전 페이지가 OS 다크에서 깨져 보이는 것.

## D. 외부 연동

### D-1. AI 전 기능 전역 중단 (2026-06-17)
- **원인**: 하드코딩 모델 ID 은퇴 → API 404. 키/한도는 전부 정상.
- **진단 함정**: 어드민 연결테스트는 다른 모델로 호출 → 테스트 통과 ≠ 런타임 정상. 런타임 키는 DB 공유키 1순위, env 폴백 — 우선순위를 모르면 미궁.
- **재발 방지**: 모델 ID env 오버라이드 + 업스트림 4xx 관리자 알림.

### D-2. 결제 API 401 — 더미 자격증명
- **원인**: 운영 DB에 저장된 토큰이 실토큰이 아닌 더미 패스워드값. **last4 힌트 컬럼이 실제 복호화값과 불일치**해 "설정됨"으로 오판 유발.
- **재발 방지**: 토큰 입력 시 형식 검증(prefix/길이). 진단은 반드시 복호화 검증. 웹훅 서명 검증은 제공사 SDK 실구현 기준으로(문서 추정 구현 금지).

### D-3. 메일 폴더 동기화 19,000회 실패
- **원인**: IMAP 폴더명 `Sent`/`Trash` 하드코딩 ↔ 실서버 `Sent Items`/`Deleted Items`.
- **재발 방지**: special-use 플래그로 해석. 외부 리소스 명칭 하드코딩 금지(01 §3.6).

### D-4. BullMQ 도입 함정
큐 이름에 `:` 금지, Worker `maxRetriesPerRequest=null` 필수.

### D-5. 외부 API 스키마는 PoC로 확정
Stalwart MailingList의 recipients 형식이 문서 추정(`members[]` 배열)과 실제(`{email:true}` 맵)가 달랐음 — 로컬 PoC로 실스키마 확인 후 구현.

## F. 신규 프로젝트에서 우선 차단할 Top 10

3. 스키마 PR에 마이그레이션 계획 누락 (운영 500)
4. `docker compose build` 직접 실행 (VITE 인라인 오염)
5. 프로덕션 배포 전 main→production PR 누락 (미반영 배포)
6. 배포 검증을 exit code로만 판단
7. Dockerfile deps에 네이티브 빌드툴 누락
8. AI 모델/외부 리소스 명칭 하드코딩
9. 저장 성공 조용한 처리 (UX 규칙 위반)
10. 스테이징 `synchronize: true` 방치
