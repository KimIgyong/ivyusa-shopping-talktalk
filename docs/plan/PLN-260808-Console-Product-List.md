## 2. 구현

### P1. 백엔드 — 콘솔 조회 API
`ProductAdminController` (기존 파일)에 추가:

| 라우트 | 설명 |
|---|---|
| `GET /admin/products` | `q`(상품명·태그) · `category` · `status` · `page` · `size` → `Paginated<AdminProductResponse>` |
| `GET /admin/products/summary` | `{ total, active, archived, withKnowledge, lastSyncedAt }` |

- 게이트: `@RequireCapability(CAPABILITY.MODULE_OPERATIONS)` — 기존 sync 라우트와 동일.
- **정적 라우트 `summary`는 `:handle` 류보다 위**(현행 컨트롤러에 경로 파라미터는 없지만 순서 규칙 유지).
- 서비스: `ProductService.adminList(tenantId, filters, page, size)` / `adminSummary(tenantId)`.
  기존 고객용 `list()`는 `status='active'` 고정이라 재사용 불가 — **보관 상품이 보여야 하는 화면**이다.
- 지식 연결: 페이지의 handle 집합으로 `kb_documents`를 **한 번에** 조회(`In(handles)`, `doc_group='product'`) → handle→boolean 맵. 행마다 조회하면 N+1.
- 응답 매퍼: `toAdminProductResponse`(camelCase) 신설. 고객용 카드 응답과 필드가 다르다(상태·동기화 시각·지식 여부 포함).

### P2. 프런트 — 화면
`apps/web/src/domain/products/`
- `products.service.ts` — `apiGetList<AdminProduct>('/admin/products', params)`, `apiGet<ProductSummary>('/admin/products/summary')`
- `products.hooks.ts` — React Query, 키에 `tenantId` 포함(멀티테넌시 규칙)
- `ProductsPage.tsx` — 요약 카드 + 필터 + 표 + 페이지네이션 + 빈 상태
- 라우트 `/products`(AppLayout 하위), 사이드바 항목을 **지식 다음**에 배치(`capability: 'knowledge'` — 상품→지식 파이프라인을 보는 화면이라 같은 그룹)
- i18n: 신규 네임스페이스 `products`(en/es/ko) 등록. **하드코딩 텍스트 없음**

### P3. 테스트
- `product.service.spec.ts` 보강: 상태 필터(보관 포함 여부), 검색이 제목·태그 both, 카테고리 필터, **다른 테넌트 행 미노출**, 요약 집계.
- 지식 매칭 맵이 handle 기준으로 정확한지(등록/미등록 혼재).

## 2-1. 증분: 상세보기 + 목록 100자 요약 (요청 2026-08-08)

목록에 상품 내용이 아예 없었고(태그 줄만), 한 행의 본문을 읽을 방법도 없었다.

```
목록 (요약 100자, 2줄 clamp)
┌────────────────────────────────────────────────────────────────────┐
│ [img] 벨라뷰티 소프트 메이크업 브러시 세트   │ 소품 │ ₩25,000 │…│
│       Sample Product Generated by AI 본 상품은 AI로 생성된 샘플…   │
└────────────────────────────────────────────────────────────────────┘
      │ 행 클릭
      ▼
┌ 상품 상세 ─────────────────────────────────────────────── [✕] ┐
│ ┌──────┐  [판매중] [지식 등록됨]                               │
│ │ 이미지│  ₩25,000                                             │
│ │      │  쇼핑몰에서 열기 ↗                                    │
│ └──────┘                                                       │
│ ─────────────────────────────────────────────────────────────  │
│ 카테고리   소품                                                │
│ 태그       소품, Free                                          │
│ SKU        P00000BH                                            │
│ 키         cafe24-33          ← 지식 문서가 파일링되는 키       │
│ 등록일     2026-07-01 / 마지막 동기화  2026-08-08 15:32        │
│ ─────────────────────────────────────────────────────────────  │
│ 상세 내용                                                      │
│ Sample Product Generated by AI 본 상품은 AI로 생성된 샘플…(전문)│
└────────────────────────────────────────────────────────────────┘
```

- **다이얼로그**(라우트 아님): 목록을 훑다가 한 행의 본문만 보려는 동작이라, 이동했다 돌아올 장소가 필요하지 않다.
- **요약은 서버에서 자르고, 목록 응답에서 전체 description을 뺐다** — 20행 페이지가 두 줄 렌더하자고 상품 본문 20개를 실어 보내고 있었다. 전문은 그것을 요구하는 상세가 가져간다.
- 자르기는 단어 경계 우선, 단 **한계의 마지막 40% 구간의 공백만** 인정한다. 한국어 문구는 100자 안에 공백이 없는 경우가 흔해 앞쪽 공백을 존중하면 요약 대부분이 날아간다.
- `GET /admin/products/:handle` 는 **정적 라우트 뒤에** 등록(`summary`/`categories` 가림 방지).
- 상세에 `handle`을 노출한다 — 지식 문서가 파일링되는 키라, 상품과 문서가 어긋났을 때 필요한 조인 키다.

## 3. 사이드 임팩트

| 대상 | 영향 | 판단 |
|---|---|---|
| 스키마 | 변경 없음 | 마이그레이션 불필요 |
| 위젯 `GET /products` | 무수정 | 고객 경로 불변 |
| 권한 모델 | 신규 capability 없음 | 기존 `module.operations` 재사용 |
| 사이드바 | 항목 1개 추가 | 기존 gating 규칙 그대로 |

## 4. 리스크

| 리스크 | 대응 |
|---|---|
| 대형 카탈로그(ivyusa 2,275건)에서 느림 | 페이지네이션 필수, 지식 조회는 페이지 handle 한정 1회 |

| 몰 링크가 외부 도메인 | 기존 `productLinkFor` 게이트와 동일한 판단 — storefront 오리진이 아니면 링크 비활성 |
