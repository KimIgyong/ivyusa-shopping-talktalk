## 1. 목적 재정의 (사용자 비전)

위젯 채팅은 **브라우저 밖/로그아웃 상태의 고객에게 닿지 못한다** — 이 갭은 앱/PWA 푸시로
해결됐다(주문·배송·상담·이벤트 푸시 스테이징 가동). 이번 재점검의 비전은 그 위에
**커뮤니케이션 중심 고객앱**을 완성하는 것이다:

- 구매는 모바일웹/ivyusa.com(Shopify)에서. 앱은 **확인과 커뮤니케이션이 주목적**.
- 앱에서 할 수 있어야 하는 것: 내 주문·배송 확인(✅있음) · 신제품/프로모션/이벤트 소식
  수신(부분) · **상품 목록/정보 보기(없음)** · **AI 추천 상품(부분)** · **찜하기 ·
  담아두기 · 조르기 · SNS 홍보 · 쇼핑 다이어리 · 리뷰 쓰기(위젯에만 있음)** · 바로 샵 방문(✅).

## 2. 현재 구현 재점검 (2026-08-07, origin/main 72d5f59 기준)

### 2.1 이미 갖춰진 것
| 영역 | 상태 |
|---|---|
| RN 앱(apps/mobile) | 5탭: 쇼핑(WebView+아이덴티티 브리지)/상담/주문/알림/설정, 푸시(Expo), 카테고리 딥링크, en/es/ko |
| PWA(apps/pwa) | /app/ 라이브: 상담/주문/알림/설정, Web Push(VAPID), 설치 UX |
| 푸시 파이프라인 | 주문·배송(웹훅 4종 LIVE, PCD 승인 완료)·상담 답변·캠페인(event) → pref/옵트아웃 게이트 → Expo/WebPush, 무효 토큰 자동 revoke |
| 상품 지식 | KB `doc_group='product'` + **CSV 임포트**(Handle 키, 5천행) + 스토어프론트 URL 검증된 **채팅 인용 상품링크**(🛍) — PR #101/#104/#106/#114 |
| 리뷰 | `POST /reviews`(주문 아이템 단위, 별점+텍스트) — **위젯 UI만** 존재 |
| 재입고 알림 | `POST /restock/subscribe` API 존재 — **어떤 클라이언트도 미사용** |
| 어필리에이트 | 신청/승인 + link_code 발급 — 공유 URL 빌더/어트리뷰션 없음 |
| CJM | `cjm_events` 존재하나 이벤트 3종뿐(session_start/chat_message/review_submitted), payload 미사용, 고객용 조회 없음 |

### 2.2 비전 기능별 갭 (핵심 표)

| # | 비전 기능 | 현재 | 갭 |
|---|---|---|---|
| V1 | 상품 목록/상세 보기 | **전무** — products 테이블·고객용 API·UI 없음. KB product 문서는 관리자 전용+이미지/가격 없음 | 카탈로그 데이터 소스 + 고객 API + 앱 UI 전부 신규 |
| V2 | AI 추천 상품 | 채팅 답변 안의 인용 링크뿐 (RAG group-bias). 추천 전용 함수/개인화/카드 UI 없음 | 추천 피드 API + 앱 카드 UI |
| V3 | 찜하기(wish) | **전무** | 신규 엔티티+API+UI |
| V4 | 담아두기(save) | **전무** (유사 형태: restock_subscriptions의 customer↔product_id 행) | V3와 통합 설계 가능 |
| V5 | 조르기(nudge) | **전무** | 공유 카드/링크 + 기록 |
| V6 | SNS 홍보하기 | **전무** — affiliate link_code는 미소비 8자 코드 | 공유 시트 + (어필리에이트) URL 빌더 |
| V7 | 쇼핑 다이어리 | **전무** — CJM은 Browse/Purchase/Delivery 이벤트 미발행, 고객용 타임라인 없음 | CJM 확장 + 고객 타임라인 API + 화면 |
| V8 | 리뷰 쓰기 | API+위젯만. **앱/PWA에 UI 없음** | 앱 리뷰 UI (+아래 결함 보완) |
| V9 | 신제품/프로모션 푸시→바로가기 | 캠페인 푸시는 감. **링크/상품 참조가 스키마·페이로드·라우팅 어디에도 없음** (category 라우팅뿐) | campaigns.content 링크 필드 → notifications.link → push data.url → 앱 라우팅 |
| V10 | 바로 샵 방문 | ✅ RN WebView / PWA 새 탭 | 상품 상세→해당 상품 구매 페이지 딥링크만 추가 |

### 2.3 재점검에서 발견된 결함 (비전과 별개로 보완 필요)
| # | 결함 | 위험 |
|---|---|---|
| D1 | `POST /reviews`가 **order_item 소유권을 검증하지 않음** (OrderItem repo 주입만 되고 미사용) — 타인 주문 아이템에 리뷰 작성 가능 | 보안/무결성 (앱 노출 확대 전 필수 수정) |
| D2 | 리뷰 본문 **모더레이션 미적용** (status 하드코딩 'submitted', 승인 흐름 없음) — 캠페인은 게이트 통과하는데 리뷰는 비게이트 | 정책 일관성(FR-069 정신) |
| D3 | 리뷰 **관리 콘솔 UI 없음** (GET /admin/reviews만 존재) | 운영 불가 |
| D4 | restock API 데드 코드 (UI 미연결, 재입고 발송 로직 없음) | V3/V4 설계에 흡수 권장 |

## 3. 제약 (설계를 결정짓는 사실)

| # | 제약 | 영향 |
|---|---|---|
| C1 | **`read_products` 스코프 미보유** — Admin GraphQL로 상품 조회 불가(코드 주석에 명시), products/* 웹훅 없음. Storefront API 클라이언트도 전무 | 카탈로그 도입 = 스코프 추가(재인가) 또는 Storefront API 신규. CSV만으로는 이미지/가격 미보유 |
| C2 | KB product CSV는 **가격을 의도적으로 제외**(벡터 인덱스 신선도), 이미지 없음 | KB 문서는 "추천 지식"이지 카탈로그가 아님 — 표시용 데이터는 별도 필요 |
| C3 | 클라이언트가 **RN+PWA 2벌** (공유 코드 없음) | 모든 신규 화면이 이중 구현 — 우선순위 명시 필요 |
| C4 | 캠페인 `segment_ref` 미사용(전 고객 발송), content는 텍스트만 | 신제품 타겟팅·상품 딥링크 모두 신규 |
| C5 | 앱 아이덴티티: verified는 RN WebView 브리지 경유, PWA는 게스트 조회 | 찜/다이어리 등 개인화 기능은 고객 바인딩 후 활성 (기존 패턴 재사용) |

## 4. 결론

푸시·주문·상담이라는 "통지 인프라"는 완성됐고, 비전의 나머지 절반인
**상품 발견(카탈로그·추천)과 인게이지먼트(찜/담기/조르기/공유/다이어리/리뷰)**가 갭이다.
공통 선행 조건은 **고객용 상품 카탈로그**(V1) — V2~V6, V9가 전부 상품 참조를 전제한다.
개선안(단계·설계·와이어프레임)은 `docs/plan/PLN-260807-IvyusaApp-Revamp.md`.
