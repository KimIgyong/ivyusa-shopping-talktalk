# FIX — "An agent is writing a reply…" 무한 대기 + 상품 링크 소실 (2026-08-06)

## 1. 증상

1. 위젯에 `십대 남자용 스킨케어 제품 추천해줘` 입력 → **"An agent is writing a reply…" 상태로 멈춤**
   (답변 영영 오지 않음).
2. (기확인) AI 상품추천의 상품페이지 링크가 답변 직후 ~5초만 보이고 사라짐.

## 2. 근본 원인 (스테이징 로그·DB 증거)

대화 82번 실제 타임라인 (`messages`, `conversations` 조회):

| 시각 | 메시지 | 처리 |
|---|---|---|
| 07:04:36 | user "please recommend me, my skin is oily" | intent `product_recommendation` 0.95 → **AI 정상 답변 + 상품 URL 인용**(`ivyusa.com/products/...`) |
| 07:06:26 | user "thanks, and recomend my young son." | intent 0.78이나 **RAG 검색 신뢰도 < 0.45** → 자동 핸드오프(`low_confidence`) → `status=waiting`, `escalated=1` |
| 07:09:19 | user "십대 남자용 스킨케어 제품 추천해줘" | **봇이 의도적으로 침묵**(FR-S4: waiting/agent 상태에선 무응답) — `intent`/`retrieval_trace` 모두 NULL = **처리 자체를 안 함** |

즉 멈춘 원인은 이 질문의 실패가 아니라 **직전 메시지에서 이미 상담사 대기 상태로 전환**된 것.
질문 자체는 처리 대상에서 제외됐다.

추가 확인:
- `agent_profiles` **0건** — 스테이징에 상담사가 한 명도 등록돼 있지 않음. 미처리 알림 2건.
  → 대기열에 들어가면 **아무도 받지 않아 영구 대기**.
- 위젯(PR #107)이 `waiting`을 "담당자가 답변을 작성 중"으로 표시 → 아무도 작성하지 않는 상태를
  곧 답이 올 것처럼 보이게 함(표시 결함).
- 에스컬레이션을 유발한 "thanks, and recomend my young son."은 **맥락 의존 후속 질문** —
  RAG는 직전 대화를 참조하지 않고 이 문장만으로 검색하므로 유사도가 바닥.

## 3. 이번 수정 (배포됨)

1. **대기 상태 표시 정정** (`TypingBubble`, `ChatTab`):
   - `sending`(AI 요청 중) → 점 애니메이션 "답변을 작성 중입니다…"
   - `status=agent`(상담사가 수락함) → 점 애니메이션 "담당자가 답변을 작성 중입니다…"
   - `status=waiting`(대기열, 담당자 미배정) → **정적 시계 아이콘 + "상담사 연결을 기다리는 중입니다.
     답변이 등록되면 여기에 표시됩니다."** — 애니메이션/오해 제거 (en/es/ko)
2. **상품 링크(citations) 영속화**: `ChatMessageResponse.citations` 추가,
   `ChatMapper`가 저장된 turn의 `retrieval_trace.citations`를 함께 반환.
   위젯 `reconcile`도 인용을 보존. → 폴링 후에도, 새로고침 후에도 🛍 상품 링크 유지.

## 4. 개선안 (승인 필요 — 미구현)

| # | 제안 | 효과 / 비고 |
|---|---|---|
| A1 | **대기 중에도 AI가 계속 답변** — 상담사가 수락(`agent`)하기 전까지는 봇이 답하고, 수락 후 침묵 | 이번 증상(질문했는데 무응답)의 근본 해소. 현재 "waiting=침묵" 정책 변경이라 승인 필요 |
| A2 | **RAG 후속 질문 맥락 반영** — 직전 2~3턴을 검색 쿼리에 합성 | "my young son"/"십대 남자용" 같은 맥락 의존 질문의 오검색·오에스컬레이션 방지 |
| A3 | **운영: 상담사 배치 또는 오프아워 이메일 라우팅 설정** | 현재 상담사 0명 → 대기열이 곧 막다른 길. 라우터는 이미 이메일 모드 지원 |
| A4 | **에스컬레이션 임계값(0.45) 재검토** / 상품추천 의도는 상품 KB 재검색 1회 후 판단 | 144개 상품 문서가 있는데 추천 질문이 에스컬레이션되는 빈도 감소 |

권고 순서: **A1 → A3 → A2 → A4** (A1이 체감 문제를 즉시 없앰).

## 5. 예방 패턴

**"대기/진행" UI는 실제로 누군가 작업 중일 때만 진행형으로 표기**한다. 큐에 들어간 상태를
진행형으로 표시하면 사용자는 무한정 기다린다 — 상태 표시는 시스템의 실제 상태(배정 여부)와
1:1로 대응시킬 것. 또한 **응답에만 실리고 저장 응답에는 없는 필드**(citations 사례)는 폴링
동기화 순간 사라진다 — 서버가 이미 저장하고 있다면 조회 응답에도 반드시 포함시킨다.
