  RAG는 직전 대화를 참조하지 않고 이 문장만으로 검색하므로 유사도가 바닥.

## 4. 개선안 처리 결과 (2026-08-06 승인 → A1·A2 구현)

| # | 제안 | 상태 |

| A1 | **대기 중에도 AI가 계속 답변** — 상담사가 수락하기 전까지 봇이 답하고, 수락(`agent` 또는 `agent_id` 배정) 후 침묵 | **구현 완료**. 이미 대기 중인 대화는 저신뢰/모더레이션 차단 시 **재에스컬레이션하지 않음**(중복 알림·중복 안내 방지, 이때만 무응답이며 위젯이 대기 상태를 계속 표시) |
| A2 | **RAG 후속 질문 맥락 반영** | **구현 완료**. 직전 고객 발화 2턴(각 200자)을 **검색 쿼리에만** 합성(모델에는 현재 질문만 전달), PII 스크럽 적용 |

### 4-1. A3 현황 (조치 필요 값)

- `tenant_ai_config.handoff_config` = **NULL**(테넌트 1·2 모두) → 라우터는 항상 "상담사에게 전달"
  모드로 동작하며, 오프아워 이메일 대체 경로가 없음.
- 테넌트 1에 콘솔 사용자 10명(모두 master, 콘솔에서 대화 수락은 가능)이 있으나
  `agent_profiles` **0건** — 상담 배정/가용성 관리 대상이 아무도 등록돼 있지 않음.
- 필요한 결정값: **업무시간·타임존·오프아워 회신 메일함**(선택: 담당자 지정 userIds).
  값을 주시면 콘솔/설정으로 반영 가능. A1 덕분에 그동안도 대화는 끊기지 않음.

### 4-2. A4 재분석 — 임계값 조정은 효과 없음

`RagService.confidence()`는 voyage 임베딩 경로에서 **이분적**이다:
최고 유사도 ≥ `RAG_MIN_SIMILARITY`(스테이징 0.45) → `clamp(best, 0.5..0.95)`, 미만이면 **0.2**.
따라서 `ESCALATION_CONFIDENCE`(0.45)를 0.2~0.5 사이 어디로 옮겨도 결과가 바뀌지 않는다.
실제 손잡이는 `RAG_MIN_SIMILARITY`이며, 이를 낮추면 근거 없는 답변(환각) 위험이 커지므로
계측 없이 조정하지 않았다. A2로 쿼리 품질이 올라가면 유사도 자체가 올라간다.

## 5. 예방 패턴

**"대기/진행" UI는 실제로 누군가 작업 중일 때만 진행형으로 표기**한다. 큐에 들어간 상태를
진행형으로 표시하면 사용자는 무한정 기다린다 — 상태 표시는 시스템의 실제 상태(배정 여부)와
1:1로 대응시킬 것. 또한 **응답에만 실리고 저장 응답에는 없는 필드**(citations 사례)는 폴링
동기화 순간 사라진다 — 서버가 이미 저장하고 있다면 조회 응답에도 반드시 포함시킨다.
