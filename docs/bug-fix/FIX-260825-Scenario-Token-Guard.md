# FIX-260825 시나리오 무토큰 조회 = 임의 세션 응답 (+구버전 위젯 캐시) — go2joy 재재현의 최종 원인

- 신고: go2joy `/partner`에서 delivery_status가 여전히 노출(#373·#382 이후). nginx 액세스 로그·DB·라이브 브라우저 재현으로 규명.

## 근본 원인 — 두 겹

1. **서버 풋건(교차 테넌트 누출)**: `GET /ai-config/scenario`가 `@Query('session_token')` 원시 파라미터를 썼고, 토큰이 **아예 없으면** `findOne({ sessionToken: undefined })` — TypeORM은 undefined 술어를 버리고 **임의의 첫 세션**을 반환한다. 그 세션의 테넌트(비스코프) 기본 6버튼이 200으로 나감. (빈 문자열은 404, 이미 있던 `SessionToken` 데코레이터가 정확히 이 풋건을 문서화하고 있었으나 이 엔드포인트와 `/restock`만 미적용.) nginx 로그로 사용자·재현 브라우저의 무토큰 200 실측.
2. **왜 위젯이 무토큰으로 호출했나 — 구버전 번들 캐시**: 위젯 `index.html`·`embed.js`에 **Cache-Control이 없어** 브라우저 휴리스틱 캐시로 수개월 전 번들(2026-07-01 토큰 파라미터 도입 이전)이 계속 실행됨. Chrome HTTP 캐시는 최상위 사이트별 파티션이라 go2joy 아래 iframe은 예전 방문 때의 index를 재사용 — 같은 URL을 최상위로 열면(다른 파티션) 최신 번들이 토큰을 정상 전송하는 것으로 검증. 해시 자산만 immutable이고 진입 파일 2종이 무헤더였던 구성 결함.

## 수정

- **서버**: `/ai-config/scenario`·`GET /restock` → `@SessionToken()` 데코레이터 적용(부재 시 401) + `getScenarioForSession` 서비스 계층에도 빈 토큰 404 이중 가드. 스윕 결과 그 외 공개 엔드포인트는 데코레이터/바디 DTO 검증 기적용.
- **엣지 nginx(스테이징·자체호스팅)**: `/widget/`(index.html)과 `/widget/embed.js`에 `Cache-Control: no-cache`(재검증 강제). 해시 자산 immutable 유지. 프로덕션 conf는 위젯 location 자체가 없어 해당 없음(추가 시 동일 규칙 적용할 것).

## 잔여 전파 특성

이미 구버전을 캐시한 브라우저는 휴리스틱 만료 후 재검증 때 최신 번들로 교체된다(마지막 배포가 오늘이라 수십 분~수시간 내). 그 사이 구번들은 서버 401→로컬 폴백 6버튼(라벨은 위젯 i18n)이 보일 수 있으나 **교차 테넌트 데이터는 차단**됨. 즉시 확인이 필요하면 강력 새로고침.

## 예방 패턴

- 위젯/공개 API에서 세션 토큰은 **항상 `SessionToken` 데코레이터**로 받기 — 원시 `@Query`는 undefined-술어 풋건에 그대로 노출된다.
- SPA 진입 파일(index.html, 로더 스크립트)은 **명시적 no-cache**가 기본 — 해시 자산 immutable 전략은 진입 파일 재검증이 전제다.
- "클라이언트가 그런 요청을 보낼 리 없다"는 소스 기준의 확신은 **배포·캐시된 과거 클라이언트**에는 적용되지 않는다 — 서버가 항상 최종 방어선.
