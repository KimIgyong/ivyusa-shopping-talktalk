Understanding the AI Response Pipeline

This is the full flow one customer message goes through. Every setting in this document adjusts some point in this flow.

Customer message
  ▼
① Intent classification ─── if orders/personal data are needed → identity-verification (login) prompt
  ▼
② Knowledge search (RAG) ─ find relevant evidence in the registered knowledge documents
  ▼
③ Answer generation ─── compose from persona·response rules + retrieved evidence, score confidence
  ▼
④ Moderation ── check the moderation rules (a failing answer is never shown to the customer)
  ▼
⑤ Branch: confidence sufficient → answer the customer (+sources)
        low confidence / blocked / customer request → agent queue (escalation)
  • The answer language follows the customer's session language (en/es/ko/vi/ja/zh).
  • Messages sent by agents also pass ④ moderation identically (non-bypassable).
01

Understanding the Knowledge Structure

Terms
Knowledge documentOne piece of text the AI uses as answer evidence. Consists of title·category·body
EmbeddingThe indexing job that turns a document into a searchable vector. Runs automatically on create/update
RAGThe method of searching for documents related to the question and answering only from that evidence
SourceA connection that imports documents automatically from outside (board·Google Drive·Notion)
GroupTop-level document classification: support (policy·FAQ) / product (from the catalog)
CategorySub-classification under a group (autocomplete presets: faq, policy, product, warranty, etc.)
Active/visibleWhether the document is included in search — inactive documents are never used as answer evidence
ConfidenceA score of how well the answer is supported by evidence. Low values hand off to an agent

The knowledge screen (/knowledge) has source·document management on the left, with the knowledge QA panel and conflict review pinned on the right, so you can move between registering ↔ verifying on one screen.

02

Registering Knowledge

2.1 Manual document creation & editing

Documents card → [Add document] → enter title / category / content → save. Clicking a title opens the detail dialog; [Edit] manages the following.

FieldPurpose
Source URLLink to the external document the content is based on (opens directly from the list)
Effective dateThe date the policy takes effect
Review interval (days)When exceeded, a stale (needs review) badge appears in the list → §3.3
ContentOn save, automatically re-embedded (search index refreshed)
💡 Tips
  • One document = one topic. Splitting "shipping+refund+exchange" into separate documents instead of one makes search more accurate.
  • Include customers' actual phrasing ("how long does shipping take") in titles·bodies — search is similarity-based, so the closer to customer vocabulary, the better it hits.
  • Instead of deleting outdated policies, exclude them with the visibility toggle OFF (inactive). History is preserved and reverting is easy.

2.2 Product knowledge — catalog sync · CSV · usage guides

Terms
Product cacheThe raw product list synced from the platform (the result of product sync on the Settings screen)
Catalog syncProduct cache → product knowledge documents. Two stages: preview → run
Variant folding (merge)Grouping dash-separated variants like "Lipstick-Red/Lipstick-Pink" into one representative product
Curation preservedProduct documents hand-polished by operators are kept from being overwritten by sync
Usage guideA shared how-to document per product type — answer evidence separate from product documents
  1. [Sync from catalog] → a preview runs first: scan count and expected results (created/updated/curation preserved/absorbed by merge/unchanged/held), estimated embedding batches, and a sample list of merges
  2. In the merge samples, verify that different products were not folded into one, then [Run]
  3. Watch the two progress lines (writing/embedding); after completion check the embedding failure count in the results table (failed items are not searchable — re-run needed)

Product CSV import: [Import product CSV] → choose a file → check the result statistics (parsed/created/updated/skipped/invalid/embedded) and per-row errors (up to 20). Re-uploading the same product overwrites it (upsert).

Usage guides: check the written/unwritten badges per type in the card → [Write] → save a title·body (20+ characters).

💡 Tips
  • Always look at the preview first. A wrong merge can only be caught in the preview, before running.
  • When platform products change, run the two stages in order — product sync in [Settings] → catalog sync in [Knowledge] — for the change to land.
  • With thin product descriptions, tags become the raw material of knowledge — tidying product tags on the platform side raises answer quality.

2.3 External source integration (board · Google Drive · Notion)

Terms
Service accountThe robot account for the Google Drive integration — the folder must be shared with this account's email to be readable
IntegrationThe unit by which Notion grants external tool access — must be "connected" to the target page
Sync result countsCreated·updated·skipped·hidden counts. dropped/truncated is a warning that part could not be imported
  1. Register credentials — Google Drive: paste the service-account key JSON → share the target folder with the displayed service-account email → [Test connection] / Notion: register the token (ntn_…) → connect the integration to the target page·DB → [Test connection]
  2. [Add source] → choose the type (board/gdrive/notion) → for gdrive the folder ID; for notion the page·DB ID or a shared URL
  3. Run ↻ (sync) on the source row → check the result counts in the last-sync column

Supported types: board ✅ · Google Drive ✅ · Notion ✅ · repository appears in the dropdown but is unsupported ("not ready").

💡 Tips
  • A red dropped/truncated warning means the page was too large or too deep and part was cut off — check the document's ending, split the original, and re-sync.
  • If a sync suddenly imports 0 items (folder unshared·integration disconnected, etc.), existing documents are left as-is rather than hidden — restore the connection first.
  • Clicking a source's status cell = toggles active↔inactive. Inactive only stops syncing; imported documents remain.
03

Knowledge Validation & Quality Management

Terms
Knowledge QA panelA test panel for asking the knowledge base questions as a customer would (pinned on the right)
CitationThe list of documents the answer is based on — shown with similarity scores
ConflictA state where two documents are detected as containing mutually contradictory content
staleThe badge on a document whose review interval has passed and needs re-checking
Knowledge gapA topic customers asked about that the knowledge had no answer for — proposed by the system as a document draft
Answer proposalA proposal to promote an agent's real answer into a knowledge document (human approval required)
RevisionA snapshot of a document's change history — supports diff view·restore

3.1 Knowledge QA panel — always verify after registering

Enter a question → check the answer + confidence score + source list → if an evidence document is wrong, press [Fix] next to the source (that document opens directly in edit mode) → after fixing, re-check with [Ask again].

💡 Tips
  • A blocked by moderation badge means the answer hit a moderation rule (§4.5) — a real customer would never have seen it.
  • If a source carries a conflicted/stale badge, clean up that document first.
  • Whenever a policy changes, the habit of throwing "3 questions a customer would ask" at the panel is the cheapest regression test (automation: §6.3).

3.2 Conflict review

Conflict review panel → status filter (pending/resolved/dismissed/failed) → per item, check similarity·detection time·verdict rationale → choose an action. [Re-scan] re-checks everything.

ActionBehavior
Keep A / Keep BKeep the chosen one and deactivate the other
Keep bothJudged not a contradiction — both stay active
DismissClose this conflict item
Re-judgeRequest a new verdict after fixing the documents
💡 Tip

Conflicts usually come from not retiring the old version when a policy is revised. Don't stop at "Keep A" — record the effective date on the surviving document so it doesn't repeat at the next revision.

3.3 Review interval · stale / change history

When a document's review interval (days) is exceeded, a stale badge appears in the list. Pressing [Mark reviewed] in the review-status box of the document detail recalculates the deadline. In the change history tab you can view per-revision diffs and [Restore].

💡 Tip

Give frequently changing documents (shipping fees·promotions) a short review interval of around 30 days and stable ones (legal notices) a long one, and the stale badges become a practical to-do list.

3.4 Knowledge gap proposals · answer proposal approval (closed loop)

  • Knowledge gap proposals (top, only when there are items): topics where the knowledge was empty accumulate as document drafts — [Accept] (confirm after editing title·content) / [Dismiss]
  • Answer proposals (when items are pending): proposals to promote an agent's real answer into knowledge — check the question·answer·source-conversation link, then [Approve] / [Reject] (reason required)
⚠️ Check for personal data before approving

Always verify that no order numbers·names remain in the answer — knowledge documents are reused as evidence for every customer's answers.

💡 Tip

These two are the channels through which the knowledge grows on its own. A weekly routine of emptying them reduces the root cause of "the AI keeps handing off to agents".

AI Settings

Left menu [AI settings] · master/director
Terms
AI agentA bot unit with its own persona·rule set — create several and run different bots per channel·page
Default agentThe agent used by widgets with no specific assignment (always active)
Entry snippetAn installation code fragment that launches the widget with a specific agent
Persona / response rulesThe bot's tone·principles description / the list of rules it must obey (injected at pipeline ③)
Scenario buttonsThe quick-menu buttons at the bottom of the widget — choose among 7 actions
AI functionsThe 5 places AI is used (chat/rag/summary/assist/moderation) — an engine is assigned per place
Moderation rulesThe rules that inspect outbound messages (pipeline ④)
Answer reuseReplaying an approved past answer for the same question without an LLM call
Change noteA one-line note recorded when saving persona·rules — viewable in the settings change history

4.1 AI agents (multi-persona)

Selecting an agent in the AI agents card switches the persona·response rules cards below to that agent's. Create with [Add] (name·lowercase code), manage [Set as default]·the active toggle·[Delete], and copy the entry snippet to install on a specific page·channel.

💡 Tips
  • An agent is assigned once at session start — the bot of a session in progress does not change even if you swap snippets.
  • Entering with a non-existent code falls back to the default agent (the widget never breaks).
  • The "AI agents" here have nothing to do with (human) agent accounts — human accounts live in the [Users] menu.

4.2 Persona & response rules

Write the persona text → enter a change note → save. Response rules are added one line at a time via [Add rule] (blank lines are removed on save).

💡 Tips
  • Put identity·tone in the persona and behavioral constraints in the rules. Factual information (shipping fees, etc.) goes in knowledge documents — the persona is not searched.
  • After saving, propagation can take up to 60 seconds because of caching.
  • [Load into editor] in the change history does not apply anything by itself — you must also save for it to take effect.

4.3 Scenario buttons

Per row, edit the label (max 60 chars) / action / enabled checkbox / order (↑↓). In [Edit reply], edit each action's response copy across 6 language tabs and configure follow-up buttons (label·action·URL).

ActionActual behavior in the widget
Track shippingFixed shipping-policy answer + follow-up buttons
Cancel / refundFixed cancellation·refund·return answer + follow-up buttons
Product helpSubmenu (usage·ingredients·exchange/return·restock)
Contact supportLeave-your-contact form — the path to an agent
My ordersIdentity verification, then jumps to the orders tab
PartnershipPartnership info card
Send messageSends the label text verbatim as the question → the AI answers from knowledge
💡 Tips
  • To turn a frequent question into a button, use the Send message action with the label written as the question sentence (e.g. "What is the free-shipping threshold?").
  • Hide buttons by unchecking them rather than deleting. Keeping Contact support always on is recommended.
  • Keep the fixed answer copy and the policy content of knowledge documents in step — update both together when a policy is revised.

4.4 AI functions (engine·parameters)

On each function's row, choose the applied engine, enter temperature (0–1)·max_tokens, and save individually. Unassigned functions show an inherited/default/stub badge plus the actually applied engine name.

FunctionActual use
chatConversation control such as intent classification of customer messages
ragKnowledge-based answer generation — the body of what customers see
summaryConversation summaries (history·handoff briefing)
assistAI assistance in the agent console
moderationLLM verdicts for context-type moderation rules

Fallback chain: chosen engine unavailable → tenant default → platform default → stub (demo responses) — automatic downgrade, so the conversation never breaks.

⚠️ temperature is not applied to Anthropic (Claude) engines

Current Claude models reject the sampling parameter, so the system deliberately does not send it. Entering a value is ignored; it applies only to OpenAI-family engines. max_tokens applies normally (512–1024 recommended for chat answers).

💡 Tip

A lingering stub badge means you are not at production quality — engine registration is a platform-administrator permission. The embedding model for knowledge search is not on this screen (shared across all tenants, server-managed).

4.5 Moderation rules

ItemChoicesMeaning
TypeWord / phraseContainment match (case-insensitive)
RegexPattern match
Context (LLM)Write "what to block" as a sentence and the AI judges each message
ScopeAI only / agents only / bothWhose outbound messages to inspect
ActionBlockDo not send the message (an AI answer converts into an agent handoff)
MaskOnly the matched part becomes ▇▇▇, then delivered
RewriteThe AI rewrites it into a safe sentence, then delivers
💡 Tips
  • This gate cannot be turned off, and if the check itself fails it resolves to block for safety. If an agent message is refused, rephrase and send again.
  • The context (LLM) type uses the moderation function's engine — in stub state there is no verdict quality.
  • Excessive word rules block legitimate answers too. Start with mask/rewrite, watch the logs, then escalate to block. Propagation takes up to 60 seconds.

4.6 Answer reuse

In the answer reuse card, search the stored Q&As (filter to active only), edit/delete per item, and stop everything at once with [Deactivate all].

💡 Tip

A reused answer goes out instantly without an LLM call — fast and cheap — but when a policy changes, a stale answer can go out unchanged. Put updating/deactivating the related items on your policy-revision checklist. Reused answers still pass moderation.

Live Chat Customer-Response Settings

The Agent handoff section of the [Settings] page
Terms
Escalation (handoff)The AI passing a conversation to the agent queue
Handoff settingsThe bundle of settings for assignment·hours·notices after escalation
Business hoursThe window when agents respond — outside it, the flow switches to off-hours notice·email intake
SLAResponse target time — the basis of the issue board's delay badges (⚠️/🔥)
Waiting (queue)The state of a handed-off conversation waiting for an agent to take it

5.1 Assignees · business hours · off-hours notice

  1. Assignees — check the agents who receive handoffs
  2. Business hours toggle → timezone·start/end·weekdays, plus a break time toggle if needed
  3. Off-hours intake email — the address that receives inquiries outside business hours (a warning shows if SMTP is not configured)
  4. Off-hours notice copy — written per language tab
  5. SLA — normal/urgent response targets (hours, 1–168h)
  6. Policy-forced handoff (deny-list) — register keyword (comma-separated) + inquiry type + duty-label rules. A matched message is delivered straight to an agent without passing through the AI, and the created issue gets the type·label stamped automatically.
💡 Tips
  • Set the business-hours timezone precisely to the store's — a US store left on Korean time sends the notices exactly backwards.
  • Off-hours email intake requires server SMTP configuration first — if you see the warning, ask the platform administrator.
  • If no assignee is designated, handed-off conversations only pile up in the shared queue — designate at least one.

5.2 Understanding escalation triggers

TriggerBehavior
Low confidenceAppends "Shall I connect you to an agent?" to the answer and queues it
Blocked by moderationThe AI answer is withheld; an agent-connection notice is shown, then queued
Customer requestThe scenario's Contact support or an explicit request → queued immediately
Policy-forced handoffOn a registered-keyword match, queued immediately with no AI response — the message is stored·displayed normally, and the issue is stamped with type·label (this is not a message-blocking feature)
💡 Tip

The confidence threshold is not adjustable on screen (code policy). If handoffs are frequent, the right response is reinforcing the knowledge, not the threshold (find the cause with the QA panel, §3.1). Handling handed-off conversations (accepting·AI briefing·closing·reassignment) happens in the live chat console (/live-chat).

Validation & Improvement Loop

The studio on the right of [AI settings] + the regression check card
Terms
PreviewA test panel for chatting with the bot without creating a real customer session
AI coachingGive natural-language feedback and receive a proposed settings change, applied only on approval
ProposalThe settings-change card coaching produced — can be applied/rejected/reverted
Golden questionsThe list of representative questions whose answer quality you want to keep checking (regression-test input)
Regression checkRe-running all golden questions after settings·knowledge changes to confirm answers did not degrade
Variability measurementRunning the same question repeatedly to see how much the answer fluctuates

6.1 Preview

Preview tab → choose a language → [New session] → choose the mode (customer/agent) and type messages. Responses display the responsible agent badge and whether escalation occurred. [Coach this] on a response attaches that turn to coaching.

💡 Tip

After changing settings, save and then start with [New session] to see a conversation with the new settings applied. The answer language follows the session language, so check your key questions across languages.

6.2 AI coaching

Agent coaching tab → pick a thread or [New thread] → review the reference turns and instruct in natural language (e.g. "The refund explanation is too long. Keep it under 3 sentences") → review the changes in the proposal card → [Apply] / [Reject] / after applying, [Revert].

💡 Tips
  • Coaching changes nothing without approval. Read the actual changes in the proposal card (persona·rules diff) before applying.
  • Factual information like "free shipping over ₩50,000" belongs in a knowledge document, not in coaching — coaching is a tool for polishing tone·behavioral rules.
  • Slight wording drift is normal variation. Falling confidence·rising escalations are the real warning signs.

6.3 Regression check (golden questions)

Regression check card → register golden questions (10–20 representative ones) → [Run now] → [Compare with previous] in the recent-runs list shows answer changes side by side. [Variability measurement] shows how much the same question's answer fluctuates.

💡 Tips
  • Put into the golden questions: ① revenue-critical questions (shipping·refunds) ② questions that produced wrong answers in the past ③ questions affected by policy revisions.
  • Make it a routine to run once right after bulk knowledge changes·catalog sync·persona revisions. A truncated badge on a run means the question count exceeded the run ceiling and only part was executed.
07

Operations Checklist

When a policy changes (e.g. shipping-fee revision)

  • Update the related knowledge documents (re-embedding automatic) + deactivate old versions
  • Check the scenario fixed answers (track shipping·cancel/refund) copy
  • Search answer-reuse items → fix/deactivate stale answers
  • Verify 3 representative questions in the QA panel → run the golden-question regression
  • Update the documents' effective date·review interval

Weekly routine

  • Empty the knowledge gap proposals·answer proposals (§3.4)
  • Process pending conflict-review items (§3.2)
  • Review stale-badged documents (§3.3)
  • Topics with frequent handoffs in live chat → reinforce the knowledge
08

FAQ / Troubleshooting

Q. I registered a document but the AI doesn't know its content.
Check ① the document is active (visibility ON) ② the document appears in the QA panel's source list. If it doesn't, reinforce the title·body with customer vocabulary. Also check for embedding failures in the catalog sync.
Q. The AI keeps handing off to agents.
Check the question's confidence·sources in the QA panel. If there is no evidence document, registering one is the answer; if there is one but confidence is low, split the document and reinforce the vocabulary.
Q. An agent's message is refused on send.
That is a moderation block. Rephrase the expression that hit a moderation rule (§4.5) and send again. If the rules are excessive, ask the master to soften the action (block→mask).
Q. Answers come out only in English.
The answer language follows the customer's session language. Verify by setting the language in the preview. Writing the persona in Korean is unrelated to the answer language.
Q. Google Drive/Notion sync imports 0 items.
Most often the folder share (service-account email) or the Notion integration connection is broken. Start over from [Test connection] on the credentials card.
Q. I applied a coaching proposal and answers got worse.
Recover with [Revert] on that proposal card. You can also open the previous revision in the settings change history, load it into the editor, and save.
Q. The same question gets slightly different answers each time.
That is normal LLM variation (check the spread with §6.3 variability measurement). If the content — not the wording — differs, suspect a knowledge conflict (§3.2). Adjusting temperature has no effect on Anthropic engines (§4.4).
