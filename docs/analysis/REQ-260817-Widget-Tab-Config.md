# REQ-260817-Widget-Tab-Config

위젯 **주문 탭 복원**과 **탭 위치(상단/하단) 테넌트별 설정화** 요구사항 분석.

- 작성일: 2026-08-17
- 원 요구: "디자인은 그대로 유지하되 주문탭을 추가한다. (설정에서 추가변경 가능) /
  탭을 상단과 하단으로 설정에서 고객사별 선택 가능하게 구현한다."
- 선행: `REQ-260817-Widget-Figma-Design` → `PLN-260817-Widget-Figma-Design` → PR #301(`0178e83`, 스테이징 LIVE)

## 0. 요구의 핵심 — 이것은 되돌리기가 아니다

주문 탭은 **몇 시간 전 PR #301에서 삭제됐고**, 그 내용은 사라진 게 아니라 **알림 탭과 챗으로 이사했다.**
따라서 "주문 탭을 추가한다"는 `git revert`가 아니라 **같은 내용을 담은 두 번째 집을 만드는 일**이며,
중복을 어떻게 처리할지가 이 요구의 실제 난제다(§4 Q1).

| PR #301 이전 주문 탭이 하던 일 | 지금 어디에 있나 |
|---|---|
| 주문 목록(결제/배송/문의 서브탭) | 알림 탭 `결제`·`배송`·`문의` 필터 |
| 주문 상세 `OrderDetailView` | 알림 탭에서 push되는 서브뷰 |
| 리뷰 작성 `ReviewForm` | 알림 탭 `리뷰` 필터의 `⭐ 리뷰 작성` |
| 배송 추적 | 알림 탭 `배송` 필터의 가로 스테퍼 |
| 챗의 `My Orders` → 탭 전환 | 챗 스레드 안 인라인 주문 카드 |
| 몰 마이페이지 링크 | 알림 탭 하단 `더 보기` |

## 2. TO-BE

### 2.1 요구 A — 주문 탭 추가 (설정으로 on/off)
- 위젯 탭 집합이 **고정 2개 → 테넌트 설정값**이 된다.
- 기본값은 **현재 상태 유지**(알림·챗)여야 한다. 그러지 않으면 이미 배포된 테넌트의 위젯이 말없이 바뀐다.

### 2.2 요구 B — 탭 위치 상단/하단 선택
- `top`(현행 세그먼트) / `bottom`(구 아이콘 탭바 계열) 중 테넌트가 선택.
- 기본값 **`top`** (현행 유지).

### 2.3 디자인 근거와 공백
- Master Shots는 **2탭까지만** 보여준다: `Notifications | Chat`(34, 57~69)과 `Notifications | Orders`(48, 49).
  → **디자인은 "두 번째 탭이 무엇인가"가 가변적일 수 있음을 이미 암시**하고 있었다(REQ-260817 §Q2에서 엇갈린다고 기록한 그 지점).
- 그러나 **상단 3탭 형태는 디자인에 없다.** 라벨 3등분 / 아이콘 병기 / 축약 중 무엇인지 결정 필요(Q3).
- **하단 탭 형태도 새 디자인 언어로는 존재하지 않는다.** 삭제된 구 탭바는 인디고 팔레트·아이콘+라벨 세로 배치였다(Q4).

## 4. 확정 사항 (사용자 결정 2026-08-17)

| # | 질문 | **결정** |
|---|---|---|
| **Q1** | 주문 탭 ON일 때 알림 탭 칩 | **주문 관련 칩을 주문 탭으로 이관.** 알림 = `전체`·`이벤트` / 주문 = `결제`·`배송`·`리뷰`·`문의` |
| **Q2** | on/off 범위 | **세 탭 모두 개별 on/off** (최소 1개 강제) |
| **Q3/Q4** | 탭 렌더 형태 | **상단 = 라벨(현행 세그먼트 N등분) · 하단 = 아이콘 + 라벨** |
| **Q5** | 챗 `My Orders` | **인라인 카드 유지** (프레임 57 준수) |
| **Q6** | 설정 권한 | 미질의 → **테넌트 설정으로 가정.** 기존 `WidgetBehaviorCard`(`/settings`)에 추가, 플랫폼 제공 계층 없음 |
| **Q7** | 기본값 | 미질의 → **현행 유지로 가정**: 탭 = `알림`·`채팅`(주문 OFF), 위치 = `상단` |

### 4.1 Q1 + Q2 결합에서 파생되는 규칙 (PLN에서 확정)

세 탭을 각각 끌 수 있으므로 "칩이 갈 곳이 사라지는" 조합이 생긴다. 목록형 탭은 알림·주문 둘뿐이므로:

| 알림 | 주문 | 칩 배치 |
|---|---|---|
| ON | ON | 알림 `전체`·`이벤트` / 주문 `결제`·`배송`·`리뷰`·`문의` (Q1) |
| ON | OFF | 알림이 **6개 전부** 흡수 (= 현행, 기본값) |
| OFF | ON | 주문이 **6개 전부** 흡수 |
| OFF | OFF | 목록형 탭 없음 — 채팅 단독. 테넌트의 명시적 선택 |

> 한 문장으로: **살아 있는 목록형 탭이 하나뿐이면 그 탭이 상대의 칩까지 가져간다.**

## 5. 제약

1. **디자인 유지가 전제** — 요구 첫 문장이 "디자인은 그대로 유지하되". 팔레트·헤더·행 구성·카드 형태는 건드리지 않는다.
2. **기존 테넌트 무변경** — 설정 기본값이 현행과 같아야 한다. `widget_login_mode`가 `default 'redirect'`로 그렇게 했다.
3. **스키마 변경 시 선적용** — 스테이징 `DB_SYNCHRONIZE=false`. PR 본문 `## Migration` 필수.
4. **i18n 6개 언어** — 신규 콘솔/위젯 문구는 en/es/ko/vi/ja/zh 전부. `npm run i18n:check` 게이트.
5. **접근성 유지** — 상단 탭의 `tablist/tab/tabpanel` 연결을 하단 탭에서도 동일하게.
6. **반응형** — 하단 탭은 모바일 전체화면 바텀시트에서 안전영역(safe-area) 고려 필요.
