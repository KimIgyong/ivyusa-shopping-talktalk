## 1. 무엇이 문제였나

AI는 매 턴 고객 문장을 보고 언어를 맞추는데, 시스템 문구는 세션이 열릴 때 정해진 `session.language` **한 값**으로 결정됐습니다. 판단 시점이 달라서 **한 대화 안에서 언어가 섞였습니다.**

스테이징 실측 — 세션 언어가 `EN`인데 고객이 한국어로 쓴 대화 27건:

| 발신 | 한국어 | 영어 |
|---|---|---|
| AI | 28 | 43 |
| **시스템** | **0** | **23** |

## 2. 무엇을 바꿨나

| 단계 | 파일 | 내용 |
|---|---|---|
| **P1** | `global/util/detect-language.util.ts` (신규) | 문자 범위 감지. 모델 호출 없음. **의미 글자 4자 미만은 판정 보류** |
| **P2** | `domain/chat/chat.service.ts` | `syncSessionLanguage()` — 메시지 저장 직후·응답 생성 **전**. 연속 2턴 동일 언어일 때만 전환 |
| | `domain/session/session.service.ts` | `applyDetectedLanguage()` — 잠그지 않는 갱신 + Redis 캐시 무효화 |
| **P3** | `sessions.language_locked` · `setLanguage()` | 선택기로 고른 언어는 감지가 덮지 않음 |
| **P4** | `widget/src/i18n/i18n.ts` · `store/widgetStore.ts` | 시작값 `'en'` 고정 → `navigator.language`(지원 3종). 수동 선택 이력이 최우선 |

신규 테스트 32건 · 전체 **1,075 passed / 101 suites** · typecheck 9/9 · build 통과.

### 설계에서 실제로 값을 한 두 가지

**길이 게이트를 문자 규칙보다 먼저** 두었습니다. "네" 한 마디는 한글임이 분명하지만 그 대화의 언어를 말해주지는 않습니다 — 스크립트를 먼저 보면 한 글자짜리 확인 응답이 전환을 일으켜 연속 2회 규칙 자체가 무력해집니다.

**갱신을 응답 생성 앞에** 두었습니다. 뒤에 두면 전환을 유발한 바로 그 턴은 여전히 옛 언어로 나가고, 고객은 "한국어로 두 번 썼는데 아직도 영어"를 한 번 더 봅니다. 검증에서 전환된 턴의 시스템 문구가 곧바로 한국어로 나온 것(대화 227)이 이 배치의 결과입니다.

## 4. 검증 요약

V1~V9 전부 통과 — 상세는 TCR. 핵심 증거 두 가지:

```
대화 227 (V1)   user 뉴욕 날씨 알려주시오 → ai(KO) → user 배송 언제 오나요?
                system 주문을 조회하려면 본인 확인이 필요합니다 …   ← 한국어로 전환
대화 232 (V5)   선택기로 EN 고정 → 한국어 3턴 → system 3턴 내내 영어  ← 수동 선택 보호
```

플립플롭 회귀(`ok`·`thanks`·`ㅇㅇ`·`?`)에서 전환이 **한 번도** 일어나지 않았습니다.
