| # | 결정 | 채택안 |
|---|---|---|
| **F2** | 링크 대상 | **직접 상품 URL**(`kb_documents.source_url`) — 검색 링크 아님 |
| **F3** | 베이스 도메인 | **테넌트 설정 신설** — `shop_domain`은 myshopify 주소라 사용 불가 |
| F1 | 표시 위치 | 답변 아래 유지 + **"지식참조" 라벨** |
| F4 | Tags 가격 문구 | 유지(가격대 태그이며 실제 가격 아님) |
| F5 | 링크 대상 인용 | **상품 그룹만** |
| F6 | 콘솔 노출 | 목록 아이콘 + 상세 링크 |

### F2·F3이 함께 필요한 이유

F2로 직접 URL을 쓰면 링크를 **조립할 일이 없어** F3이 불필요해 보입니다. 그러나 테넌트 설정은
**조립용이 아니라 검증용**으로 필요합니다.

> `source_url`은 **관리자가 업로드한 CSV에서 그대로 들어온 값**이고, 위젯은 그것을
> **고객에게 클릭 가능한 링크로 렌더링**합니다. 위젯의 `safeHttpUrl`은 `javascript:`만 막고
> `https://evil.example`은 통과시킵니다. 즉 **CSV 업로드 한 번으로 고객 대화창에 임의의 외부
> 링크를 심을 수 있습니다.**
>
> 테넌트의 스토어프론트 호스트를 알아야 "이 링크가 우리 상점 주소인가"를 판정할 수 있습니다.
> F3은 그 기준값입니다.

## 2. L1 — 테넌트 스토어프론트 URL

```sql
ALTER TABLE tenants ADD COLUMN storefront_url VARCHAR(255) NULL;
```

- 기존 테넌트 컬럼(`privacy_policy_url`, `widget_login_mode`)과 같은 평면 방식.
- **기본값 없음** — 설정 전에는 링크가 생기지 않습니다(안전한 기본값: 링크 미표시).
- 콘솔 `Tenant Settings`에 입력란 추가. `https://ivyusa.com` 형태의 **오리진**만 받습니다.
- 저장 시 `http(s)`만 허용하고 경로·쿼리는 버립니다(오리진 정규화).

> `shop_domain`(`ambshop-dev.myshopify.com`)은 **Shopify 관리 도메인**이라 고객이 보는 주소가
> 아닙니다. 재사용하면 두 번째 테넌트(`annehearts.cafe24.com`)에서도 틀린 링크가 나갑니다.

## 3. L2 — 인용에 URL 공급

### 3-1. 타입 확장

```ts
interface RetrievedChunk {
  …
  group: string;        // counsel | product
  url: string | null;   // 스토어프론트 호스트로 검증된 상품 URL만
}
```

`ChatCitation`에는 `url`이 **이미 있습니다**(위젯이 그것을 링크로 그리는 코드도 이미 있음).
`group`만 추가합니다.

### 3-2. 호스트 검증 — 이번 작업의 핵심

```
url = (doc.docGroup === 'product'
       && doc.sourceUrl
       && sameHost(doc.sourceUrl, tenant.storefrontUrl))
      ? doc.sourceUrl
      : null
```

| 조건 | 결과 | 이유 |
|---|---|---|
| 상품 그룹 아님 | `null` | 정책 문서는 `source_url`이 0건이고 "상품추천"이 아님(F5) |
| `storefront_url` 미설정 | `null` | 기준이 없으면 판정 불가 → 링크 미표시 |
| 호스트 불일치 | `null` | **CSV로 유입된 외부 링크를 고객에게 노출하지 않음** |
| http/https 아님 | `null` | 서버에서도 스킴 차단(위젯 검증에만 의존하지 않음) |

`www.` 접두는 동일 호스트로 취급하고, 서브도메인은 **정확히 일치**해야 합니다
(`shop.ivyusa.com`은 `ivyusa.com`과 다름 — 느슨하게 두면 검증의 의미가 없습니다).

## 4. L3 — 위젯 표시

현재 `MessageBubble`은 인용을 라벨 없는 목록으로 그립니다. 여기에 **"지식참조" 제목**을 붙이고,
링크가 있는 상품 인용은 **상품추천으로 구분**합니다.

```
┌──────────────────────────────────────────────┐
│  콜라겐 마스크는 어떻게 쓰나요?          [나] │
└──────────────────────────────────────────────┘

┌──────────────────────────────────────────────┐
│ 세안 후 마스크를 얼굴에 밀착시켜 20분간      │
│ 두신 뒤 떼어내고 남은 에센스를 두드려        │
│ 흡수시키면 됩니다.                            │
├──────────────────────────────────────────────┤
│ 지식참조                                      │
│  🛍 Arocell Super Collagen Mask (2 sheets)…  │  ← 상품: 링크
│  🛍 Arocell Wrinkle Solution Eye Cream        │
│  · 2.2.6 반품 검수                            │  ← 정책: 텍스트
└──────────────────────────────────────────────┘
                                          09:12
```

- 상품 인용은 **아이콘 + 밑줄 링크**, 정책 인용은 기존처럼 텍스트.
- 링크는 `target="_blank" rel="noopener noreferrer"` 유지(기존 동작).
- 인용이 없으면 영역 자체가 렌더링되지 않습니다(현행 동작 유지).
- i18n: "지식참조" 라벨을 위젯 3개 언어에 추가.

> **F1 재확인**: 요구 문언은 "대화방 하단"이었으나 **답변 바로 아래**로 둡니다.
> 대화가 길어지면 하단 고정 목록은 어느 답변의 근거인지 알 수 없게 되고, 상품 문의와
> 정책 문의가 섞이면 추천이 엉뚱한 답변에 붙습니다. 다르게 원하시면 되돌릴 수 있습니다.

## 5. L4 — 콘솔 바로가기

```
┌─ Documents ─────────────────────────────────────────────────────────┐
│ 제목                              분류      노출  출처    수정   ↗  │
│ Arocell Super Collagen Mask…      Arocell   노출  지식…  8/4   🔗 │  ← 신규
│ 2.2.6 반품 검수                    policy…   노출  지식…  7/31   —  │
└─────────────────────────────────────────────────────────────────────┘

┌─ 문서 상세 ────────────────────────────────────┐
│ [내용] [수정 이력]                              │
│ Arocell · 노출 · 지식저장소                     │
│ 🔗 상품 페이지 열기  ↗                          │  ← 신규(보기 모드)
└─────────────────────────────────────────────────┘
```

- 목록 끝에 아이콘 열. `source_url`이 있는 문서만 표시.
- 상세 **보기 모드**에 링크 추가(현재는 편집 모드 입력란에만 존재).
- 콘솔은 관리자 화면이므로 호스트 검증 없이 저장된 URL을 그대로 엽니다 —
  다만 `http(s)`만 허용합니다.

## 6. 사이드 임팩트

| 영역 | 영향 | 대응 |
|---|---|---|
| **고객 노출 링크** | CSV로 임의 외부 링크 유입 가능 | **호스트 검증(L2)** — 이번 작업의 핵심 안전장치 |
| 미설정 테넌트 | `storefront_url` 없으면 링크 0건 | 의도된 안전 기본값. 콘솔에 안내 문구 |
| 기존 정책 인용 | 변화 없음(`source_url` 0건) | 텍스트 그대로 |
| 위젯 번들 | 라벨·아이콘만 추가 | 무시 가능 |
| 모더레이션 | 인용 제목은 AI 생성물이 아님 | 게이트 통과 불필요(REQ §2) |
| 개인정보 | 상품 제목·URL은 고객 데이터 아님 | 영향 없음 |
| 통계/이력 | 변경 없음 | — |

## 7. 테스트 계획

- **호스트 검증**: 동일 호스트 통과 · `www.` 동일 취급 · **서브도메인 불일치 차단** ·
  외부 도메인 차단 · `javascript:` 차단 · `storefront_url` 미설정 시 전부 null
- **그룹 한정**: 정책 문서는 `source_url`이 있어도 링크 없음
- **위젯**: 링크 있는 인용은 앵커, 없는 인용은 텍스트 · 인용 0건이면 영역 미렌더링
- **오리진 정규화**: 경로·쿼리가 붙은 입력을 저장 시 오리진으로 정리
