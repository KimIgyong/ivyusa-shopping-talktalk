# REQ-PWA-20260802 — ShopTalk PWA (스토어 등록 전 임시·병행 채널)

- 작성일: 2026-08-02

- 관련: `REQ-MobileApp-20260731.md` / `PLN-MobileApp-20260731.md` / `RPT-MobileApp-20260731.md`
  (RN 앱 M1-M4 구현·스테이징 배포 완료, 실기기 E2E·스토어 제출 대기)

## 1. 배경 및 목표

RN 모바일 앱은 구현이 끝났지만 **스토어 공개까지 외부 의존이 남아 있다**
(Apple Developer/APNs 키·FCM·EAS 준비물, Apple 4.2 심사 리스크, 심사 기간).
그 공백 기간에도 고객에게 푸시(주문/배송/이벤트)와 채팅을 제공하기 위해
**설치형 PWA**를 먼저 배포한다.

1. 스토어 승인 **전**: PWA가 고객 접점 (홈 화면 설치 + Web Push)
2. 스토어 승인 **후**: PWA는 앱 미설치 사용자·데스크톱용 병행 채널로 유지

RN 앱과 동일한 공개 API를 사용하므로 백엔드 재작업은 Web Push 발송 경로 추가에 한정된다.

## 2. AS-IS

### 2.1 이미 있는 것 (RN 앱 작업으로 확보)
- `device_tokens` + `POST /push/register|unregister` (provider 컬럼 존재, 현재 `expo`만)
- `PushProvider` 추상화 — 발송 로직은 프로바이더 교체 가능 구조 (PLN-MobileApp D-2 의도대로)
- 억제 정책 통합 완료: `push` 채널이 pref/옵트아웃/fail-closed 게이트 통과 후 발송
- 상담원 응답(chat)·배송(shipping)·캠페인(event) 발신처 전부 연결됨
- 위젯(apps/widget)에 채팅/주문/알림 UI·서비스 레이어 존재 (iframe 전제)
- 모바일 앱(apps/mobile)에 동일 화면의 RN 구현 존재

### 2.2 갭
| # | 갭 | 근거 |
|---|---|---|
| P-G1 | `web_push` 채널은 enum/pref에만 존재, **발송은 mock** (`notification.service.ts` — push 채널만 실발송) | 기존 |
| P-G2 | Web Push(VAPID) 발송 코드·`web-push` 라이브러리 없음, VAPID 키 미생성 | `apps/api/package.json` 확인 |
| P-G3 | `device_tokens.token`이 `varchar(255)` — **Web Push 구독은 endpoint URL만 255자 초과 가능**(FCM endpoint ~300자+) + p256dh/auth 키 필요 → 스키마 변경 필수 | `device-token.entity.ts:38` |
| P-G4 | 고객용 standalone 웹앱 없음 — widget은 iframe 임베드 전제, web은 관리자 콘솔 | 구조 |
| P-G5 | Service Worker/manifest 인프라 없음 (widget/web 모두 SPA, SW 미사용) | 구조 |
| P-G6 | staging nginx/compose에 PWA 서빙 경로 없음 | `docker/staging/` |

### 2.3 플랫폼 제약 (설계를 결정짓는 외부 사실)
| # | 제약 | 영향 |
|---|---|---|
| C1 | **Shopify 스토어프론트는 iframe 금지**(frame-ancestors) | PWA 안에 쇼핑몰을 embed 불가 → 쇼핑은 탑레벨 이동/새 탭. RN의 WebView 탭과 구조가 다름 |
| C2 | **iOS Web Push는 홈 화면에 설치된 PWA에서만** 동작 (iOS 16.4+) | iOS 사용자는 A2HS 설치 유도 UX가 필수. Safari 탭에서는 푸시 불가 |
| C3 | Android/Chrome·Edge·삼성브라우저는 브라우저만으로 Web Push 동작 | Android가 주 수혜 대상 |
| C4 | PWA는 스토어 앱과 달리 Shopify App Proxy 아이덴티티 브리지를 쓸 수 없음(다른 origin) | verified 승격 경로: 게스트 조회(주문번호+이메일, `guest` 레벨) 기본. DSAR 등 `verified` 필요 기능은 PWA에서 제한 |
| C5 | Web Push 페이로드는 서비스워커가 수신·표시 (알림 표시는 SW `push` 이벤트에서) | 딥링크는 SW `notificationclick` → 라우트 열기 |

## 3. TO-BE

### 3.1 프론트: `apps/pwa` (신규 워크스페이스)
- **Vite + React 18 + Tailwind + React Query + react-i18next** (repo 표준 스택, 위젯과 동일)
- 하단 내비 4메뉴: **상담 / 주문 / 알림 / 설정** + 상단 "쇼핑하기" 버튼(스토어프론트 탑레벨 이동, C1)
- RN 앱과 동일 API·동일 UX 흐름: 동의 게이트, 5초 폴링 채팅, 게스트 주문 조회,
  알림센터(in_app 필터), 알림 pref 토글, CCPA 옵트아웃, 언어 en/es/ko
- **manifest.webmanifest**(standalone, 아이콘) + **Service Worker**:
  push 표시(C5), notificationclick 딥링크, 앱 셸 오프라인 캐시(정적 자산만; API는 네트워크 우선)
- **설치 유도**: Android `beforeinstallprompt` 배너 / iOS Safari 감지 시 "공유 → 홈 화면에 추가"
  가이드 시트(C2). 미설치 상태에서는 푸시 토글 비활성 + 사유 안내
- 푸시 구독: `PushManager.subscribe(VAPID 공개키)` → `POST /push/register`(provider `webpush`)

### 3.2 백엔드: push 모듈 확장 (`apps/api`)
- `WebPushProvider` 추가(`web-push` 라이브러리, VAPID 키 env) — 기존 `PushProvider`
  인터페이스 구현, 410/404 응답 시 구독 자동 revoke (Expo의 DeviceNotRegistered와 동일 취급)
- `PushService.dispatch`가 디바이스 행의 `provider` 값으로 프로바이더 라우팅 (expo | webpush)
- `POST /push/register` 요청 확장: `provider`, Web Push 구독(endpoint, p256dh, auth)
- **스키마 변경(P-G3)**: `device_tokens.token`을 `TEXT`로 확장 + 유니크는
  `token_hash`(SHA-256, varchar 64) 생성 컬럼/애플리케이션 컬럼으로 대체 → migration SQL
- env: `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`/`VAPID_SUBJECT` (+ 공개키 노출 endpoint `GET /push/vapid-key`)

### 3.3 배포
- staging: `docker/staging`에 pwa 서비스(+nginx 라우팅, 예: `https://shoptalk.amoeba.site/app/`)
- HTTPS 필수(SW/푸시 전제) — staging TLS 기존 충족

## 5. 사용자 흐름

```
고객이 링크(문자/이메일/스토어 배너)로 PWA 접속
 → 온보딩(언어, 알림 안내) → /session/ensure(shop_domain)
 → [Android] 설치 배너 수락 → 홈 화면 설치
   [iOS] "공유→홈 화면에 추가" 가이드 → 설치 후 재진입
 → 알림 허용 → PushManager.subscribe → /push/register(provider webpush)
 → 주문 조회(주문번호+이메일) → 세션 guest 바인딩 → 이후 배송/상담/이벤트 푸시 수신
 → 푸시 클릭 → SW가 해당 라우트(/chat, /orders, /alerts)로 딥링크
```

## 8. 결론
백엔드는 RN 작업에서 만든 push 파이프라인의 **프로바이더 1개(WebPushProvider)와
스키마 1건(token TEXT+hash)** 추가가 전부이고, 본질 작업은 `apps/pwa` 셸(SW/manifest/설치
UX)이다. 상세 설계·단계는 `docs/plan/PLN-PWA-20260802.md` 참조.
